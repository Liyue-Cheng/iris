给我搞的花花绿绿一点，每一个卡片都要精心设计，现在这个实在是太丑了，然后术语，信息呈现方式，都可以调整 ，你看现在的结构多清晰  修改文件、执行操作、获取信息 回复，但是现在的UI配不上，甚至还没有命令行做的好看，不是吗

## 设计方案

### 一、设计理念

**核心原则：让每张卡片都能"讲故事"**

- **差异化设计**：每种操作类型有独特的视觉语言，一眼就能识别
- **状态可视化**：不只是图标+文字，用颜色、动效、布局传达状态
- **信息层次**：关键信息突出，细节收起可展开
- **呼吸感**：适当留白，不要挤成一团

### 二、整体视觉系统

#### 2.1 颜色体系

给每种操作类型分配主题色，用渐变和透明度营造层次：

| 卡片类型 | 主题色 | 语义 |
|---------|--------|------|
| **文件修改** | 紫罗兰 `#8B5CF6` → `#A78BFA` | 创造性、转变 |
| **命令执行** | 翠绿 `#10B981` → `#34D399` | 生命力、执行力 |
| **信息检索** | 天蓝 `#3B82F6` → `#60A5FA` | 智慧、探索 |
| **文本回复** | 琥珀 `#F59E0B` → `#FBBF24` | 思考、沟通 |

#### 2.2 状态表达

不只用图标，用整张卡片的视觉状态：

- **运行中 (running)**：主题色边框（2px实线） + 主题色背景遮罩（3%透明度）
- **成功 (completed)**：淡绿色左侧强调条（3px宽） + 绿色背景遮罩（3%透明度）
- **失败 (failed)**：左侧红色强调条（4px宽） + 红色背景（5%透明度）
- **部分成功 (partial)**：左侧橙色强调条（3px宽） + 黄色背景（3%透明度）
- **已停止 (stopped)**：灰色边框 + 灰色背景（2%透明度）

### 三、各类卡片详细设计

#### 3.1 文件修改卡片 (FilesCard)

**视觉特征：紫色系 + 代码感**

```
┌────────────────────────────────────────────┐
│ 📝 文件变更                       [图标]  │  ← 顶栏：紫色渐变背景（linear-gradient(135deg, #8B5CF6 0%, #A78BFA 100%)）
├────────────────────────────────────────────┤
│  📄 src/renderer/components/agent.tsx      │  ← 文件条目
│      +12  -5                               │     绿色/红色代码diff风格
│                                            │
│  📄 src/main/session.ts                    │
│      +8  -2                                │
│                                            │
│  💡 2 files changed, 20 insertions(+)...  │  ← 统计信息，用等宽字体
│                                            │
│  [展开diff]                                │  ← 交互按钮，hover时紫色高亮
└────────────────────────────────────────────┘
```

**术语优化**：
- "Files Changed" → "文件变更"
- 显示 `+增加行数 -删除行数`，像git一样
- 统计摘要用等宽字体，有代码感

**交互增强**：
- hover文件名时显示完整路径tooltip
- 点击文件名可以直接打开文件
- "展开diff"按钮可以内联显示代码diff预览

**术语优化**：
- "Operations" → "执行命令"（更直白）

**交互增强**：
- 运行中时有进度指示（不确定性进度条）
- 失败时红色边框 + 错误输出高亮显示
- "查看完整输出"打开终端面板并定位到该命令

### 四、动效设计

**原则：简洁克制，像Claude Code那样**

#### 4.1 出现动画

卡片从无到有时：
- 从当前位置淡入（opacity 0 → 1）
- 轻微的高度变化（内容从0到自然高度展开）
- 持续时间：0.25s
- 缓动函数：`ease-out`

#### 4.2 状态转换动画

- **开始运行**：边框颜色渐变到主题色（0.2s）
- **完成**：
  1. 左侧强调条从上到下展开（0.2s）
  2. 背景遮罩淡入（0.15s）
  3. 状态图标淡入（0.1s延迟）
- **失败**：左侧强调条和背景遮罩同时淡入（0.2s）

#### 4.3 悬停效果（可选，保持克制）

- 边框颜色稍微变亮（0.15s）
- 不做位移、不做阴影变化

### 五、布局和间距

#### 5.1 卡片结构

```
┌─ 卡片容器 (rounded-lg, 圆角 8px) ──────────┐
│                                            │
│  ┌─ 顶栏 (h-10, 渐变背景) ──────────────┐ │
│  │  [图标]  标题      [状态] [操作按钮] │ │  ← padding: 12px 16px
│  └────────────────────────────────────┘  │
│                                            │
│  ┌─ 内容区 ─────────────────────────────┐ │
│  │                                      │ │  ← padding: 16px
│  │  (卡片具体内容)                      │ │     background: rgba(theme, 0.02)
│  │                                      │ │
│  └──────────────────────────────────────┘ │
│                                            │
│  ┌─ 底栏 (可选) ──────────────────────────┐│
│  │  [展开详情]  [其他操作]              │ │  ← padding: 8px 16px
│  └────────────────────────────────────┘  │     border-top: 1px solid
│                                            │
└────────────────────────────────────────────┘

卡片间距：16px (space-y-4)
```

#### 5.2 文字层次

- **卡片标题**：13px, font-semibold, 主题色
- **主要内容**：13px, font-normal, foreground
- **次要信息**：11px, font-normal, muted-foreground
- **元数据**：10px, font-mono (等宽字体), muted-foreground

### 六、主题系统兼容与可访问性

#### 6.1 主题系统兼容

**关键原则：使用CSS变量，不硬编码颜色**

卡片主题色应该基于现有的主题变量：
- 文件修改：`--iris-card-files` （fallback到紫色系）
- 命令执行：`--iris-card-operations` （fallback到绿色系）
- 信息检索：`--iris-card-retrievals` （fallback到蓝色系）
- 文本回复：`--iris-card-message` （fallback到琥珀色系）

状态颜色使用全局语义变量：
- 成功：`--color-success` 或 `--green-500`
- 失败：`--color-destructive` 或 `--red-500`
- 警告：`--color-warning` 或 `--amber-500`

暗色模式：
- 所有颜色都通过CSS变量自动适配
- 遮罩透明度在暗色模式下降低（3% → 2%）
- 边框使用主题变量，不单独处理

#### 6.2 无障碍支持

- 所有状态图标都有`aria-label`
- 卡片有语义化的`role`和`aria-label`
- 键盘导航：Tab可以在交互元素间移动
- 动画可以通过`prefers-reduced-motion`关闭
