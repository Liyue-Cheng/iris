---
title: Markdown 文内链接不能定位跳转
status: Done
---
现在 Markdown 文档里的链接没有 Iris 自己的导航语义。像 [跳到某一节](#某一节) 或 ./另一个文档.md#某一节 这种链接，应用没有统一解析，也没有把 fragment 定位到标题或块。

用户看到的是 Markdown 编辑器，但点击链接时最多只能依赖编辑器或浏览器默认行为；Iris 不知道这是当前文档内跳转、项目内文档跳转，还是外部链接。这样目录链接、跨文档引用、从待办跳到具体条目，都只能打开整篇文档，不能稳定落到目标位置。

当前代码证据：

* renderer 里没有 Markdown link resolver、heading slug 生成、hash 解析或 fragment 定位逻辑。

* 项目内跳转入口基本都直接调用 projectStore.selectDoc(path)，没有携带 fragment。

* 兼容性文档已经包含 #heading 风格链接，但应用层没有接住它。

需要处理：

* [x] 定义统一 Markdown link resolver：外部 http(s)、当前文档 #fragment、相对 .md\[#fragment] 分开处理。

* [x] 固定 heading slug 规则，覆盖中文、重复标题、标点和显式锚点。

* [x] projectStore.selectDoc 或新的 navigate 命令要能携带 fragment，并在编辑器 ready 后消费。

* [x] 非法路径或越界相对路径必须拒绝，不能让 Electron 默认导航接管。

* [x] 补文内标题跳转、跨文档 fragment 跳转和非法链接测试。

## 2026-08-06 分析补充

整体属于中等工作量，不需要修改 Milkdown 内核。核心逻辑并不复杂，主要集成难点是把链接解析、异步文档读取、编辑器挂载和 fragment 定位串成一条不会串目标的导航链路。

建议将“选择文档”和“带目标导航”分开：保留 `projectStore.selectDoc(path)` 处理普通选择，新增类似 `navigateDoc({ path, fragment })` 的入口。当前文档 fragment 可直接定位；跨文档 fragment 先加载文档，再由 `CrepeEditor` 的 `onCreated` 生命周期消费待处理目标；外部链接交给系统浏览器；非法目标在 renderer 拦截，并由 main 的项目根路径校验再次兜底。

现有基础：

* `projectStore.selectDoc` 已集中管理文档切换，但同文档重选会直接返回，因此 fragment 导航不宜只靠扩展现有重选行为。

* `CrepeEditor` 已有明确的 `onCreated` 回调，可以在编辑器 ready 后执行定位。

* Milkdown 会为 heading 节点维护 DOM `id`，无需自行遍历和改写渲染后的标题节点。

* `ProjectManager.resolveInside` 已提供项目根目录防逃逸校验，可作为内部链接路径校验的第二道防线。

* 待办数据已经记录源文件行号，但 `TodoPanel` 当前点击待办时只调用 `selectDoc(path)`，尚未传递行或块目标。

需要提前固定的兼容性约定：

* 不能直接把 Milkdown 当前的 heading ID 行为当成 Iris 的长期协议。其默认规则主要是转小写、裁剪和将空白替换为连字符；中文会保留，但标点也会保留，重复标题使用 `-#2` 一类后缀。应提取 Iris 自己的共享 slug 函数并用测试锁定中文、标点、空标题和重复标题行为。

* CommonMark 没有统一的显式 heading ID 语法。实现前需明确“显式锚点”具体支持 `{#anchor}`、`<a id="anchor">`，还是只支持自动 heading slug。

* 待消费导航目标必须绑定文档路径及请求代次或 editor generation。快速连续跳转时，旧文档的异步读取或旧 fragment 不能在较晚时刻落到新编辑器上。

* renderer 应拒绝绝对路径、越出项目根的相对路径、非目标 Markdown 文件及危险协议。主进程当前的 `setWindowOpenHandler` 只覆盖新窗口请求，还应防止链接触发当前 Electron 窗口的默认导航。

* heading 定位和待办定位应视为两种目标。heading 适合稳定 slug；待办已经有行号，可先用行或块目标定位，但需要考虑正文编辑后行号漂移。

测试策略：resolver、slug、重复标题和路径归一化适合写成纯函数并用现有 Vitest 覆盖。当前测试环境是 Node，尚无现成的 React/jsdom 编辑器集成测试层；编辑器 ready 后的滚动与选区行为可尽量拆成可单测逻辑，并补少量应用内交互验收，或后续单独建设 DOM 集成测试。

工作量粗估：只完成标题的文内跳转、跨文档跳转、安全解析和纯函数测试约需 1 天；若同时覆盖显式锚点、待办具体条目、源码模式定位及完整交互验证，约需 1.5 至 2 天。

## 2026-08-12 实施方案

本次先完成 Markdown 标题导航闭环，不把待办行号定位混入同一种目标协议：

* [x] 新增共享的 Markdown 链接 resolver，只接受 `http(s)`、当前文档 `#fragment` 和项目内相对 `.md[#fragment]`，拒绝绝对路径、越界路径、非 Markdown 文件、无效编码及危险协议。

* [x] 新增 Iris 自有 heading slug 规则：Unicode 字母与数字（含中文）保留，转小写，空白与连字符归一为 `-`，其他标点剔除；重复标题依次使用 `-2`、`-3`。显式锚点支持标准 HTML `<a id="anchor">`，暂不支持非 CommonMark 的 `{#anchor}`。

* [x] 保留 `selectDoc(path)` 的普通选择语义，新增带文档路径、fragment 和请求代次的导航入口；同文档目标直接交给当前编辑器，跨文档目标在文档成功加载后由对应 editor generation 消费，避免快速连续跳转串目标。

* [x] 在 Crepe 根节点统一接管链接点击：外部 HTTP(S) 交给系统浏览器，内部链接走项目导航；所有不受支持或非法链接都阻止 Electron 默认导航。

* [x] 标题定位时按编辑器文档顺序为 heading 文本生成稳定 slug，并在 editor ready 后定位对应 heading DOM；显式 HTML `<a id>` 按清洗后的 DOM id 定位。

* [x] 为 resolver、slug、重复标题、非法路径和待消费导航目标补纯函数/store 测试，并运行现有测试与 typecheck。

## 2026-08-12 实施结果

已完成标题 fragment 导航闭环。`resolveMarkdownLink` 统一分类 HTTP(S)、当前文档 fragment 和项目内相对 Markdown 文档；Crepe 根节点阻止默认点击行为并分派系统浏览器或项目导航。`projectStore.navigateDoc` 在文档读取成功后发布绑定 path、editor generation 和递增 id 的目标，普通新导航会清除旧目标；Crepe 最多等待 18 帧布局稳定后定位并消费，不存在的 fragment 降级为不滚动。

标题定位不依赖 Milkdown 的默认 ID 及其 `-#2` 重复规则，而是按当前 heading DOM 的文档顺序应用 Iris slug。显式锚点仅支持清洗后的 `<a id="...">`，`href`、事件属性和其他可执行 HTML 仍被剔除。fragment 跳转会覆盖该文档原有滚动记忆，避免恢复流程把视图拉回旧位置。

安全边界有三层：renderer resolver 拒绝绝对/越界/非 Markdown 路径、无效 percent encoding 及非 HTTP(S) 协议；Electron `will-navigate` 阻止任何未接管的顶层导航；主进程文档读取在 `resolveInside` 后再校验 `realpath`，拒绝经目录符号链接逃出项目根。

自动验证结果：

* `npm run typecheck` 通过，包含 main、preload、renderer TypeScript 与 async boundary 门禁。

* `npm test -- --run` 通过：60 个测试文件、321 项测试全部通过。

* 新增/扩展测试覆盖 14 组 resolver、slug 与 DOM fragment 场景，导航目标的代次消费，跨文档 store 导航，安全 HTML 显式锚点及主进程符号链接逃逸。

* `git diff --check` 通过。

## 2026-08-12 交互修正

人工检查发现，Milkdown 默认会在鼠标悬停链接时显示预览条。该预览条同时提供复制地址、打开地址、编辑和移除入口，其中打开地址使用独立的 `target="_blank"` 行为；它不在 Crepe 正文根节点的事件边界内，因此不会经过 Iris Markdown resolver。正文单击已经由 Iris 接管后，继续保留预览条会形成两个打开入口，且内部链接只有正文入口具备项目导航语义。

本轮先做以下收敛：

* [x] 从 Milkdown plugin 配置层关闭 link hover preview，不使用 CSS 隐藏，避免留下不可见的 hover 状态和第二个打开入口。

* [x] 保留 LinkTooltip 的编辑上下文、选区链接命令和编辑浮层，因此选中文本后仍可通过格式工具栏创建链接，已有链接仍可解除后重建。

* [x] WYSIWYG 正文链接悬停时使用系统手型指针，明确提示该文本可点击。

* [x] 评审正文单击导航、悬停无浮条、选区工具栏创建/解除链接这组交互是否符合预期。

* [ ] 确认 WYSIWYG 正文链接悬停时显示手型指针，且普通文本和显式锚点不受影响。

这版暂不新增“一步修改已有 URL”的入口。原预览条的编辑按钮随 hover UI 一并移除；若交互方向确认，后续应在编辑器右键菜单提供“编辑链接 / 复制地址 / 移除链接”，并继续复用 Iris resolver，而不是恢复第二个链接预览条。

手型指针通过仅匹配 `.ProseMirror a[href]` 的样式实现。`npm run typecheck` 通过；Markdown 导航、导航目标消费、Crepe 生命周期和项目范围 4 个相关测试文件共 41 项测试全部通过。
