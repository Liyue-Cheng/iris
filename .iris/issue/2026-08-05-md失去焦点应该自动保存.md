认真调研一下目前的md自动保存逻辑，是不是还有很多bug，能不能失去焦点就自动保存兜底，结果追加到这个issue中

## 2026-08-05 自动保存链路调研

### 结论

可以、也应该在 **Markdown 编辑区真正失去焦点**时保存，但这只是触发层的兜底，不能单独解决当前的数据安全问题。现在已经有 `window.blur` 保存，但它只在整个 Iris 窗口失焦（例如 Alt-Tab 到其他应用）时生效；从 Markdown 编辑区点到同一窗口内的终端、左栏、标题字段等位置不会触发 `window.blur`。

调研还确认了一个比“没有编辑器 blur”更严重的竞态：保存在途时用户继续编辑，新内容可能被错误标记为已保存，之后切文档或退出就会真正丢失。因此实现顺序应是：**先修保存状态机，再补编辑区失焦触发**。

### 当前实现

- WYSIWYG 每次 `markdownUpdated` 只更新 `editorStore` 内存并标脏；源码模式每次 CodeMirror `docChanged` 也只标脏。普通输入没有定时防抖保存，这是有意的“批量到某个交付点再写盘”。
- 当前交付点有：`Ctrl/Cmd+S`、整个窗口 `blur`、切文档/集合/待办/工作区、进设置页、关窗握手；标题区 frontmatter 字段提交和 GFM 复选框切换会立即保存。
- `doc.save` 按 `doc:{path}` 串行排队，主进程通过同目录临时文件加 `rename` 原子替换。这两层的写盘基础是合理的。
- 自身写盘会被 chokidar 再投影回渲染层；`lastWritten` 用完整字节比较吞掉自身回声。干净会话遇到真实外部修改会重载，脏会话则保留内存内容并显示冲突。

### 已确认的问题

#### P0：保存期间的新编辑会被误标为已保存

`editor-store.ts` 的 `save()` 在 `session.saving` 为 true 时直接返回。第一次写盘前快照了 `content=A`；写盘在途用户又输入得到内存内容 `B`，此时 blur/Ctrl+S/切换再调 `save()` 都会因 `saving` 被吞掉。当 A 写成功后，成功分支又无条件将 `dirty=false`，并用当前 `bodyCurrent=B` 作为 baseline，而盘上实际只有 A。界面显示对勾，后续保存也会认为无变更。

这个窗口不只存在于慢磁盘：frontmatter 立即保存、复选框立即保存、Ctrl+S 后继续打字，都能进入它。切文档又采用后台 flush 并立刻覆盖旧 session，因此保存在途产生的新编辑更容易无处重试。

#### P0：保存失败时，切换和关窗仍可丢内容

`save()` 内部 catch 错误后只设 `saveError`，Promise 仍按成功 resolve。切文档/视图是“不等写盘，立即替换或关闭 session”，所以失败发生在旧 session 消失之后：用户看不到错误，也没有重试所需的旧编辑内容。关窗时渲染层也会在这种失败后照常 ack，主进程随后关窗。

#### P1：“失焦保存”只覆盖窗口失焦

`DocView.tsx` 监听的是 `window.addEventListener('blur', ...)`，不是 WYSIWYG/CodeMirror 编辑区的 blur/focusout。最常见的“写完 Markdown 后点右侧终端继续工作”不会交付到磁盘；此时 agent 从盘上读到的仍是旧文本。这正是应该增加编辑区失焦保存的直接理由。

触发应放在编辑器边界或 DocView 的捕获层，并用 `relatedTarget`/`contains` 判断焦点是否真的离开编辑区，避免 ProseMirror/Crepe 内部工具、弹层或 CodeMirror 子节点间的焦点跳转制造无意义写盘。WYSIWYG 和源码模式应共用同一语义。

#### P1：自身回声标记早于真实写成功

`lastWritten.set(path, content)` 在 dispatch 前就执行。如果写盘失败，该路径仍保留一个“从未写成功”的回声值，会污染后续外部变更判断。它应至少在失败时回滚，更清晰的做法是分开“正在写的快照”与“已确认写成功的快照”。

#### P1：切换项目没有显式 flush 契约

`projectStore.handleOpened()` 直接 `closeSession()`，`openProject()` 也没有先 flush。通过原生文件夹选择器操作时，窗口 blur 大概会间接保存，但这是 UI 时序偶合，不是项目切换链路的正确性保证。应在动作本身建立明确的 flush/失败处理。

#### P2：没有针对保存状态机的自动化测试

现有测试没有覆盖 `editorStore.save()`、失焦、保存期间继续编辑、写盘失败、快速切文档、关窗 flush 等关键时序。当前正确性主要靠注释和手工验收，但 P0 竞态正好证明了“按路径串行”不等于“内存编辑不会被误清脏”。

### 建议实现

1. 把 `save()` 改成可合并的单写者状态机，不再用 `saving => return` 吞请求。每次写盘携带不变的 `{path, content, revision}` 快照；成功后只能确认该 revision，若当前 revision 已前进，必须保持 dirty 并立即 trailing save，绝不能用新 `bodyCurrent` 给旧写盘快照做 baseline。
2. 让 `save()`/`flushBeforeSwitch()` 返回真实的成功或失败结果。会销毁 session 的动作必须在失败时保留内存草稿和可见错误；关窗不能把“写盘失败”当成“flush 完成”。是否继续采用无阻塞切换可以另行决定，但旧 session 的待写快照与错误必须有独立生命周期，不能依附于当前单一 `session`。
3. 在 Crepe 与 CodeMirror 的共同编辑区边界上增加“真正离开编辑区”的 focusout 保存。保留现有 `window.blur`、Ctrl+S、切换和关窗作为多层兜底；不建议只把 `window.blur` 换个名字或在每个内部 DOM 节点上绑 blur。
4. 将 echo dedup 改为与已确认写盘快照一致，并明确测试“自身回声吞掉、真实外部写重载/报冲突、失败写不得冒充自身回声”。
5. 为 editor store 抽出可注入的 save executor 或纯状态机，用 deferred Promise 精确控制时序。单元测试应先锁定 P0 再改实现，否则 blur 只会让保存竞态更容易触发。

### 建议验收

- [ ] WYSIWYG 输入后直接点终端，不切文档、不 Alt-Tab，盘上文件已更新。
- [ ] 源码模式输入后直接点左栏/终端，盘上完整字节与 CodeMirror 一致。
- [ ] 在一次保存 Promise 未完成时继续输入，第一次只写旧快照，随后自动写新快照；中间不出现假对勾。
- [ ] 保存在途时连续点复选框、改 frontmatter、Ctrl+S 和切文档，最终盘上是最新内容，没有任何一次请求被静默吞掉。
- [ ] 模拟写盘失败后切文档、切项目和关窗，未保存内容仍可恢复，错误可见，应用不得无提示丢稿。
- [ ] 在 Crepe/CodeMirror 内部点击、选择文本、打开内部控件不会因伪 blur 重复写盘。
- [ ] 干净文档失焦是零写入；未编辑文档打开后保存仍然 `git diff` 为空。
- [ ] 保存期间发生真实外部修改时，不会被错认为自身回声，冲突标记不会被旧保存的成功回调无条件清掉。
- [ ] 快速切换 A → B → A、进集合/待办/设置页再返回，A 的最新内容与保存错误状态都不丢失。

## 2026-08-05 实现进展

本次已实现保存正确性的核心部分与编辑区失焦兜底：

- `editorStore` 增加单调 `revision`，每次正文、源码或 frontmatter 变更都前进 revision。保存使用不变快照，只有返回的 revision 仍是当前最新版本时才能清除 dirty。
- 删除 `saving => return` 的静默吞请求逻辑。现在每个文档只有一个 writer，保存在途收到的新请求合并为最新 trailing snapshot，前一次写完后自动追写。
- 写盘失败时保持 dirty 和 `saveError`，并回滚未成功写入的 `lastWritten` 回声标记，避免将未落盘内容冒充自身回声。
- `DocView` 的正文边界增加 React `onBlur`/focusout 处理；焦点只有真正离开正文区时才保存，编辑器内部子节点之间切换不触发。现有窗口 blur、Ctrl+S、切换和关窗触发仍保留。
- 新增 editor store 时序测试，覆盖“写盘在途继续编辑会自动 trailing save，且旧 revision 不能清脏”与“写盘失败保留 dirty/错误”。

自动化验证：`npm test -- --run` 共 7 个测试文件、67 项测试全部通过；`npm run typecheck` 通过；`git diff --check` 通过。

本 issue 暂不进 `In Review`：“写盘失败后切文档/切项目/关窗”的保留草稿与阻止销毁策略尚未实现，手工验收项也保持未勾选。
