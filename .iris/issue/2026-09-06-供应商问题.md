现在，为什么pi的默认供应商还放在我们的模型列表中？你现在移除，模型列表我们自行管理，不使用pi内置的

## 移除 pi 内置供应商，模型列表完全由 Iris 自管（2026-09-09）

### 原因

模型下拉用的是 `loadIrisModelCatalog`，它原先通过 pi 运行时的 `getAvailable()` 取模型。`getAvailable()` 会返回所有「凭据可用」的 provider 的模型，而 pi 的内置 provider 会从环境变量（`OPENAI_API_KEY`、`DEEPSEEK_API_KEY`、`ANTHROPIC_API_KEY` 等）和 `~/.pi/agent/auth.json` 解析凭据。所以即使用户没有在 Iris 里配置任何供应商，pi 内置的 openai / anthropic / deepseek 等模型也会进入列表。

### 变更

- `loadIrisModelCatalog`：只从已配置的 Iris 供应商档案（`iris-profile-*`）取模型，不再调用 pi 的 `getAvailable()`。pi 的内置目录降级为「API 实现 + 模型元数据」来源，仅供注册档案 provider 使用，不再作为可选模型来源。
- `createIrisModelRuntime({ kind: 'selected' })` 与 `resolveIrisModelBaseUrl`：模型 ref 必须属于某个 Iris 供应商档案，否则明确报错，避免执行阶段回落到 pi 内置 provider。
- 供应商目录投影（`IrisAgentProviderCatalog`）删除 `providers` 字段与 `IrisAgentProviderOption` 类型；移除 `IRIS_AGENT_PROVIDER_SET_KEY` / `IRIS_AGENT_PROVIDER_REMOVE` 两个通道及 `saveIrisProviderApiKey` / `removeIrisProviderCredential` / `hasStoredPiCredential`。这些是 pi 内置 provider 的凭据管理入口，界面从未使用。
- 模型下拉空态提示改为「未配置供应商模型（请先在设置中添加供应商档案）」，并清理随之无用的 i18n 文案。
- 保留 `storedPiCredentialSecrets`：本机若残留 pi 凭据，仍不会写进 provider artifact。
