---
title: Markdown 右键编辑动作可能打到新焦点
status: On Hold
---
WYSIWYG 编辑器的右键菜单里，“剪切 / 复制 / 粘贴 / 全选”不是立即执行，而是先等 50ms，再等一个 0ms 定时器，然后调用窗口级 WINDOW\_EDIT\_ACTION。

如果用户点完菜单项后立刻切换文档、打开弹窗或焦点落到别的输入框，旧编辑器的定时器不会取消。最后发出的窗口级 edit action 可能作用到新的焦点目标，而不是当时右键的那篇文档。

当前代码证据：

* src/renderer/components/doc/CrepeEditor.tsx 的 editAction 使用两层 window\.setTimeout。

* 组件卸载时没有清理这两个 timeout。

* 最终调用 WINDOW\_EDIT\_ACTION 时只带 action，没有带原始编辑器实例或文档校验。

需要处理：

* [ ] 把右键 edit action 做成可取消任务，组件卸载时取消。

* [ ] 执行前确认原 ProseMirror 仍存在且仍是目标编辑器。

* [ ] 尽量改成基于菜单关闭事件或明确焦点恢复后的确定性流程，不靠固定延迟。

* [ ] 补“右键后立即切文档/打开弹窗”的回归测试。


## 复核（2026-11-24）

**结论：问题仍然存在，但实际触发概率很低。**

代码已经重构，issue 原文中的证据位置已过时：

- 编辑器右键菜单已从 `CrepeEditor.tsx` 移到 `DocView.tsx` 的 `handleEditAction`。文本框右键菜单 `text-edit-context-menu.tsx` 也走同一条路径。
- 两处都调用 `src/renderer/components/ui/context-menu.tsx` 的 `runAfterContextMenuClose`：先等 50ms 执行 `restoreFocus`，再等 0ms 调用窗口级 `WINDOW_EDIT_ACTION`。

与原描述相比有一处改进：执行前会先把焦点还给点击时捕获的编辑器适配器（`adapter.focus()`），所以只要原编辑器还在，动作就会落回原文档。

仍未解决的部分：

- 两个定时器都没有返回句柄，组件卸载时无法取消。
- 执行前不检查原编辑器是否仍挂载、是否仍是当前文档。如果原编辑器在这 50ms 内被销毁，`focus()` 不会生效，剪切、粘贴或全选就会作用到当时恰好有焦点的元素上。

要触发它，需要在点完菜单项后 50ms 内切换文档或打开弹窗。手动操作基本做不到，只有快捷键或程序化导航恰好落在这个窗口里时才可能发生。建议降为低优先级，原有待办仍然有效。
