要是issue被意外删除，目前来看，终端就不可见了，我认为这不是好的结果，你要这样，就是要是issue被删除，相关终端就显示在工作区/项目根。然后附加警告标志

## 理解

现在的终端是按文档路径锚定的。`.iris` 文件被外部删除后，文件监听会触发重新扫描，issue 行和当前编辑器会被清掉；`TerminalSessionManager` 里的 PTY、滚动内容和会话记录仍然存在，但它们继续指向已经不存在的 `docPath`。右栏只筛选当前锚点，工作区会话列表也只接收 `docPath === null` 的会话，因此这些终端没有任何可见入口。

用户主动从删除对话框删除时已有“关闭会话”与“重新锚定到项目根”两个分支；本 issue 要补的是外部删除、文件管理器删除、Agent 删除等路径，并且要把保留下来的会话明确标成“原 issue 已删除”。终端进程不应因为文档消失而被杀掉，已有的 PTY 输出和退出后的滚动内容也应继续可用。

工作区归属按会话创建时的文档所属 workspace 保存：文档仍在时按文档路径显示；文档消失后优先显示在原 workspace 的 hub；原 workspace 也被删除时退回项目根 `.iris`。这里的“重新锚定”只改变 Iris 的显示和分组元数据，不能修改已经启动的子进程环境，所以旧进程中的 `FOCUS_DOC` 仍可能指向旧路径，警告需要把这个事实显式告诉用户。

## 实现方案（仅方案，未改代码）

### 1. 会话状态和事件

- [x] 在 `TerminalSessionInfo` 增加可选的 `orphanedDocPath`（原来被删除的文档路径）。文档会话创建时同时保存其 `workspacePath`，但仍以 `docPath` 作为当前锚点；workspace hub 会话继续使用 `docPath: null`。
- [x] 在 `TerminalSessionManager` 增加按文件监听批次处理删除的入口。对 `unlink` 以及覆盖整个 workspace 的 `unlinkDir`，匹配仍以该路径为 `docPath` 的会话；同一批次同时出现相同路径 `add` 时跳过，避免“删除后立即恢复”被误报。
- [x] 匹配到会话后原子地更新为 `docPath: null`、`workspacePath: 原所属 workspace 或 .iris`、`orphanedDocPath: 原文档路径`，只发一次 `sessionStateChanged`，不关闭 PTY、不清空镜像、不改变进程尺寸。
- [x] 在 `wireBroadcasts` 的 `irisChanged` 处理里先调用上述会话处理，再把文件事件发给 renderer，保证 renderer 收到重扫事件时已经能看到新的 hub 锚点。处理必须按项目 scope 过滤并保持幂等，重复 watcher 事件不能重复改写警告。
- [x] 保持现有 `session.reanchor` 兼容：用户主动重新锚定时清除 `orphanedDocPath`；删除对话框选择“重新锚定到项目根”仍不显示删除警告。同步扩展 ISA commit，使 `workspacePath` 和警告字段不会因只应用 `docPath` 而丢失。

### 2. 创建会话时记录 workspace

- [x] 在 `RightPane` 打开文档终端时把 `IrisDoc.workspacePath` 传给 `openSession`，再经 IPC 传入主进程；只用于未来失锚后的分组，不注入 `IRIS_WORKSPACE_PATH`，文档会话仍只注入原有的 `FOCUS_DOC`。
- [x] 更新 `sessionAnchorKey`、`terminalLayoutScope` 及相关注释/测试，明确“文档会话也可携带 fallback workspace”，但在 `docPath` 非空时仍按文档分组，避免影响现有多会话选择逻辑。

### 3. renderer 重扫和导航

- [x] 在 `projectStore.refreshFromFs` 重扫前记录被删除路径对应的当前视图和会话；重扫后若当前选中的文档正是失锚文档且存在保留会话，将视图切到所属 workspace hub，workspace 不存在时切到项目根，而不是停在没有右栏锚点的 `doc: null`。
- [x] 将原文档锚点下的显式会话选择转移到新 hub；没有显式选择时沿用现有“显示最新会话”的规则。集合视图中选中的 issue 被删且有保留会话时，也应退出集合并进入相同 hub，确保终端马上有入口。
- [x] 对已在其他文档或 hub 中的视图只更新投影，不强行切换用户当前页面；删除事件、会话事件乱序时以 `orphanedDocPath` 和当前 scope 再做一次幂等判断。

### 4. 投影和界面警告

- [x] 让 `terminalSessionProjection` 在 `docPath === null` 且存在 `orphanedDocPath` 时仍投影到 fallback workspace，并携带“文档已删除”的警告元数据；普通 workspace 会话不携带该标志。
- [x] 在 `LensTree` 的 `WorkspaceSessionList` 中给失锚会话增加警告图标、可访问名称和原文档路径提示；保留现有 SessionDot 和关闭操作。图标应在 workspace 折叠文档区时仍可见。
- [x] 在 `RightPane` 的终端 banner、会话切换菜单和当前会话项中复用同一警告图标与提示文案，提示原 `FOCUS_DOC` 已失效；不把警告伪装成普通退出状态。
- [x] 增加中英文 i18n 文案，例如“锚定文档已删除”和“原文档：{{path}}”，并补充键名测试，避免硬编码只在某一语言可见。

### 5. 测试和验收

- [x] 为 `TerminalSessionManager` 增加文件删除、workspace 目录删除、同批次恢复、重复事件和多会话测试，验证只改元数据且所有会话都保留。
- [x] 为 session projection 增加失锚会话投影到 workspace/root 及警告字段的测试；在重扫导航测试中验证显式选择转移，并验证项目 generation 隔离不变。
- [x] 为 `projectStore.refreshFromFs` 增加当前文档被删、当前文档无会话、嵌套 workspace 被删、集合视图被删和非当前文档被删的导航测试。
- [ ] 手工验收：打开 issue 终端后用文件管理器删除 issue，确认终端仍能输入、滚动内容仍在、workspace/root 列表出现警告；删除整个 workspace 时确认会话落到项目根；关闭会话后警告消失；重新创建同名 issue 不自动把旧会话挂回去。

普通 Iris Agent 会话目前使用独立的 `IrisAgentAnchor` 和上下文读取链路，不应在本次先把运行中的 Agent 静默改成 workspace 上下文。若验收范围也包含 Iris Agent，再复用同一套“失锚元数据 + hub 投影 + 警告”模型，并额外决定 Agent 读文档失败时是暂停等待用户，还是允许切换到 workspace 上下文。
