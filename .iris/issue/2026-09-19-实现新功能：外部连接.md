我现在需要实现一个新的功能：外部链接

就是很简单的，就是在默认的四个文件夹之外，还有一个external txt，可以编写一些路径，可以是文件，也可以是文件夹，然后是左栏会显示为external，然后可以拖动到md和终端来粘贴路径，然后点击之后是用默认程序打开，文件夹的话，就是用资源管理器打开

然后文件树组件要做对应功能联动

你理解需求，然后给我一个完整的程序、提示词治理方案，要考虑右键菜单等所有相关的功能

## 需求理解

这是一个**工作区级外部路径索引**，不是第五种文档类型，也不是文档资产的另一种展示：

- `status / issue / report / misc` 仍是唯一四种 PM 文档类型，`external` 不进入 `DocType`、状态机、集合页、Todo 或 Agent Session 锚点。
- 每个 Iris 工作区可在工作区根放置 `external.txt`，例如根工作区为 `.iris/external.txt`，子工作区为 `.iris/spike-auth/external.txt`。
- 文件中的每个有效行引用一个文件或目录。相对路径以该 `external.txt` 所在工作区目录为基准；绝对路径按当前操作系统解释。
- Lens 左栏在对应工作区的四类文档区之后显示 `External` 区域；文件用默认应用打开，目录用系统文件管理器打开。
- 外部项可以拖到 Markdown 编辑器和终端，插入/输入的是解析后的**绝对路径**。
- Raw 文件树仍显示真实的 `external.txt`，同时对该文件提供进入 External 语义的联动入口，避免两个互不相关的管理入口。
- 这与 `<document>.assets/links.txt` 不同：后者属于单篇文档，随文档 companion 目录管理；`external.txt` 属于整个工作区，不能复用文档资产生命周期。

## 文件协议

### 文件位置与作用域

- 根工作区：`.iris/external.txt`。
- 子工作区：`<workspacePath>/external.txt`。
- 只有**已被扫描器识别为工作区**的目录中的 `external.txt` 生效；普通目录里同名文件只是普通文件。
- 不递归展开外部目录，避免监听外部磁盘、网络盘或超大目录。每一行始终投影成一个叶子项。
- 初始化 Iris 时建议创建空的 `.iris/external.txt`，使该能力可发现；子工作区使用 standard 模板时也创建空文件，empty 模板保持真正为空。
- 兼容已有项目：文件缺失等同于空清单，不报错、不自动写盘。

### 文本格式

保持 plain text，不引入 JSON/YAML 或 manifest：

```text
# 一行一个路径；空行和以 # 开头的行忽略
../design/spec.pdf
../../shared-assets
C:\Users\name\Documents\reference.docx
```

规则：

1. UTF-8 文本，支持 LF/CRLF，可接受 UTF-8 BOM。
2. 去掉每行首尾空白；空行及首个非空字符为 `#` 的行忽略。
3. 不做 shell 展开：不解释 `~`、`$HOME`、`%USERPROFILE%`、glob、环境变量或引号。这样路径含 `$`、`*`、单双引号时没有二义性，也不引入命令执行面。
4. 相对路径按 `external.txt` 所在工作区目录解析，而不是项目根或进程 cwd。
5. 保存时优先保存相对路径：目标位于工作区或项目附近且可生成稳定相对路径时写 portable `/`；否则保存规范化绝对路径。
6. 展示按文件中的行序，去重以平台路径等价规则为准；Windows 比较时大小写不敏感，POSIX 保持大小写敏感。首个条目胜出。
7. 路径不存在、无权限、格式非法或跨平台不可解释时不丢弃原行，投影为 disabled/missing 项并显示原始路径。
8. 行级错误不能使整份清单失败；只有文件读取失败才投影清单级错误。

建议投影模型：

```ts
interface ExternalPathEntry {
  storedPath: string;
  absolutePath: string | null;
  name: string;
  kind: 'file' | 'directory' | null;
  exists: boolean;
  line: number;
  error: 'invalid' | 'missing' | 'unreadable' | 'unsupported-platform' | null;
}

interface WorkspaceExternalPaths {
  workspacePath: string;
  manifestPath: string;
  entries: ExternalPathEntry[];
  diagnostics: Array<{ line: number | null; message: string }>;
}
```

不要把这些条目做成持久数据库。它们应是可由磁盘即时重建、随 project scope 一起丢弃的投影。

## 程序方案

### 1. 主进程与共享类型

新增独立的 `ExternalPathManager`（建议 `src/main/external-path-manager.ts`），不要把项目级语义塞进 `AssetManager`：

- `list(projectRoot, workspacePath)`：验证 workspacePath 位于当前项目内，读取并解析 `<workspacePath>/external.txt`，对每项 `lstat/stat`，返回逐行诊断。
- `add(projectRoot, workspacePath, targetPath)`：验证目标当前存在且是普通文件或目录，按上述规则序列化，原子写回并去重。
- `remove(projectRoot, workspacePath, storedPath, line)`：基于行号 + 原值做 compare-and-swap，避免重复路径或外部编辑时误删其他行；保留注释、空行及未识别行。
- `resolve(projectRoot, workspacePath, storedPath, line)`：重新读取清单并验证该条仍存在，然后返回当前绝对路径。打开、Reveal 和删除引用所需的可信路径都从这里取得，不能信任 renderer 直接提交的任意绝对路径。
- `pick` 可复用现有文件/目录 native picker，但业务命名应独立于 asset。
- 建议允许清单指向 symlink，但使用链接本身的绝对路径打开，不递归扫描；类型以目标可访问时的 `stat` 为准，断链为 missing。

新增 IPC/query/verb：

- `external:list`
- `external:add`
- `external:remove`
- `external:open`
- `external:reveal`
- `dialog:pick-external-path`

写操作通过 FrontCPU ISA（`external.link-add`、`external.link-remove`）并以 `external:<workspacePath>` 串行；list 是 projection query。open/reveal 是系统副作用，走独立 shell ISA，但在主进程中必须先通过 manifest membership 校验。

`external:open` 的目录语义应明确：

- 文件：`shell.openPath(path)`，交给默认应用。
- 目录：`shell.openPath(path)`，让 Finder/Explorer/文件管理器直接打开目录。
- `reveal`：文件用 `shell.showItemInFolder(path)`；目录的平台行为不一致时降级为 `shell.openPath(path)`。
- missing/invalid：拒绝操作并返回可本地化错误，不让 renderer 猜测。

### 2. 扫描、监听与初始化

`iris-scanner.ts` 在确认一个目录为 workspace 后读取其直属 `external.txt`，不把它当文档，也不因为仅存在 `external.txt` 就推断出工作区。`IrisWorkspace` 增加 `external` 投影。

现有 chokidar 已监听整个 `.iris/`，因此 `external.txt` 的新增、修改、删除会自然进入 `FS_IRIS_CHANGED`，触发 scan 重投影。需要补齐：

- 删除或清空文件后 External 区域立即更新。
- raw mode 开启时，同一事件同时刷新 RawTree。
- 项目切换/renderer reload 仍依赖 project scope/generation 丢弃陈旧响应。
- 不监听外部目标本身：目标被删除后不会即时收到事件；在点击/右键操作时重新校验，另外提供手动 Refresh。下次 `.iris` 重扫或 Refresh 后更新 missing 状态。

`project.init` 和 standard workspace 模板创建空 `external.txt`，并扩展 `ProjectInitResult`，让初始化 UI 能准确报告文件是否新建；重复初始化不得覆盖已有内容。

### 3. Lens 左栏

在每个 `WorkspaceSection` 中、四种类型之后、子工作区之前增加 `ExternalSection`：

- 标题使用 `External` + `FolderOpen/ExternalLink` 图标 + 条目数，支持折叠。
- 文件与目录分别使用 `File` / `Folder` 图标；missing 用 `FileWarning`，文字降级但仍可右键。
- 单击文件或目录执行系统打开，不切换中栏视图，也不改变当前文档/终端 selection。
- 点击操作前调用 `editorStore.flushBeforeSwitch('before-external-action')`，与 RawTree/文档右键现有行为一致，避免系统动作发生时丢失草稿。
- 条目按清单顺序显示；全局文档 filter 开启时也过滤 `name + storedPath`，但不参与 mtime/title 排序。
- 空的显式 `external.txt` 可显示 section + Empty，增强可发现性；文件缺失时默认不显示。
- 标题区提供 `+`：菜单选择 Add file / Add folder；选择完成后写入当前工作区清单。
- archived workspace 仍显示且可打开，但禁止添加/移除，保持“冻结过去”的既有语义。

### 4. 右键菜单

每个有效项：

- Open（文件默认应用、目录文件管理器）
- Reveal in File Manager
- Copy Absolute Path
- Copy Stored Path
- Remove from External（只删清单行，不动目标文件/目录；destructive 样式，文案明确“不删除磁盘内容”）

missing/invalid 项：

- Copy Stored Path
- Remove from External
- Refresh

区段标题或 `external.txt` 的菜单：

- Add File
- Add Folder
- Open `external.txt` with Default App
- Reveal `external.txt`
- Refresh

不得提供 Rename/Delete target 等真实文件管理操作。本功能是引用索引，不拥有外部目标的生命周期。

### 5. 拖放到 Markdown 与终端

新增独立 MIME，例如 `application/x-iris-external-path`。不能复用 `IRIS_DOC_MIME`：后者在终端会读取文档并粘贴快照，而 External 只应粘贴路径。

拖动数据：

- custom MIME：解析后的绝对路径。
- `text/plain`：同一绝对路径，拖到系统外应用仍可用。
- `effectAllowed = 'copy'`。

编辑器：

- 扩展 `resolveEditorPathDrop`，优先级为 External MIME > Iris Doc MIME > OS Files。
- 插入解析后的绝对路径；多项未来若支持多选则一行一个。
- 保持现有 drop point、preventDefault 和错误提示机制。

终端：

- External MIME 进入 `inputController.dropPaths([absolutePath])`，复用 OS 文件 drop 的 shell quoting、危险字符确认和单一输入路径。
- 不经过 `handleDocDrop`，不读取文件内容，也不把目录递归展开。
- missing/invalid 项禁用 draggable。

需要覆盖 Windows 路径空格、`&|;()$'"` 等字符，macOS/Linux 空格与单引号，以及中文路径。

### 6. Raw 文件树联动

RawTree 保持“磁盘真实结构”的职责，不把清单中的外部目标伪装成项目子节点，否则会破坏项目边界并造成无限/巨大树问题。联动方式：

- `.iris/**/external.txt` 仍作为普通文件显示，单击按默认应用打开。
- 当该文件直属已识别 workspace 时，右键增加 `Manage External` / `Show External Section`，退出 raw mode 并定位、展开对应 workspace 的 External 区域。
- 其菜单保留 Copy path / Open default / Reveal；可以增加 Add file / Add folder。
- Lens 与 RawTree 共用同一 manager/parser，不能各自解析 `external.txt`。

为支持定位，需要在 lens prefs/store 增加一次性 reveal intent（workspacePath + section=`external`），由 `ExternalSection` 消费并展开/滚动。

### 7. 国际化、错误和无障碍

补齐中英文资源，不复用“External change”或“External URL”相关键，避免概念混淆。至少包括：External、Add file/folder、Open、Reveal、Copy absolute/stored path、Remove reference、missing、invalid line、read/write/open/reveal failure、Refresh。

所有图标按钮有 tooltip/aria-label；路径文本使用 truncate + aria-label；菜单键盘可达；打开失败通过现有 `runUserAction` / notification 显示，不只 `console.warn`。

## 安全与跨平台边界

1. renderer 不应获得“打开任意绝对路径”的通用能力。`external:open/reveal` 必须由主进程重新读取所属 `external.txt` 并验证条目成员关系。
2. 不执行清单文本，不做变量、glob、URL 或 shell 展开；`http:` 等 URI 视为普通无效路径，网页链接继续走现有 URL 安全通道。
3. 拖到终端必须复用 `dropPaths` 的 shell quoting/确认逻辑，不能直接 `SESSION_INPUT` 拼字符串。
4. 外部目标永不随 Iris 文档、工作区或项目删除而删除；Remove 只编辑 `external.txt`。
5. 不把外部绝对路径写入 Agent 上下文或遥测。UI 可显示，错误消息尽量只包含用户已操作的 storedPath。
6. 清单可进入 Git，绝对路径可能泄露用户名和机器结构。提示词应推荐团队项目使用相对路径；UI 可在添加绝对路径时给非阻断提示，但不得擅自复制文件。
7. Windows 路径在 macOS/Linux checkout 后可能不可解释，必须保留并标为 unsupported，不能改写或删除。

## 提示词治理方案

需要同步修改 `src/main/iris-templates.ts` 中的 canonical software prompt，并由现有治理链投影到 `AGENTS.md` / 已参与的 vendor entry。建议在 `<iris-software>` 的 Folder semantics 与 Document assets 之间加入：

```markdown
## Workspace external paths

A workspace may contain an `external.txt` file at its root. Each non-empty,
non-comment line associates one external file or directory with that workspace.
Relative paths are resolved from the workspace directory; absolute paths remain
machine-specific. These entries are references only: do not move, modify, or
delete their targets unless the user explicitly asks.

`external.txt` is not a fifth document type and is not a PM write-back target.
Preserve comments, blank lines, unknown or unavailable paths, and existing line
order when editing it. Prefer portable relative paths for shared projects. A
workspace or document deletion never deletes an external target.
```

同时更新：

- `software-definition.md`：项目结构示例、工作区定义、裸树/Lens 展示、文档资产章节中明确 `external.txt` 与 `links.txt` 的不同所有权。
- `technical-design.md`：增加项目级 external manager、IPC 和安全边界。
- README 中英文：说明格式、相对路径基准、点击/拖放和“不拥有目标生命周期”。
- `src/main/software-prompt.test.ts`：断言 canonical prompt 包含 `external.txt`、“not a fifth document type”、不删除外部目标和相对路径基准。

Agent 行为约束：

- Agent 可读取清单来理解工作区关联资源，但不会自动读取清单中所有目标，避免越界和上下文爆炸。
- 只有用户明确要求添加/移除关联时才编辑 `external.txt`；不得因路径 missing 自动清理。
- 修改时保留注释、空行、未知行与顺序，按精确行做最小改动。
- 外部目标不属于 Iris 管理数据，任何写入、移动、重命名、删除都需要用户明确授权。
- 聚焦文档仍由 `FOCUS_DOC` 决定，`external.txt` 不成为文档 focus，也不创建 Agent Session 锚点。

协议版本无需把 `DocType` 从四种扩成五种；这是工作区附属索引。canonical block 更新应通过现有治理状态呈现，不静默覆盖用户手写 project guidance。
