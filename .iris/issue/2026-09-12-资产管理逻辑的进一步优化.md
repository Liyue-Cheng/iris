## 当前实现的业务逻辑（2026-09-12）

> 本轮调整：资产模型已简化为“内部引用”和“外部关联”两类。以下早期段落中关于 SHA-256、内容去重、受管/非受管、孤儿/缺失状态、收编和孤儿清理的描述均已废弃，以本节末尾的《简化模型补充》为准。

以下内容按现有代码的实际行为整理，不代表下一轮优化方案。

### 1. 资产归属和目录结构

* 每个 Iris Markdown 文档 `<name>.md` 只对应同级的 `<name>.assets/` companion 目录。

* companion 目录首次导入受管资产、或首次添加外部关联路径时按需创建；没有内容时不会主动创建空目录。

* 目录中普通文件是受管资产；`links.txt` 是保留的外部路径索引，不计入资产数量、资产健康状态或普通文件列表。

* scanner 将名称以 `.assets` 结尾的目录视为不透明叶子目录，跳过其中的 Markdown、todo 和 workspace 扫描。

* 当前没有 manifest、frontmatter 资产表或全局资产数据库；资产状态每次根据 Markdown 内容和磁盘目录即时重建。

* 资产所有权检查要求文档是项目内 `.iris/` 下的普通 `.md` 文件，文档本身不能是符号链接；companion 目录如果存在，也必须是普通目录且真实路径仍在项目边界内。

### 2. Markdown 引用审计

`asset:list` 读取文档全文，用 remark 解析 AST，识别以下引用：

* 普通图片：`![alt](url)`。

* 普通链接：`[text](url)`，但部分文档链接会被过滤，不作为资产展示。

* 图片引用式链接和普通引用式链接：`![alt][id]`、`[text][id]`，通过 definition 解析最终 URL。

* URL 会去除 query/fragment 后解析为项目内路径；URL 编码会先解码。

* 危险协议、绝对路径、以 `/` 或 `\\` 开头的路径、越出项目根目录的 `..` 路径不会被当作本地资产目标。

* 支持审计的 data URL 仅限 `png/jpeg/gif/webp/avif` 的 base64 图片；远程 `http/https`、`blob:` 等不会进入受管资产列表。

引用与磁盘文件合并后产生四种状态：

| 状态           | 当前判定                                                  |
| ------------ | ----------------------------------------------------- |
| `referenced` | companion 目录中的普通文件，且至少有一条 AST 引用指向它                   |
| `orphan`     | companion 目录中的普通文件，但没有任何 AST 引用                       |
| `missing`    | Markdown 引用解析到了当前文档自己的 companion 目录，但对应文件已不存在         |
| `unmanaged`  | 项目内 companion 之外的本地文件引用，或受支持的 data URL；Iris 只审计，不自动复制 |

* companion 内的符号链接、目录和非普通文件不会列入普通资产清单。

* Markdown 链接到另一个 `.md` 文件时通常被视为文档导航，不显示为 unmanaged 资产；普通非图片附件链接是否显示取决于其目标扩展名和引用类型。

* 同一文件被多处引用只显示一条资产记录，`referenceCount` 记录引用次数；引用式链接也会计数。

* 资产按 `missing -> orphan -> unmanaged -> referenced` 排序，再按名称排序。

* 列表同时返回四类计数、companion 目录路径和 `links.txt` 解析出的外部关联项。

### 3. 受管资产导入

入口包括资产面板文件选择、Crepe 图片块上传、粘贴和拖入；renderer 只把文件名、声明 MIME 和字节发送给主进程。

主进程导入流程：

1. 校验目标文档、项目 scope、payload 必填字段和非空字节。
2. 读取文件真实内容并进行图片魔数识别，不能只相信扩展名或浏览器声明的 MIME。
3. SVG 以及声明为图片但签名不是受支持栅格图片的文件直接拒绝。
4. 图片单文件上限为 10 MiB；普通附件单文件上限为 25 MiB。
5. 使用原始字节计算 SHA-256；文件名为“清洗后的原名 stem + `--` + hash 前缀 + 规范扩展名”。stem 会做 Unicode 规范化、替换危险字符、压缩空白并限制长度。
6. 同一 companion 目录中发现字节完全相同且文件名带有匹配 hash 前缀的文件时复用该文件，不重复写入。
7. hash 前缀从 12 位逐步扩展到 16/24/32/64 位以避免命名冲突。
8. 目标目录按需创建，使用原子写入；写入失败且目录原先不存在时会尝试清理空目录。
9. 返回项目相对路径、可直接写入 Markdown 的 URL、名称、种类、MIME、大小和 `reused` 标记。

生成的 Markdown URL 相对于文档所在目录，路径段进行 URL 编码，形如：

```markdown
![图片名](./文档名.assets/图片名--<sha256前缀>.png)
[附件名](./文档名.assets/附件名--<sha256前缀>.zip)
```

导入本身不会修改 Markdown；Crepe 在导入成功后才插入返回的 URL，因此失败时不会写入假链接或持久化 `blob:` URL。资产面板单文件导入成功后会把生成的 Markdown 链接复制到剪贴板。

### 4. 历史引用收编（adopt）

资产面板对 `unmanaged` 项提供收编动作：

* data URL：解码图片字节后按普通导入流程写入 companion。

* 项目内相对本地文件：读取原文件字节，要求目标是普通文件、不能是符号链接，且不能已经位于当前 companion 目录内。

* 远程 URL、绝对危险路径、无法解析的引用、目录和符号链接不能收编。

* 收编成功后，使用 AST 源码位置只替换原 URL，不重新序列化整篇 Markdown；写入前后会做一次内容一致性检查，检测到文档并发变化就拒绝更新。

* 收编会复制文件，不会删除原来的非受管文件；原引用只有在文档写回成功后才变成受管引用。

* 如果导入已经落盘但文档写回失败，当前实现没有事务性回滚，可能留下一个未引用的 orphan 文件。

### 5. 孤儿清理

* 资产面板只允许对健康状态为 `orphan` 的 companion 普通文件执行清理。

* 主进程再次列出并确认该文件仍是 orphan，确认路径的父目录必须正好是当前文档的 companion 目录。

* 目标必须是普通文件，不能是目录、符号链接或其他类型。

* 删除通过 Electron 系统回收站回调执行；成功后尝试删除空的 companion 目录，失败会保留目录。

* `referenced`、`missing`、`unmanaged` 不能通过此入口清理；删除 Markdown 引用不会自动删除文件，只会使其变为 orphan。

### 6. 外部关联文件/文件夹（`links.txt`）

这是与 Markdown 引用分离的第二套关联机制，用于发布压缩包、构建产物、HTML 目录等不适合复制进 `.iris/` 的文件或文件夹。

* 资产面板可通过系统选择器选择一个文件或目录；主进程确认目标存在且是普通文件或目录。

* 路径逐行写入当前文档 companion 目录内的 `links.txt`，UTF-8、一行一条；项目内路径存为项目相对路径，项目外路径保留绝对路径。

* 同一目标按规范化绝对路径去重；`links.txt` 本身永远不显示为普通资产。

* 列表时重新读取每一行并 `stat`，因此外部目标被移动或删除后仍保留记录，但显示为 `exists: false`、`kind: null`。

* 关联项显示名称、文件/目录类型、存在状态、文件大小和原始存储路径。

* “打开”和“在资源管理器中显示”不会复制目标；执行前主进程要求该路径仍登记在当前文档的 `links.txt` 中。

* 删除关联只从 `links.txt` 移除登记，不删除外部文件或目录；最后一条被移除时删除 `links.txt`，不会主动删除 companion 目录以外的目标。

* 当前 `links.txt` 是可手工编辑的普通文件；读取时会跳过空行，但没有 manifest 校验、注释语法或版本号。

* 当前实现对已写入的项目外绝对路径依赖登记关系进行访问确认，外部目标本身不归 Iris 所有，也不会随资产清理或文档删除被删除。

### 7. 文档删除和生命周期

* 用户通过文档删除 UI 删除 `.iris/` 下的 Markdown 时，确认界面先读取受管文件数量；数量只统计 `referenced` 和 `orphan`，不统计 missing/unmanaged，也不统计 `links.txt` 的关联项。

* 主进程把 Markdown 文件和同名 companion 目录先移动到临时 staging 目录，再把 staging 聚合整体送入系统回收站。

* companion 目录即使包含 orphan、missing 对应残留文件、`links.txt` 或其他未知内容，也会整体随文档处理。

* 任一步移动或回收站操作失败，会按已完成的步骤恢复文档、companion 目录和 staging 状态；失败通过项目错误返回 UI。

* 删除成功后不影响 `links.txt` 指向的外部目标。

* 当前没有文档重命名、移动、复制 UI，也没有对应的资产聚合迁移逻辑；外部直接移动/重命名文档时不会自动改写 companion 名称或 Markdown 相对链接。

### 8. IPC、并发和刷新

* renderer 通过 project-scoped IPC 调用 `asset:list/import/adopt/trash/link-add/link-remove/link-open/link-reveal`；所有请求都带当前项目 scope，主进程拒绝过期或跨项目请求。

* FrontCPU 为导入、收编、孤儿清理和关联增删建立 `doc:<docPath>` 与 `assets:<docPath>` 资源锁，采用 read-write 调度，避免同一文档资产操作互相覆盖。

* 资产面板打开时加载列表；收到 `.iris` 文件变更事件后，如果变化路径是文档本身或其 companion 子路径就自动刷新。

* renderer 对操作采用单面板 busy 状态，逐个导入多文件；当前不会批量事务回滚，前面成功的文件会保留，即使后面的文件失败。

* 所有业务错误会在面板内显示；shell 打开/定位、IPC 和异步边界均通过统一错误通道返回，而不是静默吞掉。

### 9. 当前安全和兼容边界

* 项目内文档、companion 目录和受管目标会做项目根路径、真实路径、符号链接和普通文件检查。

* 受管图片使用共享图片签名表；当前可识别 PNG、JPEG、GIF、WebP、AVIF，SVG 明确禁用。

* 普通附件按扩展名推断 MIME，未知扩展名使用 `application/octet-stream`，安全扩展名不超过 10 个字符。

* Markdown 中已有的 HTTPS、其他外部 URL 和未收编的本地引用保持兼容显示；Iris 不自动下载远程资源，也不自动搬移非受管文件。

* scanner 只负责跳过 `.assets`，不会主动验证 companion 文件名是否符合 hash 命名，也不会全局扫描所有文档的资产健康状态。

### 10. 目前明确存在的功能空白/行为差异

* 资产面板目前没有“替换”动作；替换只能通过编辑 Markdown、重新导入新文件或手工操作完成，旧文件会按引用状态变成 orphan。

* 没有 workspace 级资产审计、跨文档重复检测或孤儿批量清理。

* 没有文档移动、重命名、复制时的 companion 聚合处理和相对链接重写。

* 收编的“导入文件 + 写回 Markdown”不是完整事务，文档写回失败可能留下 orphan。

* 外部关联路径允许项目外绝对路径，且 `links.txt` 可手工编辑；当前主要保证“登记后才能从 UI 打开”，没有额外的外部路径所有权模型。

* 删除确认数量只覆盖受管文件，不展示关联文件/文件夹数量，也不展示 missing/unmanaged 项的影响。

* 资产目录中的未知普通文件会被当作 orphan 纳入列表；未知目录、符号链接和非普通文件会被忽略，但文档聚合删除时仍会随整个 companion 目录一起处理。

## 简化模型补充（本轮生效）

* 取消资产 SHA-256：不计算 hash、不按内容去重、不在文件名中追加 hash，也不以 hash 作为任何资产身份。

* 取消“受管资产/非受管资产”概念。资产只分为：Markdown 引用到当前文档 `.assets/` 目录的内部文件，以及 `links.txt` 登记的外部关联文件/文件夹。

* 取消 `referenced`、`orphan`、`missing`、`unmanaged` 四种健康状态和对应计数；内部文件只记录路径、名称、类型、大小、引用次数和是否存在。

* 取消 adopt/收编、trash orphan/孤儿清理及其 IPC、FrontCPU 指令和面板按钮。删除 Markdown 引用不会删除 companion 文件。

* 导入使用清洗后的原始文件名；同名文件按 `name.ext`、`name-2.ext`、`name-3.ext` 顺序落盘，不覆盖已有文件。

* companion 目录中的文件不要求必须被 Markdown 引用；目录实际存在的文件都可以在资产面板中查看和打开。

* companion 目录之外的 Markdown 本地链接、远程链接和 data URL 不作为资产条目处理；它们只是正文内容。

* 文档删除仍把文档与 companion 目录作为一个整体处理；`links.txt` 仍只登记外部路径，删除关联只移除登记，不删除外部目标。

## 待审批的其他提示词简化方案

下面只提出方案，不代表已经实施。每一项都保留“当前原版片段 / 建议修改后 / 简化原因”，请逐项审批；未获批准前不修改对应提示词或代码。

### A. Folder semantics：把扫描器内部规则改成 Agent 可执行规则 批准

当前原版：

> Typed folders — `status/`, `issue/`, `report/`, `misc/` — may appear at any depth. Any folder containing typed folders is a **workspace**; a document's type is decided by the nearest enclosing typed folder.

> Archive gesture: a workspace nested anywhere inside a `report/` folder is archived (frozen past, renders grayed).

建议修改后：

> Iris documents live in `.iris/status/`, `.iris/issue/`, `.iris/report/`, or `.iris/misc/` folders. Work in the workspace containing the focused document. Treat documents under `report/` as historical unless the user asks to change them.

简化原因：

* “任意深度”“最近 enclosing typed folder”“含 typed folder 才是 workspace”是 scanner 实现细节。

* “report 内嵌 workspace 的 archive gesture”是 UI 投影规则，Agent 不需要理解灰显和冻结状态。

* Agent 只需要知道文档类型和写回范围。

### B. Issue 状态机：只保留 Agent 需要的状态操作 批准

当前原版：

> Issues: `Todo` -> `In Progress` -> `In Review` -> `Done`, with `Blocked` as an active side state, `On Hold` as an inactive but unresolved state, and `Canceled` as a terminal side state.

> Never make an issue inactive unprompted. A transition to `On Hold`, `Done`, or `Canceled` ... may close attached terminal sessions; those transitions are the user's call.

建议修改后：

> Issues normally move from `Todo` to `In Progress` and then `In Review`. Do not mark an issue `Done`, `Canceled`, or `On Hold` unless the user explicitly asks. You may move an issue to `In Review` when the work is ready for review.

简化原因：

* Agent 不需要知道状态对终端会话的副作用。

* `Blocked`、`On Hold` 的 active/inactive 语义属于 UI 过滤器，不是写回行为核心。

* 保留“不要擅自关闭 issue”和“可以推进到 In Review”即可。

### C. Focus protocol：删除注入实现细节 批准

当前原版：

> For agents with a SessionStart hook it injects only dynamic context: `<iris-workspace>` ... `<iris-focus>` ... The session environment variables and reading the focus from disk are a FALLBACK.

建议修改后：

> If Iris provides a focused document or workspace snapshot, use it as the initial context. If no snapshot is provided and `FOCUS_DOC` is available, read that document first. Do not reread unchanged injected context.

简化原因：

* SessionStart hook、环境变量 fallback 和动态腿/静态腿是 Iris 内部实现。

* Agent 只需要一个优先级：先使用已注入上下文，再按需读取 focus 文件。

### D. Write-back scope：简化 workspace 写回说明 批准

当前原版：

> Write results into the nearest workspace enclosing `$FOCUS_DOC`. Do not create new workspaces unless asked.

建议修改后：

> Write results beside the focused document, within its existing `.iris/` workspace. Do not create a new workspace unless the user asks.

简化原因：

* “nearest workspace enclosing”是 scanner 术语。

* “写回 focused document 所在 workspace”对 Agent 已足够明确。

### E. No unsolicited files：压缩创建文件边界 批准

当前原版：

> Never create a new document in a typed folder — reports included — or a new companion asset unless the user explicitly asks. This restriction does not apply to project source, tests, configuration, or other files needed for an authorized implementation task. Editing the focused document is always fine, as are frontmatter updates ...

建议修改后：

> Do not create new `.iris/` documents or assets unless the user asks. For an explicitly requested implementation task, you may create the required source, test, and configuration files. You may edit the focused document and its frontmatter.

简化原因：

* 保留真正重要的边界：不要擅自创建 Iris 文档；授权实现可以创建代码文件。

* 删除“typed folder/report included/companion asset/frontmatter transition”这类重复解释。

### F. Issue 历史保护：允许用户明确要求整理 批准

当前原版：

> Treat the body as a record: prefer appending updates; do not rewrite or delete existing content unprompted.

建议修改后：

> Preserve issue history by default and append updates. If the user explicitly asks to reorganize, rewrite, or remove content, follow that request.

简化原因：

* 当前规则容易让 Agent 在用户明确要求整理 issue 时仍拒绝修改。

* “默认保留、明确授权可改”更符合用户意图优先级。

### G. Checkbox：从绝对规则改成面板用途说明 拒绝

当前原版：

> Anything that awaits someone's action ... must be written as task checkboxes, one per discrete item, never as prose or plain bullets: a pending item written as prose is invisible to the panel.

建议修改后：

> Use GFM task checkboxes for items that should appear in Iris's todo panel. Use normal prose or bullets for background, explanations, and completed work.

简化原因：

* 当前绝对禁止普通 bullet，会把说明性内容错误变成任务。

* 只说明 checkbox 的产品用途即可。

### H. Managed prompt blocks：允许用户明确授权修改 拒绝

当前原版：

> Never modify the `<iris-software>` or `<iris-project>` blocks.

建议修改后：

> Do not modify Iris-managed prompt blocks as part of ordinary work. If the user explicitly asks to change the Iris prompt, follow that request and preserve the block structure.

简化原因：

* 当前“Never”与用户明确要求存在冲突。

* 保留默认保护，同时承认用户可以授权修改。

### I. Markdown 格式：删除 remark 实现名词 批准

当前原版：

> Write plain CommonMark. Iris's editor serializes with fixed remark defaults; match them to keep diffs quiet.

建议修改后：

> Write standard Markdown and preserve the document's existing formatting where practical.

简化原因：

* Agent 不需要知道 Iris 使用 remark。

* “fixed defaults”会诱导模型猜测编辑器内部序列化规则。

### J. Naming：把命名规则限制在必要范围 拒绝

当前原版：

> New files in `issue/` and `report/` use a `YYYY-MM-DD-<slug>` prefix.

建议修改后：

> New issue and report documents use the project's date-prefixed naming convention.

简化原因：

* 具体 slug 格式可以由应用创建文档时保证，Agent 不必承担文件名拼接细节。

* 如果保留日期前缀要求，使用自然语言即可。
