切换到某个终端后，偶发（低概率）出现内容没有加载出来的状态，视觉上像空白 / 未完成 replay，有时"动一下"（resize、敲键）才重新画出来。

本 issue 从《【长期跟踪】性能问题专项》拆出，便于独立处理。下面是 2026-06-19 复查 replay 链路（`RightPane` → `TerminalView` mount effect → 主进程 `getScrollbackForReplay`）后的定位。6-14 的 seq 边界修复已堵住"清屏后 redraw 被误丢"的丢包路径，但空白的根因不止那一处。

## 根因（按可疑度排序）

### 1. 结构性根因（最该改）：每次切会话都整体销毁重建

`RightPane.tsx:214` 只挂一个 `<TerminalView key={shownSession.id}>`。key 绑 sessionId ⇒ 每次切换都是完整 unmount + remount：销毁旧 xterm/WebGL/各 addon → 新建 → 请求 serialize 快照 → base64 回传 → 解码 → 分片 write → fence → reveal。这条链上任意一环抖动，用户看到的都是"切过去空白"。空白不是孤立 bug，而是"销毁-重放每次都来一遍"这个范式的故障面。

证据：

- `src/renderer/components/layout/RightPane.tsx:214` —— 单实例、`key={shownSession.id}`，无隐藏保活。
- `src/renderer/components/terminal/TerminalView.tsx` 整个 mount effect（`[sessionId]` 依赖）每次切换全量重建。

durable 修法：把切换从"销毁/重建"改成"保活/隐藏"——同一锚点下最近 N 个 `TerminalView` 常驻挂载，用 `display:none` / 绝对定位错层切换可见性，而不是 unmount。没有重放就没有重放竞态，也没有 WebGL 上下文翻动，空白面直接消失。这是最该做的一步，同时干掉下面 #2、#3。

### 2. WebGL 上下文翻动：切换频繁时新建上下文可能失败

每次 remount 都 `new WebglAddon()`（`TerminalView.tsx:466-481`），即新建一个 WebGL 上下文，unmount 时 dispose。浏览器对同时存活的 WebGL 上下文有上限（约 16 个），dispose 又非同步立即回收。频繁切换 / dev 下 StrictMode 双挂载 / 旧上下文回收滞后时，`new WebglAddon()` 可能抛错被 catch 落到 DOM 渲染——功能上能回退，但已知 xterm 在"WebGL 上下文创建失败或中途丢失"后，首帧画布可能空白，直到下一次 resize/refresh 才重绘。`onContextLoss` 里只 dispose+置 null，没有强制 `term.refresh()`。这条和现象"切过去空白、动一下才出来"高度吻合。

### 3. fence 窗口里的二次写竞态（6-14 修复的镜像问题）

headless 镜像在 `handlePtyData` 里逐 chunk 即时 `headlessTerm.write(data)`（`session-manager.ts:494`），而 replay 的 seq 边界冻结在 flush 批边界（`getScrollbackForReplay` 里 `replayLastSeq = managed.scrollbackLastSeq`，`session-manager.ts:435`）。两者粒度不一致：`await term.write('', cb)` 这段 await 期间到达的 chunk 会即时写进 headless（可能进快照），且 seq 一定 > `replayLastSeq`（一定被 renderer 当 live 补写）。是否进快照取决于 xterm `_innerWrite` 是否在同一同步批里连带解析了它——时序竞态。命中时该帧被写两遍。对 alt-buffer TUI 整屏重绘多半幂等（看不出），对行模式输出会重复行。它不直接产生纯空白，但属同一处时序裂缝。

根因一句话：headless 镜像按 chunk 即时写入，而 replay 的 seq 边界按 flush 批冻结，两者粒度不一致，fence 只能保证冻结点之前已入队的部分，盖不住 await 期间新到的 chunk。

## 建议落地顺序

1. 先用已埋好的性能监视器抓一次真实空白（零改动定性）：复现时看 `terminal.replay.serialize` 的 `ansiBytes`、`terminal.replay.ipc` 的 `base64Bytes`、`holdQueueFlushed/Filtered`、`fenceTimeout`、`replay.failed`。据此区分是"快照本身为空 / IPC 超时降级 / 有数据但没画出来（→ 指向 #2 WebGL）"。
2. 做 #1 TerminalView 保活（隐藏而非销毁），根治手段。
3. 若保活短期不做，先给 #2 兜底：`onContextLoss` 与 WebGL 创建失败回退后，reveal 时强制一次 `term.refresh(0, term.rows - 1)`；并评估把默认渲染器降为 DOM/canvas，验证空白是否消失。
4. #3 精确修法：让 headless 写入也走 seq-gated 的批（与 emit 同源推进），或在冻结 `replayLastSeq` 后、serialize 之前对 await 期间到达的 chunk 显式排除，使"进快照"和"> replayLastSeq"严格互斥。
