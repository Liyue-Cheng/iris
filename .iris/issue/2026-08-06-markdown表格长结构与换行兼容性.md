# Markdown 表格长结构与换行兼容性

## 现象

兼容性测试文档的“表格单元格中的长结构” case 暴露出一个需要单独处理的问题：表格单元格包含长行内代码、不可断字符串、长链接或较长中文文本时，换行策略和表格宽度行为不明确。

重点复现内容是长行内代码：

`const documentMeta = { title: "Markdown 渲染兼容性测试", reflects: "c07af2434e26b5bfb6d5899fa131954062396ade" }`

需要确认它在表格单元格中不会撑破页面，并且换行后仍保持代码样式和可读性。

复现入口：`.iris/status/Markdown 渲染兼容性测试.md` 第 7 节“表格单元格中的长结构”。

## 研究结论

这不是 Markdown/GFM 解析器的 bug。Crepe 能把该段解析成表格、单元格和行内 `code` 节点；问题发生在 M2 WYSIWYG 的 CSS 布局层：

1. 当前正文实际由 `src/renderer/components/doc/CrepeEditor.tsx` 挂载 Milkdown Crepe（该文件第 38–39 行只引入 Crepe 默认主题）。旧的 `.markdown-body { overflow-wrap: break-word; }` 位于 `global.css` 的 M1 只读预览样式，当前 `.crepe-host` 下的 ProseMirror 表格不会继承它。
2. Crepe 默认 reset 将 `.ProseMirror code` 设为 `display: inline-block`。长行内代码因此是一个不可拆分的行内盒；只要其中最长不可断 token 大于该列可用宽度，就会溢出，而不是在 token 中断开。
3. Crepe 的表格组件实际生成 `.table-wrapper`（`@milkdown/components` 的 `table-block/view/component.tsx`），但它引入的 ProseMirror 表格 CSS 只匹配 `.ProseMirror .tableWrapper`。因此默认的 `overflow-x: auto` 没有命中当前 DOM，横向滚动兜底也失效。表格本身仍被设为 `table-layout: fixed; width: 100%`，所以溢出会表现为内容撑出/遮挡，而不是稳定的容器滚动。

责任拆分：解析行为属于正常结果；`.table-wrapper`/`.tableWrapper` 选择器不一致和行内代码 `inline-block` 是 Milkdown/Crepe 默认主题与表格组件的上游缺口；Iris 的集成层没有为 `.crepe-host` 补上长 token 断行和表格容器策略，所以最终问题在 Iris 中暴露。修复时应同时决定长 token 使用 `overflow-wrap: anywhere`，以及表格在极窄宽度下采用断行还是容器横滚，不能只调整 Markdown 文本。

## 待处理

- 明确表格单元格对长行内代码和不可断字符串的换行或横向滚动策略。
- 检查长链接、长中文文本以及混合格式内容是否会撑宽表格或遮挡相邻列。
- 保证窄屏、宽屏和编辑/阅读模式切换时表格宽度与行高稳定。

## 验收

- [ ] 长行内代码在表格单元格中不会撑破页面，换行后仍保持代码样式。
- [ ] 不可断字符串、长中文文本和长链接按预期换行或进入稳定的容器滚动，不遮挡其他列。
- [ ] 混合格式与转义竖线仍能正确解析，表格列不会因内容异常扩张。
- [ ] 浅色/深色主题及窄屏、宽屏下均完成复测。
- [ ] 编辑模式与阅读模式切换时表格布局无明显跳动。
