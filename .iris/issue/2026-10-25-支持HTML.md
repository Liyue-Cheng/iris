目前iris仅仅支持md一种文件类型，你认为是否需要支持HTML？要是支持HTML，应该不能实现实时编辑了吧，还是市面上连这种编辑器都有？

***

## 调研结果（2026-10-25）

### 结论速览

1. **值得支持，但定位是"以渲染为主的文档"，而不是第二种 md。** HTML 最适合 `report/`（分析、评审、方案对比、带图表的总结）这种"写一次、主要给人读"的文档。`issue/`、`status/` 需要追加历史、勾 checkbox、改 frontmatter 状态，这些仍然应该用 md。
2. **"所见即所得地编辑任意 HTML"市面上有，但都有损。** 不丢信息的做法只有"源码 + 实时预览"。所以 Iris 第一版建议做：**沙箱渲染预览 + CodeMirror 源码编辑 + 保存后预览实时刷新**，不做 WYSIWYG。
3. **为什么现在值得做：** AI agent 越来越多直接产出 HTML（下面有来源）。Iris 本来就是给 agent 用的文档工具，如果 agent 写出的 `.html` 在 Iris 里完全看不到，会越来越别扭。

### 1. 为什么值得支持：agent 正在大量产出 HTML

* Claude Code 团队的 Thariq Shihipar 于 2026-05-20 发文 *[Using Claude Code: The unreasonable effectiveness of HTML](https://claude.dev/blog/using-claude-code-the-unreasonable-effectiveness-of-html/)*，主张用 HTML 代替 Markdown 作为 agent 的输出格式。理由是信息密度更高（表格、SVG 图、交互控件、排版）、长文更容易读、可以直接分享链接。他列出的用途有方案对比、实现计划、PR 讲解、状态报告和事故报告、幻灯片，以及"一次性小编辑器"。
* 文章里还有两点和 Iris 直接相关：
  * 作者说自己**几乎不再手改这些文件**，要改就让 Claude 改，人只在页面 UI 上操作或导出。所以对 HTML 来说，"人手工编辑"的需求本来就比 md 低。
  * 文章**没有讨论** diff、review、版本管理、合并冲突这些问题。
* 反对的声音（[mdflow：Output vs. Storage](https://mdflow.cz/blog/html-is-the-new-markdown)、[agentpatterns.ai](https://agentpatterns.ai/instructions/html-as-output-format/)）认为：md 省 token，任何模型都能直接读源码，逐行 diff 友好，适合作为持久的底稿。比较主流的折中是"**需要人读、要交互时用 HTML；要进仓库、反复 review 的用 md**"。

这和 Iris 的文件夹语义正好对应：`report/` 按协议本来就是"有日期的历史分析"，适合 HTML；`issue/` 和 `status/` 是要持续维护的工作底稿，适合 md。

### 2. 能不能"实时编辑"HTML：市面上的三类编辑器

| 类型                     | 代表                                                                                                                                                                                                 | 能做什么                     | 代价                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 富文本编辑器（基于 schema）      | Tiptap / ProseMirror（Milkdown 底层也是它）、CKEditor 5、TinyMCE、Lexical                                                                                                                                    | 编辑 HTML **片段**（段落、列表、表格） | schema 里没定义的标签、属性、样式会被**直接丢掉**。[Tiptap FAQ](https://tiptap.dev/docs/guides/faq) 明说 ProseMirror 没有配置能改变这一点。CKEditor 5 的 [General HTML Support](https://ckeditor.com/docs/ckeditor5/latest/features/html/general-html-support.html) 可以选择保留，但内部仍会归一化到自己的模型再输出，结构会变（[#16203](https://github.com/ckeditor/ckeditor5/issues/16203)）。脚本、`<style>`、整页布局都处理不了。 |
| 可视化网页编辑器（page builder） | Dreamweaver Live View、[Pinegrow](https://pinegrow.com/release_notes/pinegrow-web-editor-10-1/)、GrapesJS、Obsidian 插件 [HTML Visual Editor](https://community.obsidian.md/plugins/html-visual-editor) | 编辑整页：拖拽元素、改样式、改文字        | GrapesJS 把 HTML 解析成自己的组件模型再导出，格式、注释、属性顺序都会变，官方建议存它的 project JSON，而不是存 HTML。Pinegrow 花了多年才做到"关掉自动格式化后，未改动的代码基本保持原样"，即便如此仍会改引号和标签内空白。这是一个完整的专业产品，不适合当 Iris 的一个子功能来做。                                                                                                                                                                                    |
| 源码 + 实时预览              | VS Code Live Preview、Brackets、Obsidian 插件 [HTML Works](https://community.obsidian.md/plugins/html-works)                                                                                           | 改源码，预览即时刷新               | **无损**。HTML Works 明确写着"预览不会改写你的 HTML，只保存源码编辑"，连 CRLF 都原样保留。                                                                                                                                                                                                                                                                                           |

**本质难点：** md 能做无损 WYSIWYG，是因为 md 本身的表达能力窄，基本能和编辑器的 schema 一一对应。任意 HTML 没有这种对应：

* 有 CSS 和脚本；
* 脚本会在运行时修改 DOM，如果把"当前 DOM"序列化回文件，运行时状态会被写进源码；
* 一个视觉效果可以由很多种源码写法得到，反向映射回原来的写法本身就是难题。

Obsidian 生态的做法可以作为参考：它原生不支持 `.html`，社区插件基本都选了"预览 + 源码"这条路（[HTML Works](https://community.obsidian.md/plugins/html-works)、[HTML Page Viewer](https://community.obsidian.md/plugins/html-page-viewer)、[HTML Reader](https://www.obsidianstats.com/plugins/obsidian-html-plugin)），默认关闭脚本，沙箱运行。

所以回答原问题：**实时预览完全可以做到；无损的所见即所得做不到；有损的 WYSIWYG 存在，但不适合 agent 生成的整页 HTML。**

### 3. 现有代码里写死只支持 md 的地方

* 扫描：`src/main/iris-scanner.ts:171` 只收 `.md`。
* 新建文档：`src/main/project-manager.ts:410` 固定生成 `${baseName}.md`。
* 资源目录：`src/main/asset-manager.ts:265` 要求宿主文档是 `.md`。
* 文档间跳转：`src/renderer/lib/markdown-navigation.ts:68` 只把 `.md` 链接当成文档链接。
* 元数据：读在 `src/main/iris-scanner.ts:86`（gray-matter），写在 `src/renderer/lib/issue-actions.ts` 和 `editor-store.setFrontmatterField`。两者都基于 YAML frontmatter。
* 编辑器：`src/renderer/components/doc/DocView.tsx:210` 只在 Crepe（WYSIWYG）和 SourceEditor（CodeMirror）之间切换。`@codemirror/lang-html` 已经作为 `language-data` 的依赖装在 node\_modules 里。
* 安全：
  * 主窗口 `sandbox: false`（`src/main/app-main.ts:324`）。
  * 渲染页的 CSP 是 `script-src 'self'`（`src/renderer/index.html:7`）。
  * 已有 `setWindowOpenHandler` 和 `will-navigate` 拦截。
  * **没有 `setPermissionRequestHandler`。**
* 协议文本：`src/main/iris-templates.ts:80` 一带向 agent 声明的是"frontmatter 字段"，没有 HTML 的元数据约定。

### 4. 建议方案（尚未实施，等你确认）

**4.1 元数据载体：用 `<title>` 和 `<meta>`，不用 YAML frontmatter**

在 HTML 顶部写 `---` frontmatter 的话，浏览器打开时会把它当正文显示出来，破坏"HTML 可以直接分享"这个核心价值。建议：

```html
<head>
  <title>2026-10 终端稳定性评审</title>
  <meta name="iris:status" content="Active">
  <meta name="iris:labels" content="...">  <!-- 保留字段，原样保存 -->
</head>
```

* 读取：解析 `<head>`。
* 写回：和现在 `setFrontmatterKey` 一样做最小文本手术，只替换或插入那一行 `<meta>`，不经过任何 DOM 序列化，以保证无损。
* 缺少 `<head>` 时视为没有元数据，title 退回用文件名。

**4.2 查看：沙箱 iframe，通过自定义协议加载，而不是用 `srcdoc`**

* `srcdoc` 有两个问题：
  * 它会**继承父页面的 CSP**，Iris 现在的 `script-src 'self'` 会让内联脚本全部失效；
  * 它的 base URL 是 `about:srcdoc`，`./xxx.assets/img.png` 这类相对路径会全部失效。
* 改用主进程注册一个只读协议（例如 `iris-doc://<project>/<relPath>`）：
  * 只允许访问项目根目录内的文件；
  * 由协议响应头给这份文档单独下发 CSP；
  * 这样相对路径的资源能正常加载，也方便和"脚本开关"联动。
* iframe 的 `sandbox`：
  * 默认空值，即**不执行脚本**；
  * 每篇文档可以单独"信任并运行脚本"，此时只加 `allow-scripts`；
  * **永远不加 `allow-same-origin`**，两者同时开启时，页面可以拆掉自己的沙箱。
* 网络：默认 CSP 禁止外网请求。但 agent 生成的 HTML 经常用 CDN（Chart.js、mermaid、Tailwind CDN），这需要你取舍（见下方待决项）。
* 补上 `session.setPermissionRequestHandler`，默认拒绝所有权限请求（包括 openExternal）。参考 Electron 的 iframe 沙箱 CVE-2026-70612：当前用的 Electron 43.8.3 已经是修复后的版本，但官方建议仍是装一个权限 handler。见 [Electron Security](https://www.electronjs.org/docs/latest/tutorial/security)。

**4.3 编辑：复用 SourceEditor，加上 HTML 语言模式和预览刷新**

* HTML 文档的两种模式是"预览 / 源码"，而不是 md 的"WYSIWYG / 源码"。
* 源码模式下，可以选左右分栏，预览在停止输入后防抖刷新。
* 外部改动的 reload 和冲突提示沿用现有的 editor-store 机制。agent 改了文件，预览会自动刷新，这本身就是用户感受最明显的"实时"。

**4.4 范围控制**

* 扫描器在各个 typed 文件夹都识别 `.html` / `.htm`，因为 agent 可能写在任何地方。
* 新建对话框只在 `report/`（以及可能的 `misc/`）提供 HTML 选项。
* 协议文本补一段 HTML 文档的元数据约定，并说明 issue 仍然必须用 md。
* 资源目录（`<name>.assets/`）和 `links.txt` 模型对 HTML 同样适用。
* 只做轻量的 HTML 片段工具（比如插入资源时生成 `<img>` 而不是 md 语法）。

**4.5 明确不做（第一版）**

* 任何形式的 HTML WYSIWYG。
* 在预览里直接点击改文字（`contenteditable` 再回写到源码）。如果以后要做，只能限定在"纯文本节点改字"并配合源码位置映射，成本高，收益也不确定。

### 5. 风险与未验证项

* 以上都是调研和代码阅读的结论，**没有写原型，也没有实测**。
* 文章里"agent 产出 HTML 是趋势"的判断，主要来自 Anthropic 员工的博客和第三方评论，属于业界观点，不是定论。
* 自定义协议和 iframe 在 Electron 43 下的具体行为没有验证，包括响应头 CSP 是否生效、sandbox 下的跨源资源加载。
* 外部 `.html` 文件可能很大，也可能含有恶意脚本。默认不执行脚本可以缓解，但"信任"开关的交互需要设计。

## 实施结果（2026-10-25）

按上面的决策落地：HTML 可以出现在任意 typed 文件夹，新建入口只在 `report/`；元数据用 `<title>` + `<meta name="iris:*">`；设置里有全局开关控制外网。代码已改完，**没有提交**。

### 和原方案不同的地方（需要你确认）

* **脚本开关从"每篇文档单独信任"改成了全局设置**："HTML 预览运行脚本"，默认**开**。原因有两个：
  * 和你选择的"外网全局开关"保持同一套交互；
  * 单篇信任需要一个持久化存储位置，目前还没定。

  脚本始终在 opaque origin 的沙箱里运行，访问不到 Iris，也拿不到其他项目文件的内容；关闭外网时也无法外传数据。
* **外网开关"HTML 预览允许联网"默认关**：用 CDN 的页面在默认状态下会缺样式或缺图表。

### 文件级改动

**共享层（新增）**

* `src/shared/html-doc.ts`：
  * 格式识别（`.html` / `.htm`）；
  * head 元数据的读写，做法和 frontmatter 一样是"文本手术"：只替换 `<title>` 的文字或 meta 的 `content` 值，缺失时插到 `</head>` 前，自动补 head，并保留缩进和 CRLF；
  * 注释和 script/style 的内容会先被屏蔽，所以 script 字符串里出现的 `<title>`、body 里的 SVG `<title>` 都不会被误匹配；
  * 资源引用提取（src / href / poster / data）；
  * 新页面骨架和资产片段（`<img>` / `<a>`）。
* `src/shared/doc-fields.ts`：按格式分派字段读写（Markdown 走 frontmatter，HTML 走 head）。

**主进程**

* `iris-scanner.ts`：扫描时识别 `.html`；HTML 的元数据来自 head，todos 为空。
* `project-manager.ts`：
  * `readDoc` 对 HTML 返回整页作为 body；
  * `createDoc` 新增 `format` 参数，**只有 report 允许 html**，其他文件夹拒绝；
  * 新建时如果已有同名 `.md`、`.html` 或 `.htm`，名字自动加 `-2`，因为它们会共用同一个 `<name>.assets/` 目录；
  * `deleteDoc` 允许删除 `.html`。
* `asset-manager.ts`：HTML 文档也可以有 `.assets/`，引用计数改用 HTML 属性。
* `html-doc-protocol.ts`（新增）：
  * `iris-doc://<token>/<相对路径>` 协议。token 是每个窗口、每次项目代际随机生成的，切换项目或关闭窗口后失效；
  * 只服务项目根目录内的文件（会做 realpath 校验），不发 CORS 头；
  * 每个响应都带 CSP，内容按设置生成：默认 `default-src 'none'`，本地资源放行，联网关闭时 `connect-src 'none'`；
  * 所有来自子 frame 的权限请求一律拒绝，包括 openExternal；
  * 预览里的链接：跳到项目内的文件允许；`http(s)` 和 `mailto` 交给系统浏览器打开，每秒最多 1 次；其他一律丢弃。
* `index.ts` 在 ready 之前注册 scheme；`app-main.ts` 安装协议处理和导航守卫，窗口关闭时回收 token。
* `ipc.ts` 和 `shared/protocol.ts`：新增 `doc:preview-base` 通道。
* `settings-manager.ts` 和 `types.ts`：新增 `behavior.htmlPreviewScripts`（默认 true）和 `behavior.htmlPreviewNetwork`（默认 false），并加了校验。
* `iris-templates.ts`：协议文本里补充了 "HTML documents" 一节：
  * 元数据约定；
  * **Markdown 是所有文档的默认格式，只有用户明确要求时才写 HTML**；不得自行选择 HTML，不得把现有 md 转成 HTML，不得用 HTML 往 issue 里追加内容（2026-10-25 按你的要求收紧）；
  * 写 HTML 时页面要自包含。

  **注意：** 下次打开项目时，app 会把这段同步进 `AGENTS.md` 和 `CLAUDE.md` 的 `<iris-software>` 块，git 里会出现对应的 diff。

**渲染进程**

* `HtmlPreview.tsx`（新增）：
  * `<iframe sandbox>`，**永远不加 allow-same-origin**；开脚本时用 `allow-scripts allow-popups`，关脚本时只有 `allow-popups`；
  * 内容的指纹或设置一变，iframe 就重建。所以 agent 改了文件、自己保存了、切换了开关，预览都会自动刷新。
* `editor-session.ts` 和 `editor-store.ts`：
  * HTML 会话内部始终是 source 模式，另用 `htmlPreview` 标志切换"预览 / 源码"两个视图；
  * 切到预览前会先保存，因为预览显示的是磁盘上的文件；
  * 在 head 里改标题或状态都是文本手术；如果当时停在源码视图，会让 CodeMirror 重新挂载。
* `TypedHeader.tsx`：HTML 的标题和状态可以编辑，模式按钮在"源码"和"返回预览"之间切换。
* `SourceEditor.tsx`：HTML 文件使用 `@codemirror/lang-html` 高亮。这个包原本就以传递依赖的形式装着，现在在 `package.json` 和 lock 里显式声明了。
* `CreateDocDialog.tsx`：新建 report 时可以选 Markdown 或 HTML 页面。
* `issue-actions.ts`：集合视图（issue 面板等）改状态时按格式分派；HTML 没有 checkbox，所以不会被"Done 时自动勾选"影响。
* `markdown-navigation.ts`：Markdown 里指向 `.html` 文档的链接会在 Iris 内打开。
* `asset-actions.ts` 和 `AssetPanel.tsx`：在 HTML 文档里，复制或导入资产时生成的是 HTML 片段。
* `doc-utils.ts` 和 `RightPane.tsx`：没有标题时，文件名回退显示会去掉 `.html` 后缀。
* `index.html`：渲染页的 CSP 增加 `frame-src iris-doc:`。
* 设置页的编辑器分组加了两个开关，`resources.ts` 补了中英文文案。

### 协议提示词改动（`src/main/iris-templates.ts` 中的 `SOFTWARE_PROMPT_TEMPLATE`）

这是 `<iris-software>` 块的源文本。app 打开项目时会把它同步进 `AGENTS.md` 和已存在的 vendor 入口文件（例如 `CLAUDE.md`），内置 Iris Agent 也直接使用它。一共四处改动，下面是最终版本。

**1. 新增一节 `## HTML documents`**，位于 "Document fields and statuses" 之后、"How context reaches you" 之前：

```markdown
## HTML documents

Iris also recognizes `.html` documents in typed folders. They carry the same
fields in the page head instead of frontmatter: `<title>` is `title:`, and
`<meta name="iris:status" content="…">` is `status:` (likewise
`iris:labels` for the reserved `labels:` field). Edit those elements in place
and leave the rest of the page unchanged.

Markdown is the default format for every Iris document. Write an HTML document
only when the user explicitly asks for HTML; never choose HTML on your own,
convert an existing Markdown document to HTML, or append to an issue in HTML.
When the user does ask for one, keep it self-contained (inline CSS and scripts,
local files in the companion directory): Iris previews HTML in a sandbox that
may block network access.
```

**2. 开头第二行：**

```diff
- All PM artifacts are plain markdown files under `.iris/`, in typed folders.
+ All PM artifacts are plain Markdown (or HTML) files under `.iris/`, in typed folders.
```

**3. "Document assets" 第一段**：资产目录不再只属于 Markdown 文档，HTML 文档用 `src` / `href` 引用资产。

```diff
- Each Markdown document may have a sibling `<name>.assets/` directory. Files
- inside that directory are internal document files and may be referenced with
- ordinary relative Markdown links such as `./<name>.assets/image.png`.
+ Each document may have a sibling `<name>.assets/` directory. Files inside that
+ directory are internal document files and may be referenced with ordinary
+ relative links such as `./<name>.assets/image.png` (Markdown links, or
+ `src`/`href` attributes in HTML documents).
```

**4. 结尾一句：**

```diff
- Write standard Markdown and preserve the document's existing formatting where
- practical.
+ Write standard Markdown (or well-formed HTML in HTML documents) and preserve the
+ document's existing formatting where practical.
```

### 已知限制和未验证项

* 下面几点是按 Electron 文档推断的，没有实测：
  * `protocol.handle` 返回的 CSP 响应头在 iframe 里是否生效；
  * dev 模式下 `http://localhost` 父页面能不能嵌入 `iris-doc:` iframe；
  * 沙箱 iframe 里的相对资源能否正常加载。
* `type="module"` 的脚本需要 CORS，而为了不让预览脚本读取项目文件，协议故意不发 CORS 头，所以 ES module 脚本加载不了，只支持经典 `<script>`。
* 预览重新加载后滚动位置会丢失。
* 预览只显示已保存的内容；如果关闭了自动保存，源码改完要先切到预览（会自动保存）或按 Ctrl+S。
* 脚本里调用 `window.open` 不受那个每秒 1 次的限制，只要是 http(s) 就会直接打开系统浏览器。恶意页面可以借此骚扰，但读不到任何数据。
* 顺带发现一个疑似**既有 bug**（Markdown，这次没有改）：在源码模式下通过标题栏改 title 或 status，CodeMirror 不会重新挂载；之后再敲一个键，`sourceText` 会回到改之前的版本。见 `editor-store.ts` 的 `applyFmBlock`。HTML 这边已经通过 bump generation 避开了。
