现在，这个软件各个md的asset没有很好的管理，这是不行的，必须有良好的管理，你现在给我个方案

## 方案结论

采用“文档 + 同目录 companion asset 目录”的聚合模型。每篇 Markdown 的受管资产都放在它旁边、与文档同名并以 `.assets` 结尾的目录中：

```text
.iris/
  issue/
    2026-08-08-iris协议补完：asset.md
    2026-08-08-iris协议补完：asset.assets/
      upload-flow--c34ab87d2e10.png
      requirements--977e83ca12f.pdf
```

正文只写标准相对链接：

```markdown
![上传流程](./2026-08-08-iris协议补完：asset.assets/upload-flow--c34ab87d2e10.png)

[需求原件](./2026-08-08-iris协议补完：asset.assets/requirements--977e83ca12f.pdf)
```

不增加 `assets:` frontmatter，不维护 manifest，不建立全局数据库。磁盘文件和 Markdown 引用本身就是唯一真相。集中式 `.iris/assets/` 虽能跨文档去重，但会模糊所有权，让删除、复制、子 workspace 迁移和孤儿判断都变复杂，不适合 Iris 的文档中心模型。

## 协议规则

### 所有权与边界

1. `<name>.md` 只拥有同目录的 `<name>.assets/`；目录在首次导入时按需创建，不创建空目录。
2. 一份资产只能由一篇文档拥有。另一篇文档使用相同文件时，复制到自己的 companion 目录；不跨文档引用别人的 `.assets/`。
3. `.assets/` 是保留后缀，属于最近的 Markdown 文档，不是 workspace，也不参与 `status/issue/report/misc` 类型推断。
4. scanner、todo 收集和文档树必须跳过 `.assets/` 子树，避免其中的 `.md` 附件被误识别为 PM 文档；Raw Tree 可以展示它，但应标记为资产目录。
5. 资产仍位于最近的 typed folder 内，因此不扩大 agent 的写回 workspace，也不破坏“不要写出 typed folders”的现有边界。

### 文件名与写入

1. 文件名格式为 `<清洗后的原名>--<SHA-256 前 12 位>.<规范扩展名>`；同一文档重复导入相同内容时复用已有文件。
2. hash 以实际字节计算，扩展名由检测到的 MIME 决定，不能只信任用户提供的扩展名。若短 hash 真正碰撞，自动扩展 hash 长度。
3. 已被引用的资产视为不可变对象。替换图片或附件时写入新文件并改 Markdown 链接，不原地覆盖旧文件。
4. 写入采用临时文件、刷新并原子 rename；失败时不插入 Markdown 链接，也不留下半文件。
5. Git 默认跟踪资产；不把它们写进 `.gitignore`，不把二进制编码成 data URL 塞入 Markdown。

### 引用分类

* `./<doc>.assets/...`：受管资产，Iris 负责导入、审计、移动和清理。
* 其他项目内相对路径：兼容的非受管引用，继续渲染，但 Iris 不擅自移动或删除。
* `https:`：外部资源，继续允许；提供“导入本地”动作后才转为受管资产。
* `blob:`：只允许编辑器内部瞬时使用，禁止保存到 Markdown，因为重启后必然失效。
* `data:`：已有文档可兼容读取，但新内容不生成；提供转存为受管资产的修复动作。
* 绝对路径、`file:`、越界的 `..`、符号链接逃逸和危险协议：拒绝。

引用发现、孤儿判断和链接改写必须基于 Markdown AST，不能用正则扫描正文。改写时只修改 URL 对应的源码范围，不能为改一条链接而重新序列化整篇文档。

### 生命周期

1. 粘贴、拖入或文件选择：先把字节交给主进程落盘，成功后再由 Crepe 插入返回的相对 URL。当前默认 `URL.createObjectURL(file)` 的路径必须被替换，否则会把重启即失效的 `blob:` 写入正文。
2. 重命名或移动：文档和 companion 目录是一个逻辑聚合，Iris UI 必须在一次操作中移动两者并改写该文档的相对链接。当前尚无重命名 UI；外部只移动 `.md` 时由审计提示修复，不能静默猜测。
3. 删除：人类在 UI 删除文档时，确认框明确显示将连同多少个资产处理；使用系统回收站处理文档和 companion 目录。agent 仍受“issue 不得自行删除”的既有规则约束。
4. 替换或删除引用后，文件先成为 orphan，不即时自动删除。资产面板提供按文档和按 workspace 的审计，列出 `referenced`、`orphan`、`missing`、`unmanaged` 四种状态；只有人类确认后才清理 orphan。
5. 复制文档到另一 typed folder 或 workspace 时复制整个聚合并重新计算相对链接；不能留下指向原 workspace 的隐式依赖。

### 安全与限额

首期可编辑预览只开放现有安全图片集合：PNG、JPEG、GIF、WebP、AVIF，单文件沿用当前 10 MiB 上限；SVG 继续禁用，因为其主动内容安全面明显更大。普通附件首期只做落盘、链接、在资源管理器中显示和显式打开，不尝试内嵌执行或预览。所有资产操作都必须校验 project scope、真实路径、普通文件类型和 companion 目录所有权。

## 产品交互

文档头部增加回形针图标入口，打开该文档的资产面板。面板是紧凑列表，显示名称、类型、大小、引用次数和健康状态，并提供添加、复制 Markdown 链接、在资源管理器中显示、替换、删除孤儿等动作。

编辑器支持三条同一落盘链路：粘贴剪贴板图片、拖入文件、图片块的上传按钮。用户看到图片节点前，文件必须已经持久化成功；失败时保留编辑内容并显示错误，不能插入假链接。外部 URL 旁提供显式“导入本地”，不默认抓取网络资源。

## 2026-08-08 实施记录

受管资产协议、主进程、renderer 和测试已经部署。新增 `AssetManager` 负责 companion 目录、内容 hash、MIME 魔数、限额、原子写入、AST 引用审计和 symlink/越界防护；`asset:list/import/adopt/trash` 经 project scope 与 FrontCPU 资源锁进入主进程。

Crepe 图片粘贴、拖入和上传现在先持久化再插入相对链接，不再使用默认的临时 `blob:` 结果。文档头部回形针打开资产面板，可查看四类健康状态、添加、复制链接、打开、定位、收编旧引用和删除孤儿。删除文档会先展示 companion 资产数量，再把文档与资产目录暂存成一个聚合并移入系统回收站；回收站失败会恢复两者。

当前软件没有文档重命名、移动或复制手势，因此没有凭空增加这三种 UI；以后实现这些手势时必须复用本 issue 已确定的聚合规则。HTTPS 保持外部非受管资源，不由 Iris 自动下载。

## 验收标准

1. 从剪贴板粘贴图片后立即关闭并重开 Iris，图片仍能显示，Markdown 中不存在 `blob:`、绝对路径或 data URL。
2. 文档连同 companion 目录复制到另一台机器后，普通 Markdown 阅读器与 Iris 都能解析相对链接。
3. 删除引用不会静默删除文件；审计能准确区分孤儿、缺失、受管和非受管资产。
4. 删除、移动或重命名文档时，UI 明确展示资产影响，成功后不产生断链；任一步失败时聚合保持可恢复。
5. 外部修改仍以磁盘为准，Iris 不需要私有索引即可重新构建完整资产状态。
