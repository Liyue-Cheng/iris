## 2026-08-09 调查结论

这是 renderer 侧根目录 hub 的会话选择被异步视图切换覆盖，不是 xterm replay、PTY
串流或主进程选错会话。

回归来自提交 `5ddd91d`（`feat(ui): unify project workspace interactions`）中两项组合改动：

1. `projectStore.selectRoot()` / `selectWorkspace()` 从同步方法改为先等待
   `editorStore.flushBeforeSwitch()` 的异步方法。
2. `LensTree` 的 hub 会话点击从原来的“等待根视图切换完成，再选择会话”改为不等待的
   `selectHub(workspacePath); sessionStore.select(s.id)`。

因此点击根目录中的任意终端时，实际顺序是：先启动 `selectRoot()` 并停在第一个
`await`；随后 `sessionStore.select(s.id)` 短暂选中目标；最后 `selectRoot()` 恢复，调用
`sessionStore.syncToRoot()`，重新按 `active > idle > exited` 选择会话。同状态会话使用
`>=` 比较并按插入顺序遍历，所以稳定落到最后一个，和实际症状完全一致。子工作区 hub
使用同一点击路径，也存在相同缺陷。右栏终端下拉菜单直接调用 `sessionStore.select()`，
不触发 hub 视图切换，因而不受这条竞态影响。

当前未提交工作区中，`2026-08-08-终端切换问题` 为 session store 增加了“按锚点记住
手工选择”的改动。它会让后到的 `syncToRoot()` 恢复刚选中的会话，因此能够顺带掩盖
本问题；但现有测试只覆盖跨文档恢复和关闭回退，没有覆盖根目录或子工作区点击，也没有
直接修正 `LensTree` 的异步调用契约。定向 Vitest 当前 5 项通过，只能证明已有选择记忆
测试通过，不能证明 hub 点击链路已被回归测试保护。

建议将 hub 点击恢复为有序事务：等待 `selectRoot()` / `selectWorkspace()` 成功切换到目标
hub 后再执行 `sessionStore.select(s.id)`；若编辑器保存或冲突处理阻止离开，则不得改变隐藏
的终端选择。按锚点记忆仍应保留，它解决的是离开再返回时恢复选择，不能代替调用方正确
排序。测试应同时覆盖根目录和子工作区，并模拟 `flushBeforeSwitch()` 异步完成及拒绝离开。

## 第一性原理分析

`2026-08-08-终端切换问题` 与本 issue 是同一个状态模型的两种失败。前者表现为离开文档
再返回后丢失手工选择，后者表现为点击根目录终端后被异步 hub 切换覆盖。共同原因是当前
系统同时保存一个全局 `activeSessionId`，又让 `selectDoc` / `selectRoot` /
`selectWorkspace` 通过 `syncTo*` 主动重选终端。导航和终端选择都能写同一个状态，但没有
统一的事务边界和优先级规则。

从用户语义看，系统只有三个独立事实：

1. 会话集合，以及每个会话不可含糊的 anchor（文档或 workspace hub）。
2. 当前正在查看的 anchor。
3. 每个 anchor 内用户最后明确选择的会话。

“当前显示的终端”不应作为第四份可独立写入的事实；它应由“当前 anchor + 该 anchor 的
记忆选择 + 会话集合”派生。只有尚无记忆或被选会话已关闭时才执行一次确定性 fallback。
导航本身不应调用 `syncTo*` 重选终端，会话活跃/空闲状态变化也不应抢走用户选择。

交互命令也应按用户意图建模，而不是由组件拼接底层 store 调用：

* `navigateToAnchor(anchor)`：等待编辑器离开检查，成功后只切换当前 anchor。
* `activateSession(sessionId)`：由 session 推导目标 anchor；等待离开检查；等待期间不修改
  任何可见或记忆状态；成功后重新校验项目代际和 session 是否仍存在，再把目标 anchor
  与该 anchor 的选择作为一次提交完成。
* `openSession(anchor, agentId)`：通过同一离开检查后创建；创建成功再选择新 session。
* `closeSession(sessionId)`：关闭非选中 session 不改变选择；关闭选中 session 才在同一
  anchor 内选择确定性 fallback。

如果视图状态与 session 选择仍保留在两个 external store，提交时应先在目标 anchor 写入
选择、再切换视图；旧视图不会读取目标 anchor 的选择，而新视图第一次渲染就能得到正确
session。更彻底的方案是把 `currentAnchor` 和 `selectedSessionIdByAnchor` 放入同一个
workspace navigation store，以单次 emit 保证原子快照。PTY 生命周期和输出仍由 main
process 持有，不需要随 UI 状态模型调整。

这种设计会同时消除两个问题：跨文档返回时只是改变 `currentAnchor`，原选择没有被重算；
点击根目录终端时走一个 `activateSession` 事务，不再存在 `selectRoot` 与 `select` 的先后
竞态。当前的 `selectedSessionIdByAnchor` 是正确方向，但仍是对全局
`activeSessionId + syncTo*` 模型的补丁，尚未把不变量变成结构约束。

## 2026-08-09 根治实现

已删除全局 `activeSessionId` 以及 `syncToDoc` / `syncToRoot` /
`syncToWorkspace`。session projection 现在只保存会话集合和每个 anchor 的粘性选择；
当前显示终端由当前 view 的 anchor 与该选择派生。状态点变化和普通导航不再拥有重选终端
的权限，无有效选择时只建立一次“同 anchor 最新会话”的确定性 fallback。

`projectStore.activateSession(sessionId)` 现在是唯一的会话激活事务：先从 session 推导文档
或 workspace anchor，跨 anchor 时等待编辑器离开检查，成功后重新校验项目代际、session
存活及 anchor，再按“目标选择先提交、目标 view 后提交”的顺序完成切换。拒绝离开时两者
都不变；递增 navigation intent 会让较晚完成的旧操作失效。文档路径同时收进
`MiddleView.doc`，不再与独立 `selectedPath` 形成不一致组合。

左栏 root/workspace 会话、右栏下拉、新建会话和项目快捷命令均已迁移到同一激活入口。
关闭选中会话只在同 anchor 内回退，关闭非选中会话保持选择；reanchor 会搬迁选择，项目
代际变化会清空旧选择，新建 sibling 和 `active/idle/exited` 变化不会抢占用户选择。
