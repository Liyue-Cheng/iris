从 [iris左栏逻辑优化](./2026-09-28-iris左栏逻辑优化.md) 的「补充四：状态徽章里的圆点是否需要」及其后续追问中拆出。原始分析见该 issue，本文只记录要做什么。

## 背景

`2026-08-11-状态徽章的视觉效果不统一` 已把所有文档状态统一为 soft pill：浅色语义底色，左侧 6px 实心圆点，后面是状态原文。复核后发现两处问题。

**圆点没有带来额外信息。**

* 圆点、底色、文字三者都取自同一个 `--badge-color`，形状也不随状态变化。
* 08-11 之前，各状态用的样式结构不同，圆点曾是区分手段之一；统一之后，这个作用已经消失。
* 左栏行首另有一个会话圆点（`SessionDot`），两个圆点形状相同、颜色撞车：`In Progress` 和会话「工作中」都是 foam，`On Hold` 和会话「空闲」都是 gold。
* 每个徽章因圆点多占约 10px（6px 圆点加 4px 间距），压缩了左栏标题的显示宽度。

**去掉圆点后，胶囊形状会让文字贴着弧边。**

* `sm` 档高 19px，端部半圆半径约 9.5px，左内边距只有 6px。
* `md` 档高 22px，端部半圆半径 11px，左内边距只有 8px。
* 内边距小于半径，文字起点落在弧内。现在这段弧被圆点填住了，去掉圆点后会显得拥挤、偏左。

## 方案

1. **状态徽章不再渲染圆点。**
2. **状态徽章由 `rounded-full` 改为 `rounded-sm`（4px）**，`sm` 和 `md` 两档相同。这与左栏行 hover/选中态、工具栏计数徽标的圆角保持一致。
3. **其余参数保持 08-11 的数值**：高度、字号、内边距、hover 加深、focus 外轮廓、可编辑时的下拉箭头。
4. **影响范围**：所有使用 `StatusBadge` 的位置都会一起变化，即左栏、Issue 面板、文档头部和报告时间线，保持同一结构的约定。

## 实现提示

* `src/renderer/components/ui/badge.tsx` 中，`hasDot()` 对 `soft` 返回 true，根节点 class 含 `rounded-full`。
* 目前只有 `src/renderer/components/ui/status-badge.tsx` 使用 `Badge`，且全部走 `soft` 模板。可以选择以下两种做法之一：
  * 直接修改 `soft` 变体：去掉圆点，并把圆角改为 `rounded-sm`。
  * 新增一个不带圆点的 `pill` 变体，由 `StatusBadge` 使用，`Badge` 其他变体保持原样。
  * 选定后，同步更新 `badge.tsx` 文件头部对各变体的注释。
* 不在本 issue 范围内：Iris Agent 的状态徽章（`AgentWorkbenchDialog.tsx`，`rounded-full` 加圆点）、Git 状态、终端会话圆点。08-11 已说明这些属于不同领域。
* 需要同步把 08-11 issue 中「每个状态都带 6px 实心圆点」的约定标记为已被本 issue 取代，在那份 issue 末尾追加说明即可。

## 2026-10-26 实现

按确认的方式直接修改 `soft` 变体，改动集中在 `src/renderer/components/ui/badge.tsx`：

* `hasDot()` 不再对 `soft` 返回 true，状态徽章不再渲染圆点。`outline`、`dot` 两个变体仍带圆点。
* 根节点圆角按变体区分：`soft` 用 `rounded-sm`，在当前 `--radius: 0.5rem` 下为 4px；`solid`、`outline`、`dot` 仍是 `rounded-full`。
* 文件头部注释已同步：`soft` 改为「浅色圆角矩形，无圆点」，`outline` 补注带圆点。
* `status-badge.tsx`、`global.css` 中的颜色、hover 加深、focus 外轮廓没有改动。Chromium 的 `outline` 会跟随 `border-radius`，所以焦点环也会随之变成圆角矩形。

**`px-2.5` 的评估结论：不改，保持 `px-2`。** 圆角降到 4px 后，`md` 档 8px、`sm` 档 6px 的左右内边距都大于圆角半径，文字起点已经不在弧内，原先「贴弧边」的问题不再存在。去掉圆点后，左右留白都是同一个内边距，两侧对称。如果手工检查时仍觉得 `md` 档偏紧，再单独调整。

同时在 [08-11 issue](./2026-08-11-状态徽章的视觉效果不统一.md) 末尾追加了说明：圆点和胶囊形状的约定已由本 issue 取代。

## 2026-10-26 追问：去掉圆点后有点单调，要不要设计一下字体

### 判断

单调感主要不是字体造成的，改字体能起的作用有限。

* 去掉圆点后，每个徽章都只剩「浅色底 + 文字」一种结构，九个状态之间只有色相不同。
* `Todo`、`Canceled`、`Backlog` 和未知值都用中性灰。一列徽章里同色、同形的比例很高，看起来就平。
* 圆点虽然没有携带信息，但它是徽章里唯一的非文字元素，原本提供了一点节奏感。

### 字体方面的约束

* **字体族不宜单独指定。** UI 字体可以由用户配置（`appearance.uiFontFamily` → `--ui-font-family`），默认值是 `'LXGW WenKai', system-ui, sans-serif`，应用本身没有打包这个字体。从注册表看，本机没有安装 LXGW WenKai，实际显示的应该是 `system-ui`。如果徽章单独写死另一套字体，会绕开用户设置，同一行里也会混排两套字体。
* **不建议全大写加字距**（如 `IN PROGRESS`）。这会让显示效果偏离「存盘值即显示值」的约定；文字会变宽约 20%–30%，和本 issue 节省左栏宽度的目标相反；对中文或自定义状态也不起作用。
* **字重值得核实一下。** 当前用的是 `font-medium`（500）。字体缺少 500 这一档时，浏览器会回退到 400，徽章就和正文一样细，这可能是「平」的原因之一。可以试 `font-semibold`（600），但 11px 的浅底徽章用 600 可能偏重，需要实际看一下。

### 可选方向（按改动量从小到大）

**A. 只调字重。** 把 500 改为 600，或者先确认 500 是否真正生效。改动只有一行，能让文字更立体，但不能从根本上解决单调。

**B. 同一结构内，降低「未开始/已结束」状态的存在感。** 例如 `Canceled` 加删除线，`Backlog` 和 `Canceled` 的底色再淡一些。结构仍然一致，只是让灰色状态之间、灰色和彩色之间拉开层次。需要注意，08-11 曾指出「填充强度同时变化会压过状态语义」，所以变化幅度要克制。

**C. 按状态区分形状图标（Linear 式）。** 在文字前放一个 12px 的线性图标，形状随状态变化，颜色仍取 `--badge-color`：

| 状态 | 图标 |
| --- | --- |
| Todo | 空心圆 `Circle` |
| In Progress | 半填充圆（需自绘，lucide 没有现成的） |
| In Review | `CircleDot` |
| Blocked | `CircleSlash` |
| On Hold | `CirclePause` |
| Done | `CircleCheck` |
| Canceled | `CircleX` |
| Active | 半填充圆，与 In Progress 一致 |
| Backlog | `CircleDashed` |
| 未知值 | 空心圆 |

* 好处：图标携带信息，这正是圆点缺少的；能直接解决 08-11 遗留的「色觉差异下能否辨认」问题；形状和左栏的 `SessionDot` 不同，也不会再撞色。
* 代价：每个徽章多出约 16px（12px 图标加 4px 间距），比原来的圆点还宽，和本 issue 节省左栏宽度的初衷冲突。如果左栏的 `sm` 档不加图标，又会打破「所有入口结构一致」的约定。

### 建议

如果主要想解决单调，**C 是唯一能真正改变观感、并且带信息的方案**，但需要先决定左栏宽度怎么取舍。如果更看重左栏宽度，可以先做 A 加 B 的轻量版，看看效果再定。

* [ ] 决定方向：A、A+B，还是 C。
* [ ] 如果选 C：决定左栏 `sm` 档是否也显示图标（保持结构一致，代价是宽度）。
* [ ] 在实际界面中确认 `font-medium` 是否生效，即默认字体链下有没有 500 这一档。
