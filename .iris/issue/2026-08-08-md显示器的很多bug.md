## 2026-08-08 编辑器重构

编辑器会话已按“磁盘基线 + 当前草稿”重写。`baselineRaw` 与当前完整 Markdown 字节的比较是 dirty 的唯一真相；Crepe 初始化和格式归一化在 hydration 阶段隔离，不再被当作用户编辑，也不会对未修改文档执行写入或扰动 mtime 排序。

保存路径统一为串行快照队列和 main 进程 compare-and-swap。写入携带 `expectedContent`，盘上内容偏离编辑基线时拒绝写入；显式覆盖使用 `expectedContent: null`。写入期间产生的新修订保留在队列尾部，冲突重试始终选择最新草稿。

外部修改策略已加入设置：默认“提示处理”会在 dirty 时暂停保存并显示“载入外部版本 / 保留本地并覆盖”；可切换为“静默覆盖”。自动保存、输入空闲延迟和失焦保存均可配置。正文空闲、checkbox、frontmatter 提交、失焦、视图/项目切换、Git 等外部动作和退出分别使用明确的保存触发器；冲突或写入失败会阻止离开文档和关闭窗口。

WYSIWYG 与源码模式共享同一会话状态机；源码模式 frontmatter 提交会保留尚未保存的源码正文。滚动位置按“文档 + 编辑模式”记忆，编辑器把焦点交给 Git、终端或工具栏控件时会恢复原滚动位置。

验证结果：完整 Vitest 共 15 个测试文件、106 项通过；`npm run typecheck`、`npm run build` 和 Electron 启动冒烟均通过。新增覆盖包括初始化不产生 dirty、字节级回退、模式切换、串行尾随保存、写入中冲突的最新修订保留、提示/覆盖冲突策略、自动保存延迟、源码 frontmatter、失败保持 dirty、CAS 冲突和相同内容不改 mtime。

## 2026-08-08 下拉菜单触发代码块闪烁

问题不是 Git 特有，也不是普通失焦或整个 Crepe 编辑器重挂载。所有应用下拉菜单共用 Radix DropdownMenu；其默认 `modal=true` 会在打开时启用全局滚动锁、焦点陷阱、外部指针屏蔽和无障碍隐藏。Milkdown 代码块同时由 IntersectionObserver 管理 CodeMirror 的卸载与重建，两者叠加后会让当前代码块短暂退化为 placeholder。

运行态采样确认：打开主题下拉约 100ms 后，可见代码块从 `.cm-editor` 变为 `.milkdown-code-block-placeholder`，高度从 94px 降为 57px，约 76ms 后重新创建 CodeMirror；页面总高度同步缩短再恢复。相同场景将 DropdownMenu 改为非模态后，连续 6 秒没有代码块 DOM 重建，也不再给 body 加滚动锁。

共享 DropdownMenu 现默认 `modal=false`，调用方仍可显式传入 `modal=true`。这一次没有修改编辑器滚动记忆，因为 A/B 对照表明它不是该闪烁的根因。新增回归测试锁定默认非模态和显式覆盖行为；完整 Vitest 共 16 个测试文件、114 项通过，正式构建通过。

## 2026-08-08 代码块生命周期收回

Iris 现在在 Crepe 内显式注册最后生效的 `code_block` NodeView 工厂，不再通过修改 Milkdown 全局 prototype 干预生命周期。代码块 UI、语言加载和首次进入视口时的惰性初始化仍复用 Milkdown；代码块一旦初始化，其离屏 teardown 入口由 Iris 在当前 NodeView 实例上接管，不会在离屏 5 秒后退化为 placeholder。真正删除代码块或销毁文档时仍走 Milkdown 的 `destroy()` 完整释放 CodeMirror、Vue 应用和观察器。

这与下拉菜单修复是两层独立保障：DropdownMenu 的 `modal=false` 阻止 Radix `hideOthers()` 改写整棵 ProseMirror DOM；稳定 NodeView 则阻止正常滚动离屏触发 Milkdown 自带回收。前者避免菜单引发文档 reconciliation，后者消除代码块因虚拟化造成的高度变化和再次创建。

自动运行态验证确认：可见代码块滚动离屏 6.5 秒后仍是同一 `.cm-editor` DOM，重新滚回并触发菜单后也保持同一实例。全量 Vitest、类型检查、正式构建和 Electron 启动冒烟通过；生命周期测试覆盖实例隔离、重复安装以及 Milkdown 上游接口变化时显式失败。用户已完成人工验收，未再观察到下拉菜单触发的代码块闪烁。
