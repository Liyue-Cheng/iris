现在 就是有一个问题，就是感觉目前的md编辑器，文本最大宽度不是很够，然后就是现在，md编辑器的代码框显示效果一般，就是没有Typora那么精致，你研究一下，这是为什么，然后你有什么修改建议

## 诊断（根因）

**1. 正文最大宽度不够**

`global.css` 把阅读列宽硬编码成 `max-width: 48rem`（约 768px），偏窄且无处可调；当时只有「正文对齐」设置，没有列宽设置。

**2. 代码框不如 Typora 精致** —— 三层根因：

- Crepe 的 CodeMirror feature 虽启用，但 `CrepeEditor.tsx` 没给它传 `languages`，导致代码块**没有语法高亮**（整块单色文本）。语言包其实都在 `node_modules/@codemirror/lang-*` 与 `language-data`（传递依赖），只差接进去。
- 即便接上，CodeMirror 的 `defaultHighlightStyle` 是浅色配色，与 Rose Pine 不搭。
- frame 主题对 `.milkdown-code-block` 只给了背景 + padding，**无圆角/无边框**，语言与复制按钮默认 `opacity: 0`，整体扁平。

## 改动

**A. 正文列宽做成设置项（窄 48 / 中 58 / 宽 72 rem，默认中）**

- `src/shared/types.ts` — `behavior.editorMaxWidth: number`
- `src/main/settings-manager.ts` — 默认 58，校验范围 `[30, 120]`
- `src/renderer/stores/settings-store.ts` — `applyAppearance` 写 `--editor-max-width` CSS 变量
- `src/renderer/styles/global.css` 与 `TypedHeader.tsx` — 正文列与标题表头统一读该变量（单一真源，消除两处硬编码漂移）
- `src/renderer/components/settings/SettingsView.tsx` — 「文档排版」占位换成「正文列宽」窄/中/宽 Segmented

**B. 代码块全套（语法高亮 + Rose Pine 配色 + 卡片外观）**

- 新建 `src/renderer/styles/codemirror-theme.ts` — Rose Pine `HighlightStyle`，颜色全部用 `var(--rp-*)`，靠 var() 间接让三变体（base/dawn/moon）自动跟随、切主题即时生效
- `src/renderer/components/doc/CrepeEditor.tsx` — 给 CodeMirror feature 传 `languages`（解决「无高亮」根因）并叠加 Rose Pine 扩展
- `src/renderer/components/doc/SourceEditor.tsx` — 源码模式复用同一份高亮
- `src/renderer/styles/global.css` — `.milkdown-code-block` 加圆角/边框、语言按钮常显、行号弱化

`npm run typecheck` 三进程通过。

## 跟进：源码模式行号仍为白色（2026-06-26）

**现象**：上一轮改完后，源码模式左侧行号（gutter）仍全白、未应用主题。

**根因**：行号来自 `basicSetup` 自带的 CodeMirror 默认浅色 gutter（近白数字），**无视主题**。之前给代码块行号上色的 `.cm-gutters` 规则写在 `global.css`，选择器限定 `.crepe-host .milkdown .milkdown-code-block` 下；源码模式宿主是 `.cm-host`，不在该选择器范围内，故行号一直白着。

**改动**（收进两处编辑器共用的扩展，单一真源）：

- `src/renderer/styles/codemirror-theme.ts` — 在 `rosePineCodeMirror` 的 `EditorView.theme` 加 gutter 规则：`.cm-gutters`/`.cm-lineNumbers` 用 `var(--rp-muted)`、活动行号 `var(--rp-subtle)`、背景透明去边框。靠 var() 间接，自动跟随 base/dawn/moon、切主题即时变色。
- `src/renderer/styles/global.css` — 删除原先只覆盖 Crepe 的 `.cm-gutters` 规则（现由共用扩展统一覆盖两处，消除双份漂移）。

`npm run typecheck` 三进程通过。
