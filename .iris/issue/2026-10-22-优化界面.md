## 视觉调研（第二版，2026-10-24）：只看三栏的视觉层次

> **范围**：只看分栏的视觉处理，包括底色、分隔、浮层和圆角，不涉及任何功能或业务逻辑。
>
> **方法**：在附图原图（1440×1178，窗口占 x 71–1368）上逐像素取色、扫描边界。
>
> **单位**：下文的「px」都指这张图的像素。图是转载后缩放过的，换算到 CSS 像素大约要除以 1.5～2，所以请只看比例。JPEG 压缩会让极淡的线条略有失真。assets 里的三张 jpg 是同一张图。

### 1. 结论：两层，而不是三张卡片

```
 截图（Claude）                                Iris 现状
┌───────────┬──────────────────┬╭─────────╮┐  ┌──────────────── TitleBar ────────────────┐
│ ●●●       │ 标题  Overview   ││ 面包屑   ││  ├──────────────────────────────────────────┤
│           │                  ││          ││  │╭───────╮ ╭──────────────╮ ╭───────────╮│
│  左栏     │     中栏          ││  右栏    ││  ││ 左栏   │ │    中栏       │ │  右栏      ││
│ （底面）  │   （底面）        ││ （浮层） ││  ││ 卡片   │ │    卡片       │ │  卡片      ││
│           │                  ││          ││  │╰───────╯ ╰──────────────╯ ╰───────────╯│
└───────────┴──────────────────┴╰─────────╯┘  └──────────────────────────────────────────┘
      ↑ 1px 极淡竖线             ↑ 四周留边、细边框、淡阴影              ↑ 三张平级圆角卡片
```

* **截图**：左栏和中栏是**同一张「纸」**，只用一根竖线隔开。右栏是**放在这张纸上的一块浮起面板**。视觉上分成「底面层」和「浮层」两个层级，右栏因此被突出。
* **Iris 现状**：外面一圈 `bg-card` 衬底，里面放三张相同的 `rounded-lg bg-background shadow-sm` 卡片。卡片之间是 4px 宽的拖拽条，条中间有一根淡线。三栏地位相同，没有主次。
  * 布局：`src/renderer/components/layout/ThreePane.tsx:159-177`
  * 拖拽条：`src/renderer/components/ui/resizable.tsx:31`

### 3. 为什么它显得「有层次」

1. **只有一处被抬起**。三张卡片平均用力，等于没有重点；截图只抬起右栏，层次差就出来了。
2. **分隔用最轻的手段**。左/中之间只有一根对比度约 3% 的线，标题行下和面板头部下都没有线。线越少，浮层的边缘越显眼。
3. **浮层的几个要素同时出现，而且每个都很弱**：四周留一点边、一根细边框、一层很淡的阴影，再加上填充略亮。单看哪一项都不明显，叠在一起就有了清楚的前后关系。
4. **没有衬底**。Iris 现在的 `bg-card` 衬底让所有面板都像嵌在凹槽里；截图里底面本身就是左栏和中栏的背景。
5. **圆角分级**。窗口约 20px，浮层约 8～10px，内容卡片和按钮更小。圆角随层级递减，整体显得规整。

### 4. 映射到 Iris 时要注意的地方（只谈视觉）

* **Windows 标题栏冲突**。截图是 macOS，窗口按钮在左上角，所以右栏能顶到窗口顶部。Iris 在 Windows 上把窗口按钮放在右上角（`TitleBar.tsx:60-119`），右栏顶到顶部会和它们冲突。有三种处理方式：

  1. 保留 40px 标题行，但让它与底面同色、不加分隔线，右栏浮层从标题行下方开始。
  2. 把窗口按钮挪进右栏浮层的头部。
  3. 右栏浮层顶部给窗口按钮让出一块位置。

  第一种最稳。
* **单栏视图**。hub 视图（终端全宽）、todos、collection 都不是「左 + 中 + 右」的结构，需要分别决定谁当浮层。一个自然的规则是：**终端和详情面板永远浮起，文档、列表和导航永远在底面**。
* **深色主题的层级**。浅色模式下浮层更白；深色模式的惯例是浮层更亮一点、阴影基本看不见，主要靠边框。14 套主题都需要补：

  * 一个浮层底色 token，例如 `--surface-raised`；
  * 一档比现有 `--border` 稍重的浮层边框。

  现有的 `--border` 和 `--border-subtle` 两档，正好可以用作左/中分隔线。
* **终端背景**。右栏浮层里是 xterm，它的背景色在 `src/renderer/theme/xterm-themes.ts` 里单独维护。浮层底色变了，这里也要同步，否则浮层里会出现一块颜色不一样的终端区域。
* **拖拽条**。左/中之间可以继续用现有的 1px 线（`resizable.tsx` 的 `after:` 伪元素），只需调淡。中/右之间不再画线，浮层边框本身就是边界，拖拽热区放在浮层左边缘附近即可。

### 5. 可做的视觉改动清单（供选择，未实施）

1. 去掉 `ThreePane` 的 `bg-card` 衬底，以及左、中两栏的卡片外壳，让它们直接铺在 `bg-background` 上。
2. 左/中之间只保留一根 1px 的极淡竖线。
3. 右栏改成浮层：
   * 上、右、下留约 6px 边距，左侧 0～2px；
   * 1px 浮层边框，加很淡的阴影；
   * 填充用新的 `--surface-raised`；
   * 圆角约 8px。
4. 标题栏与底面同色，去掉下分隔线。右栏浮层从标题栏下方开始（即第 4 节的第一种方式）。
5. 文档正文继续限宽（现在是 48rem），左右留白保持宽松。
6. 先在一套浅色主题和一套深色主题上出效果，确认后再推广到其余主题。

### 顺带发现（未处理）

本仓库的 Tailwind 颜色是直接写成 `var(--x)` 的。用 `npx tailwindcss` 实测：`bg-card/30`、`after:bg-border/40` 这类**带透明度修饰符的写法根本不会生成 CSS**。

已知受影响的地方：

* 拖拽条平时那根「淡线」实际一直不显示，只有 hover 时的 `hover:after:bg-border` 生效。
* `TypedHeader`、`TodoPanel`、集合面板头部的 `bg-card/30`，以及 `bg-[var(--rp-gold)]/20` 一类写法，都需要另行排查。

本次的发丝线改用不带修饰符的 `after:bg-border`，不受这个问题影响。

## 布局风格做成设置项（2026-10-24）

用户要求：两种布局可以在设置里切换。

### 改动

* **新设置 `appearance.paneStyle`**，取值 `'cards' | 'layered'`，**默认 `cards`**，即原来的卡片布局。
  * 旧的 `settings.json` 没有这个字段，会通过 `deepMerge` 自动补成默认值。
  * `validateSettings` 只接受这两个值。
  * 涉及文件：`types.ts`、`settings-manager.ts`。
* **设置页入口**：「外观 › 主题」组里新增一行「布局风格」，用分段按钮在「卡片 / 分层」之间切换，立即生效。中英文文案都已补上（`SettingsView.tsx`、`resources.ts`）。
* **布局实现**（`ThreePane.tsx`）：上一版的 `RaisedPane` 改成 `PaneFrame`，同时支持两种风格。
  * 每一栏声明自己的角色，`flat`（平铺）或 `raised`（浮起）。
  * `cards` 风格下，所有栏都画成原来的 `rounded-lg bg-background shadow-sm` 卡片；collection 视图仍是 `rounded-xl`，衬底是 `bg-card`。
  * `layered` 风格下，`flat` 栏铺在 `bg-shell` 上，`raised` 栏画成浮层；两个平铺栏之间才画发丝线。
  * 两种风格、两种角色渲染的元素树完全相同，只换 class。所以在设置里来回切换时，终端不会重新挂载。
* **标题栏**跟随这项设置：`cards` 用 `bg-card`，`layered` 用 `bg-shell`。
* **左栏**根节点不再自带 `bg-background`。卡片模式下这层背景由卡片外壳提供，视觉上和原来一样。
* **Paper 主题与布局风格无关**，两种布局下都能用。在卡片布局下，它就是一套普通的暖白主题。

## 同类显示问题全面检查（2026-10-25）

用户要求：继续全面检查是否还有类似显示问题。本轮围绕当前工作区源码检查入口／恢复、根节点／子工作区／文档／集合／待办切换、删除与空状态、布局尺寸持久化、卡片／分层风格以及终端组件生命周期。通过状态测试和不启动应用的 DOM 检查核实可复现路径；区分代码证据、自动化复现和仍需桌面验收的视觉现象。检查结果继续追加到本 issue。

### 结论

确认还有 **6 类问题**，其中 D1 与首次打开文件夹的空中栏是同一类状态错误；D2／D3 是当前布局结构与「终端稳定挂载、左栏宽度稳定」设计目标不一致。另复核了本 issue 先前记录的透明度样式问题，仍然存在。以下针对当前工作区源码，本轮完成检查，未实施这些修复，也未把 DOM 模型检查等同于桌面视觉验收。

### 已确认问题

**D1：删除当前文档后，空中栏仍会回来。**

* 触发：打开一个没有关联终端的文档，再通过文件操作删除它。
* 位置：`src/renderer/stores/project-store.ts:564`。
* 实际路径：删除回退仍写入 `{ kind: 'doc', path: null }`。状态测试确认编辑器 session 被清除，DOM 检查确认这一状态依然保留三栏和中间容器。此前首次打开的修复只改了入口默认值，没有覆盖这条删除路径。现有 `project-scope.test.ts` 的「deleted document has no linked session」用例还把这一旧行为当成通过条件。
* 建议：普通文档删除后返回仍存在的原工作区 hub，否则返回 root；集合里的文档删除则保留集合，并清空详情选择。

**D2：文档与 hub 切换时，终端容器无条件重建。**

* 触发：从文档视图切到项目根节点／子工作区，或反向切换。
* 位置：`src/renderer/components/layout/ThreePane.tsx:218`、`:233`、`:253`。
* 实际路径：文档分支把 `RightPane` 直接放在外层第三栏，hub 分支却放进第二栏的 `RightArea` 嵌套组。DOM mount 探针确认一次 doc → root 产生两次挂载、一次卸载，前后终端容器不是同一个节点。`RightArea` 中关于 doc／hub 共用稳定终端节点的注释与实际调用不符：doc 已在外层提前返回，内部 doc 分支不会被用到。
* 影响边界：不同会话切换本来就会按现有协议回放；这里额外确认的是布局无条件销毁终端容器。在删除文档后同一个终端重挂到 hub 等场景，也无法保住实例。`TerminalView.tsx:573` 开始回放、卸载时清理 runtime／adapter 的路径已经核对。是否出现肉眼闪烁、持续多久，仍需桌面验证。
* 建议：让主页面共用稳定的左栏与终端节点，在节点之间管理编辑器的显隐和尺寸，并用挂载次数测试约束视图切换。

**D3：三栏和两栏分别恢复左栏宽度，切换时会跳。**

* 触发：在文档视图调整左栏，再切到 hub／待办，之后切回。
* 位置：`src/renderer/components/layout/ThreePane.tsx:220`、`:246`。
* 实际路径：虽然都叫 `autoSaveId="iris-shell"`，`react-resizable-panels@2.1.9` 还会用面板集合生成第二级保存 key。三栏包含 `doc-editor`／`doc-terminal`，两栏是另一组成员，因此左栏宽度并不共享。使用符合库实际序列化规则的保存配置，DOM 检查复现了 **文档左栏 35% → hub 左栏 25% → 返回文档 35%**。浏览器版面板库同时给出了动态面板缺少稳定 id／order 的警告。
* 建议：固定外层「左栏 + 右区」，把文档分栏放进右区；或者显式共享左栏尺寸、分开存储右区比例。单纯复用 `autoSaveId` 不足以保证宽度稳定。

**D4：工作区被删除后，当前视图仍指向已经消失的工作区。**

* 触发：停留在子工作区 hub、该工作区的待办或集合，外部删除整个子工作区。
* 位置：`src/renderer/stores/project-store.ts:429`、`:494`。
* 实际路径：重扫后只针对「当前选中文档被删除」处理回退，没有统一校验当前工作区。三条状态探针均确认：新 scan 已经没有该工作区，`view` 仍保留旧的 workspace path。hub 会继续显示旧工作区的终端或启动面板，集合／待办则保持失效筛选并显示空内容。`leaveCollection()`、`toggleTodos()` 的部分返回路径已有存在性检查，但停留在页面时不生效。
* 建议：每次扫描结果提交后，统一校验当前 hub、待办 scope、集合 scope 和返回目标；按存活父工作区／root 回退，同时检查工作区会话锚点。

**D5：整个 `.iris` 消失时，待办／集合会退化成文档占位。**

* 触发：停留在待办／集合页面，外部删除 `.iris`，重扫得到 `hasIris: false, root: null`。
* 位置：`src/renderer/components/layout/MiddlePane.tsx:35`、`src/renderer/stores/project-store.ts:429`。
* 实际路径：视图状态仍是 todos／collection，但 `MiddlePane` 只有在 `scan.root` 存在时才渲染管理器，否则一律落到 `DocView`。状态及 dispatcher 检查均确认该路径。待办页面因此不显示待办或终端，而显示「请选择文档」；未选中文档的集合还会在两栏分别落入文档占位。
* 建议：项目结构消失时清理集合／待办视图并回 root／初始化引导；dispatcher 对缺失根节点应显示对应空状态，不能默认视为文档。

**D6：文件树首次加载或加载失败时，左栏树区域会空白。**

* 触发：首次进入文件树时请求尚未返回，或 `PROJECT_RAW_TREE` 请求失败。
* 位置：`src/renderer/components/layout/LeftPane.tsx:512`、`src/renderer/stores/project-store.ts:853`。
* 实际路径：`rawMode` 已经为 true、`rawTree` 仍是 null；文件树条件不满足，Lens 条件又因 rawMode 为 true 而不满足。故障注入确认请求失败后仍停留在这一状态。全局健康条已有错误和重试入口，但左栏树区域没有本地加载、错误或空目录说明。
* 建议：补 raw tree 的 loading／error 状态与局部重试反馈，或首次失败后恢复 Lens；有旧树时保留旧树并显示刷新失败提示。
