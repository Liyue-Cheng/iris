## 需求整理

### 背景与现状

目前，将文档状态设置为 `Done` 或关闭 Iris 时，相关终端虽然会关闭，但与文档关联的 Iris Agent 实例并没有全部关闭或妥善退出。

这会带来两个问题：

1. 再次打开 Iris 时，之前残留的 Agent 实例会被全部加载，导致启动速度变慢。
2. 左侧文档区域会因为这些残留实例显示小圆点等运行状态，容易让人误以为它们仍然需要保持活跃。

### 需求一：文档设为 Done 或退出 Iris 时关闭 Agent 实例

将文档状态设置为 `Done` 和关闭 Iris，应当采用一致的 Agent 退出处理流程：前者处理该文档关联的 Agent 实例，后者处理应用中所有仍然活跃的 Agent 实例。

- 将文档设为 `Done` 时，如果该文档仍有打开或运行中的 Agent 实例，应弹出确认弹窗。
- 关闭 Iris 时，如果仍有打开或运行中的 Agent 实例，也应弹出相同的确认弹窗。
- 用户确认后，应关闭相关终端，并同时关闭或结束对应的 Iris Agent 实例，避免它们在下次启动时被自动恢复为活跃实例。
- 下次打开 Iris 时，不应因为上一次正常退出前存在 Agent 实例，就自动加载全部历史实例。
- 已结束的实例不应继续触发左侧的小圆点等活跃状态提示。
- 历史会话记录需要保留，关闭实例不等于删除历史。

### 需求二：查看当前文档的 Agent 历史

在通过 Agent 打开或查看某个文档时，需要提供一个历史入口。点击该入口后，展示当前文档关联过的全部 Iris Agent 会话记录，而不是展示整个项目的全部会话。

历史列表中的每条会话至少提供两个操作：

1. **切换**：将当前文档正在使用的 Agent Session 切换到选中的历史 Session，并继续查看或使用该会话。
2. **加号**：基于选中的历史 Session，重新打开一个新的 Agent 实例，并将这个新实例挂到当前文档下面；原历史记录本身保持不变。

### 预期结果

- 将文档设为 `Done` 后，不再遗留该文档下仍然活跃的 Agent 实例。
- 正常关闭 Iris 后，不再遗留需要在下次启动时恢复的活跃 Agent 实例。
- Iris 再次启动时，不会因为批量加载旧实例而变慢。
- 左侧只显示当前实际活跃的 Agent 状态。
- 用户仍然可以从文档进入历史记录，切换到旧 Session，或者把旧 Session 重新打开为挂在该文档下的新 Agent 实例。

### 已确认的交互规则

- [x] “切换”到历史 Session 时，底层可以直接恢复原实例，也可以创建承接其上下文的新实例；两种实现均可，关键是用户能够切换并继续使用选中的历史会话。
- [x] 点击“加号”后，必须完整恢复所选历史 Session 的上下文，并创建一个新的 Agent 实例挂在当前文档下面；不能只保留当前文档的关联。
- [x] 退出确认弹窗不提供保留个别实例的选项。用户确认后，按终端关闭的方式统一关闭适用范围内的 Agent 实例；如果之后需要继续使用，再从当前文档的历史记录中恢复。

## 实现方案

### 核心概念：关闭 = 归档，不是删除

当前 `IRIS_AGENT_CLOSE` 走的是 `IrisAgentSessionStore.delete()`，会连 journal、快照、附件一起删掉，所以“关闭”等于“历史消失”。方案引入一个持久化标量 `closedAt`（Session 聚合字段）：

- **打开（live）**：`closedAt === undefined`。照旧投影到右栏、参与状态点与小圆点。
- **归档（history）**：`closedAt` 有值。保留全部 Trace、Intent、附件与 journal；不再出现在右栏/状态点，只出现在该文档的历史列表里。

`closeSession()` 改为：先 `shutdownHost` + 释放该会话全部终端，再把运行中的 Intent 收束为 `paused`（复用 `pauseActiveAgentIntent`），置 `closedAt`、`mailboxPaused`，提交一次，然后发 `sessionDestroyed`（只从投影里消失，磁盘记录保留）。

### 启动不再全量加载历史实例

历史随归档无限增长后，`IrisAgentSessionStore.load()` 会逐个重放 journal 做 hash 链校验，启动开销与历史条数成正比——这正是“第二次打开很慢”的来源。方案：

- 归档发生时该会话必然静止，`commit()` 会写 `snapshot.json`。
- `load()` 先只读每个会话的 `snapshot.json`；若快照里 `closedAt` 有值且会话静止，则只记一条轻量 meta（id / anchor / 名称 / 时间 / Intent 数 / 最后一条输入），**不重放 journal**。
- `list()` 只返回 live 会话；`history()` 用 meta + 已加载聚合合成历史列表。
- 需要真正读写某个归档会话时（切换/加号）才 `ensureLoaded()`：完整重放 journal、校验 hash 链后放入内存。

### 需求二：历史入口、切换、加号

- 新增 `IRIS_AGENT_HISTORY`（按 anchor 取当前文档的历史列表）、`IRIS_AGENT_REOPEN`（切换：清 `closedAt` 恢复为 live）、`IRIS_AGENT_RESTORE`（加号：以所选历史会话为源创建新实例）。
- “加号”复用既有 Fork 语义：源有 `completed` 尾 Intent 时走 Reply Fork，否则走 Input Fork，源会话不变，新实例挂在同一文档下；源没有任何 Intent 时创建一个新的空会话。
- 右栏 banner 增加一个“历史”图标（仅 Iris Agent 开启时显示），点开一个按当前 anchor 过滤的会话列表弹窗，每行提供“切换”和“加号”两个动作。

### 需求一：设为 Done 与退出应用

- 渲染端 `setDocsStatus` 在关闭终端会话的同时，把锚定到这些文档的 Iris Agent 会话一并归档；确认弹窗把 Agent 实例计数一并展示（沿用原有“关闭并切换”文案结构）。
- 主进程退出：`IrisAgentSessionManager.shutdown()` 在销毁 store 之前，把所有 live 会话归档（收束运行中 Intent → 置 `closedAt` → 提交），因此下次启动不会自动恢复为活跃实例。
- 退出确认弹窗的计数口径由“运行中的会话”改为“仍然打开的会话（终端 + Iris Agent）”，与需求“仍有打开或运行中的实例就提示”一致；`behavior.confirmOnQuit` 仍为开关。

### 已验证的不变量

- 归档不删除任何 Trace 事实；`list()` 过滤而非 `delete()`。
- 归档会话在磁盘上仍是合法的 v3 记录，重新打开后 revision 从原值继续单调递增。
- 历史列表按 anchor 过滤：文档 A 的历史不会混入文档 B 或整个项目。

## 方案审核（2026-09-10）

### 审核结论

总体方向可行，`closedAt` 将“实例是否打开”与“历史是否存在”拆开，以及历史 Session 按需加载，都是适合当前领域模型的做法。但现方案和当前实现草稿还不能直接通过审核：正常路径已经覆盖，仍有几个生命周期缺口会让“实例关闭后又出现”“Done 后仍有后台进程”“启动仍然重放历史”复发。

建议保留核心模型，但把归档收敛为主进程中的一个权威操作，并补齐下述阻断项后再进入人工验收。

### 阻断项

#### 1. 项目切换没有真正归档旧项目的 Session

当前 `IrisAgentSessionManager.closeProject()` 只关闭 Host、释放终端，并且只把忙碌 Session 暂停；空闲 Session 和暂停后的 Session 都没有写入 `closedAt`。随后 `ensureStore()` 会卸载旧项目 Store。这样用户先切换项目、再退出 Iris 时，退出流程只会归档当前已加载项目，旧项目仍保留 live 记录；以后重新打开旧项目，实例和状态点还会重新出现。

项目切换、关闭窗口、退出应用必须复用同一个归档原语。离开项目时也要把该项目全部 live Session 归档，而不只是 pause busy Session。

#### 2. Done 流程是渲染端逐条 best-effort 关闭，失败后仍会改状态

当前草稿从 `irisAgentStore` 取 Session，再逐条调用关闭；`closeIrisAgentInstance()` 会吞掉所有异常。运行中的 Session 很容易在弹窗显示期间增加 revision，导致 `expectedRevision` 冲突。此时关闭失败，但 `setDocsStatus()` 仍会继续把文档写成 `Done`，直接违反“Done 后不遗留实例”。渲染端投影也不是批量关闭时的权威数据源。

应新增主进程批量归档命令，以文档 anchor/path 为输入，在主进程重新枚举当前 live Session，并在各 Session 的 mutation queue 上执行关闭。只有全部归档成功后才写文档状态；如果部分失败，应保持原状态并向用户报告失败项，不能静默继续。

#### 3. 关闭 Session 没有处理 Agent 后台任务，晚到事件会把它重新投影出来

`closeSession()` 当前停止 Worker 和普通 Agent 终端，但没有取消 `AgentTaskManager` 中属于该 Session 的 queued/starting/running 后台任务。任务可以在 Session 归档后继续运行；任务结束时，`onTaskChanged()` 仍能取得这个 closed aggregate，提交后又发送 `sessionChanged`，渲染端会把刚刚移除的 Session 加回来。

归档原语必须取消并等待该 Session 的全部后台任务收束；同时所有运行时事件入口都应拒绝修改或重新投影 `closedAt` 已存在的 Session。应用退出的全局 `taskManager.shutdown()` 不能替代单 Session/单文档关闭路径。

#### 4. 不能直接把 closed snapshot 当作 journal 的最新权威状态

当前启动优化只要看到 snapshot 中存在 `closedAt`，就跳过 journal。可是 snapshot 在现有 Store 中是可丢弃缓存，写入失败会被吞掉，而且进程可能在 journal `sync()` 完成后、snapshot 更新前退出。典型情况是：旧 snapshot 仍显示 closed，journal 已追加 reopen 或后续提交；下次启动会错误地把实际已打开的 Session 当成历史，并展示陈旧 meta。

仍可避免全量重放，但读取 closed snapshot 前必须用低成本方式确认它就是 journal 尾部，例如读取最后一条完整 journal record，校验 `revision + journalHash` 与 snapshot 一致；不一致时再回退到完整重放。不能依赖“归档时必然会成功写 snapshot”这一假设。

#### 5. 退出归档失败目前只记录日志，无法保证下次不恢复

`archiveLiveSessions()` 对单 Session 提交失败后仅记录 warning，整个 shutdown 仍被视为完成。如果磁盘提交失败，该 Session 下次仍可能作为 live 加载。至少要让归档结果可观测并进入退出清理的失败处理；更稳妥的是让启动恢复策略也能识别上一进程遗留的 live 记录并默认降级为非活动历史，避免单次归档写失败重新制造状态点。

### 需要补充定义的行为

- 归档时不能只设置 `mailboxPaused` 而保留可自动执行的 queued/running mailbox。需要明确将未执行消息标记为取消/未执行，或在重新打开后要求用户显式恢复；不能在用户下一次发送消息时悄悄先执行旧队列。
- 历史列表包含 live Session 时，“切换”可以只做选中；对仍在运行的 live Session，“加号”当前会失败。应明确采用“禁用并提示先停止”，或者只从最后一个已完成 Intent 建新实例，不能所有行都显示可用按钮但点击后报错。
- 分支编号不能只统计当前 live 子 Session，否则历史分支归档后会重复出现 `Branch 1` 等名称。
- Session 与文档目前按 path 关联。文档重命名或移动后，历史会留在旧 path；需要决定是否随现有文档移动流程迁移 anchor。该项可以后做，但应记录为已知限制。
- 退出确认的计数口径还需统一：当前 Iris Agent 统计全部 open Session，而终端只统计未退出 Session。如果文案称“所有打开会话”，应决定已退出但仍显示的终端是否计入。

### 建议收敛后的归档原语

主进程提供一个统一的 `archiveSessions(scope, selector, reason)`，`selector` 支持 Session id、文档 anchor 集合、当前项目全部 Session。单个 Session 的顺序建议固定为：

1. 进入该 Session 的 mutation queue，阻止新命令并重新读取最新 aggregate。
2. 停止 compaction 和 Worker，取消并等待普通终端、后台任务及监督流程收束。
3. 将运行中 Intent 收束为 `paused`，明确处理 queued/running mailbox。
4. 写入 `closedAt` 并提交；确认 journal 与可用于轻量启动的 meta/snapshot 达到一致状态。
5. 提交成功后才发送 `sessionDestroyed`；失败则保留当前投影并向调用方返回错误。

`IRIS_AGENT_CLOSE`、文档设为 `Done`、项目切换、关闭窗口和退出应用都调用这个原语，避免五条路径各自实现一套略有差异的关闭逻辑。

## 实践实现（2026-09-10）

已按审核意见完成一轮增量实现，没有运行 `build`、`dist` 或开发服务器。

### 已落地

- 主进程新增按文档路径统计和批量归档 Iris Agent Session 的 IPC。Done/On Hold 弹窗的 Agent 数量来自主进程 Store，确认后也由主进程重新枚举最新 live Session，不再依赖渲染端逐条携带旧 revision 关闭。
- `setDocsStatus()` 只有在终端关闭和 Agent 批量归档全部成功后才写状态；Agent 归档失败会中止 `Done` 写入，不再吞掉异常继续执行。
- `closeSession()`、文档状态切换和 `closeProject()` 已共用同一个 Session 归档流程。项目切换会先归档旧项目全部 live Session，避免旧 Store 卸载后留下下次重新出现的实例。
- 单 Session 归档现在会停止 compaction/Worker/普通终端，取消并等待该 Session 的后台任务结束，再提交 `closedAt`。
- 归档期间和归档完成后，后台任务的晚到通知不会再修改或重新投影 closed Session；任务最终状态会在关闭提交前同步回 Session 历史。
- 归档时 queued/running mailbox 会转为 `superseded`，重新打开后不会因用户下一次发送而自动执行旧队列。
- closed snapshot 作为轻量 meta 使用前，会读取 journal 最后一条完整合法记录并校验 `revision + journalHash`。发现 snapshot 落后于有效 journal 尾部时回退到完整重放；不再把旧 closed snapshot 当作无条件权威。
- 退出归档会聚合并抛出提交失败，而不是在 Manager 内部只写 warning 后假装成功。窗口清理仍会完成，失败会进入上层统一清理日志。
- 历史分支编号会统计 live 与 closed 子 Session，避免归档旧分支后重复命名为 `Branch 1`。
- 历史列表对正在运行的 live Session 禁用“加号”并提示先停止；动作失败时弹窗不再无条件关闭。
