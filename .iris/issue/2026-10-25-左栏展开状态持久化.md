## 背景

左栏的几类展开和模式状态都存在组件的局部 state 里：

- 工作区文档区的折叠：`WorkspaceSection` 中的 `useState(depth === 0)`，见 `src/renderer/components/lens/LensTree.tsx`。
- 类型分区的折叠：`TypeSection` 中的 `useState(true)`，同一文件。
- 文件树的目录展开：`RawTree` 中局部的 `expandedPaths: Map<path, boolean>`，见 `src/renderer/components/lens/RawTree.tsx`。
- Git 视图开关：`LeftPane` 中局部的 `gitOpen`，见 `src/renderer/components/layout/LeftPane.tsx`。文件树开关 `rawMode` 则放在 `project-store` 里。

进出集合页时，`ThreePane` 会切换到 `DocumentCollectionShell`，换掉整棵组件树。左栏被卸载后，上面这些状态全部回到默认值。切换项目或重启应用后也一样。这个结论来自读代码，尚未在桌面端手工复现。

## 范围

| 状态 | 同一会话内保留 | 重启后保留 |
| --- | --- | --- |
| 工作区文档区的展开/折叠 | 必须 | 本期做 |
| 类型分区的展开/折叠 | 必须 | 本期做 |
| 左栏模式（文档 / 文件 / Git） | 必须 | 待定 |
| 文件树的目录展开 | 必须 | 待定，后续可做，需要限制条数 |
| 搜索词、搜索框开关 | 可以保留 | 不保存 |
| 搜索时的临时展开 | 不写入 | 不写入 |
| 滚动位置 | 建议保留 | 不保存 |

## 设计要点

1. **只存覆盖值。** 以路径为键，值为 `true` 或 `false`。没有记录时按默认规则：根工作区展开，非根工作区折叠，类型分区展开。新出现的工作区自动按默认显示。写入时顺带清理当前 scan 中已经不存在的路径。
2. **状态提到 store。** 不再放在组件局部 state 中，这样组件卸载也不会丢失。这一步是「同一会话内保留」的前提。
3. **跨重启存在本机，不写入 `.iris/`。** 复用 `src/renderer/lib/view-prefs.ts`：它基于 localStorage，集合面板的分组折叠已经在用。也可以按同样方式另建一个 store。
4. **键名包含项目绝对路径。** 例如「项目根 + 工作区相对路径 + 类型」，避免把一个项目的状态带进另一个项目。多窗口打开同一项目时以最后一次写入为准。
5. **搜索导致的展开与持久化隔离。** 搜索时临时展开，清空后恢复原状，不写入覆盖值。这一条依赖父 issue 中的 B1「搜索穿透折叠」；如果 B1 还没做，至少保证搜索不改写持久化状态。
6. **定位文档时展开并记录。** 从待办、集合页、文内链接等入口打开一篇文档时，如果它所在的分区是折叠的，自动展开并写入覆盖值，类似 VS Code 的 reveal。
7. **右键菜单的「折叠文档区 / 展开文档区」写入同一套覆盖值。**
8. **左栏模式改成单一状态。** 用一个 `documents | files | git` 状态替代 `rawMode` 和 `gitOpen`，放在 store 中。现有的文件树刷新逻辑和 Git 刷新逻辑保持不变。
9. **不影响会话。** 收起、切换模式、进出集合页都不能关闭或重建会话。折叠后会话状态不可见的问题，由父 issue 中的 B5「折叠汇总」另行解决，不在本 issue 范围内。

## 实施结果（2026-11-22）

- 新增 `src/renderer/lib/left-pane-prefs.ts`，使用 `localStorage` 按项目绝对路径隔离偏好。工作区、类型和目录只保存偏离默认规则的覆盖值；扫描刷新时清理已不存在的工作区、类型和目录键。
- 左栏模式改为单一的 `documents | files | git`，按项目跨重启恢复。进入文件模式时仍按原逻辑刷新文件树，Git 面板仍在项目 ready 后刷新。
- `LensTree` 和 `RawTree` 不再用组件局部 state 保存普通展开状态，因此进出集合页和切换模式造成组件卸载后仍能恢复。搜索期间的目录/类型展开仍为临时状态，不写入偏好。
- 普通文档导航和从集合页进入默认文档视图时，会展开并记录文档所属工作区与类型分区。
- 文件树目录覆盖值同样跨重启保存，每个项目最多保留最近写入的 500 条，避免大型仓库无限占用本机存储。
