## 2026-08-08 语言现状调研

### 结论

Iris 适合增加“简体中文 / English”两套界面语言，但不应把协议词汇也做成可翻译文案。
正确边界是：**界面文案按 locale 切换，协议、存储、解析和用户内容始终使用原始值。**

第一版建议支持 `system`、`zh-CN`、`en-US` 三个语言偏好，其中 `system` 为默认值；系统
locale 以 `zh` 开头时解析为 `zh-CN`，其余解析为 `en-US`。切换后立即生效并写入机器级
设置，所有窗口跟随同一设置。

### 当前状态

- 项目没有 i18n 依赖、翻译资源、locale 类型或语言设置。所有文案都直接写在 TS/TSX 中。
- 代码粗略扫描显示，包含中文的文件覆盖 renderer 50/100、main 13/26、shared 4/9。该数字
  包含注释和测试，不等同于文案数量，但说明改造跨越全部三层，不是只改设置页。
- renderer 的操作文案以中文为主，类型名、状态值、Git、Agent、Source Control 等保留英文，
  当前实际是未经治理的中英混用。
- `src/renderer/index.html` 固定声明 `lang="en"`，与当前中文界面不一致；
  `src/renderer/index.tsx` 又把开发调试控制台固定为 `zh-CN`。
- `Settings` 没有语言字段。现有设置由主进程持久化到 `~/.iris/settings.json` 或开发版的
  `~/.iris-dev/settings.json`，并广播给所有窗口，适合直接承载全局语言偏好。
- Electron 原生打开目录、退出确认等对话框在 main 进程直接写死中文；renderer 内的按钮、
  tooltip、placeholder、ARIA、空状态、确认框和错误标题也直接写死中文。
- 主进程错误信息中英文混杂，renderer 经常直接显示 `Error.message`。仅替换 JSX 文案会留下
  大量不可控的混合语言错误提示。
- `SOFTWARE_PROMPT_TEMPLATE`、`FOCUS_CONTEXT_SCRIPT` 及 `<iris-focus>` /
  `<iris-workspace>` 注入内容是 agent 协议，不是普通界面文案。当前主体为英文，应该继续只有
  一个权威版本，不能随界面语言分叉。
- 当前有少量展示文本兼任程序状态：Issue 分组用 `无状态` / `无标签` 作为 Map key，Report
  时间桶直接用 `今天` / `近7天` / `近30天` / `更早` / `无日期` 作为内部 id。直接翻译这些
  字符串会改变逻辑，应先拆成稳定 id 和本地化 label。
- 排序行为不一致：左侧文档标题固定使用 `localeCompare(..., 'zh')`，其他标题/标签排序依赖
  操作系统默认 locale，协议路径排序也使用 `localeCompare`。需要把“面向人的本地化排序”和
  “协议级稳定排序”分开。

## 多语言边界

### 必须保持 canonical 的内容

以下内容在中文和英文界面中都保持原样，不进入翻译资源：

| 类别 | 固定内容 | 原因 |
| --- | --- | --- |
| typed folder | `status/`、`issue/`、`report/`、`misc/` | 文件夹名参与类型解析 |
| frontmatter key | `title:`、`status:`、`labels:`、`assignee:`、`priority:`、`due:`、`reflects:` | key 按字面解析 |
| canonical status | `Todo`、`In Progress`、`In Review`、`Blocked`、`Done`、`Canceled`、`Active`、`Backlog` | 写盘、筛选、状态机和 agent 规则共同依赖 |
| 协议标记 | `.iris/`、`AGENTS.md`、`<iris-software>`、`<iris-project>`、`<iris-focus>`、`<iris-workspace>` | 文件和标签边界是硬接口 |
| 环境变量 | `FOCUS_DOC`、`IRIS_WORKSPACE_PATH` | 进程协议 |
| 程序标识 | IPC channel、ISA 名、错误 code、设置 enum、theme id、session state | 机器接口，不是展示文本 |
| 文件格式 | `YYYY-MM-DD` 前缀、GFM checkbox、Markdown、Mermaid、Git SHA / `HEAD` | 解析、互操作或行业标准 |
| 用户数据 | 标题、正文、label、自由 status、负责人、路径、分支名、提交信息、agent 名和终端输出 | 不得自动翻译用户内容 |

`StatusBadge` 应继续逐字显示磁盘中的 `status:` 值。中文界面也显示 `In Progress`，而不是写成
“进行中”或“进行中 / In Progress”；未知或自由状态同样原样显示。周边动作可以翻译，例如
“更改状态” / “Change status”，但值本身不能翻译。这一规则延续当前“stored value = displayed
value”的产品契约。

类型集合标题也建议继续显示 `status`、`issue`、`report`、`misc`，因为它们同时是用户在磁盘
中会看到的真实目录名；解释性副标题、按钮和帮助文本可以本地化。`frontmatter`、Git、Markdown、
Mermaid、Agent 等技术名词保留统一拼写，不制造同义词。

### 可以本地化的内容

- 应用导航、设置、按钮、菜单、tooltip、placeholder、空状态、加载状态、确认与错误说明。
- ARIA label、窗口原生对话框、图片失败提示、Mermaid 状态提示和 Git 操作说明。
- “工作区”“会话”“终端”“源代码管理”等人类界面概念；它们的内部 id 仍保持英文。
- 时间桶、数量句式和面向人的标题/标签排序。磁盘中的 ISO 日期和值不改变。
- 设置页中的协议查看器外壳和说明。查看器展示的协议正文、tag、key 与注入示例保持原文。

## 推荐架构

### 1. locale 模型

在共享 `Settings` 顶层增加：

```ts
type LocalePreference = 'system' | 'zh-CN' | 'en-US';
type AppLocale = 'zh-CN' | 'en-US';
```

设置版本可继续为 `1`：现有 deep merge 会为旧设置补上默认值，不需要迁移用户文件。新增统一的
`resolveLocale(preference, systemLocale)`，main 和 renderer 不各自猜测回退规则。

### 2. 翻译引擎和资源

建议使用 `i18next` + `react-i18next`：renderer 使用 React hook，main 使用独立的 i18next
instance 处理 Electron 原生对话框；两端共享同一套资源和 locale 解析。它已提供插值、复数、
fallback 和缺失 key 处理，避免自造字符串模板器。

资源按领域拆分为 `common`、`project`、`collection`、`editor`、`terminal`、`git`、`settings`、
`errors`。以 `en-US` catalog 的 key 结构作为类型真相源，`zh-CN` 必须满足同一 key 集；生产环境
fallback 到 `en-US`，测试环境遇到缺失 key 直接失败。key 描述语义，例如
`terminal.search.noMatch`，不得把中文原文当 key。

翻译函数只接受 message key 和结构化参数。canonical token 通过领域常量直接渲染，禁止调用
`t(status)` 或把磁盘值拼成翻译 key。

### 3. 两个运行时

- renderer 在首次绘制前读取设置、初始化 i18n，再挂载 React，避免语言闪烁。设置广播后调用
  `changeLanguage`，同时更新 `document.documentElement.lang`。
- main 在 `SettingsManager.initialize()` 后初始化自己的 i18n instance。退出确认和目录选择等
  原生对话框按当前 resolved locale 取文案；语言变更广播时同步切换。
- 开发态 `front-cpu` 调试控制台若仅支持有限 locale，则映射到其支持值；它不能反过来决定
  Iris 的 locale。

### 4. 稳定 id 与展示 label 分离

- Issue 空分组改用 `__no_status__` / `__no_label__` 或 discriminated union，label 在渲染时翻译。
- Report 时间桶改用 `today`、`last7Days`、`last30Days`、`older`、`undated`，折叠状态也保存 id。
- session state、Git resource group、设置分类、筛选、分组、排序和主题 tone 均以现有英文 id
  驱动逻辑，再映射本地化 label。
- 面向人的标题和标签排序统一使用缓存的 `Intl.Collator(resolvedLocale)`；路径、status rank、
  日期前缀和协议扫描顺序继续使用稳定的非本地化比较。

### 5. 错误处理

主进程领域错误应保留稳定 `code` 和结构化 `details`，IPC 边界把它们序列化为
`{ code, params, technicalMessage }`。renderer 翻译已知 code，并在未知错误时原样展示
`technicalMessage`，日志始终记录技术原文。这样可以本地化用户可行动的信息，又不隐藏排障
细节。文件路径、Git 输出、CLI 输出和解析器原始错误作为参数插入，绝不翻译。

不要求第一轮重写所有内部异常；先覆盖会直接到达 UI 的 Project、Git、Asset、Session、Settings
错误，纯断言和开发错误继续使用英文技术消息。

## 发布与回滚

该方案不迁移 `.iris/` 项目文件，也不改协议版本。唯一新增持久化数据是机器级 locale preference，
旧设置通过默认合并兼容。若需要回滚，可以停止读取该设置并固定使用现有中文 catalog；由于
canonical 数据从未被翻译，回滚不需要修复项目文件、状态值或 agent 提示词。
