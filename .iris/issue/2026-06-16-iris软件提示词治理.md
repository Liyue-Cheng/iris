## 这件事要解决什么

Iris 会把一些规则交给 agent。现在这些规则主要挤在
`.iris/CONVENTIONS.md` 里，软件自己的规则和项目自己的规则混在一起，带来三个问题：

- 不清楚哪些内容由 Iris 维护，哪些内容由项目作者维护。
- 入口文件只留下“请去读另一个文件”的提示。没有 hook 的 agent 可能不会继续读，导致拿不到规则。
- 文件被升级、手工修改或漏写以后，没有可靠的方法判断该怎么办。

目标很简单：规则放在磁盘上，注入时直接给 agent 正文；Iris 自己管理的部分有明确边界和版本，用户写的内容不被偷偷覆盖。

## 最终决定

规则分三层：

### 1. 软件层

所有项目都一样的 Iris 规则，例如目录语义、focus 文档协议、写回范围和注入兜底规则。

- 放在入口文件的 `<iris-software>` 块中。
- Iris 负责维护，随 App 版本更新。
- `AGENTS.md` 是标准入口；已经存在的 `CLAUDE.md` 等 vendor 入口只做镜像，不主动新建。

### 2. 项目层

只对当前项目有效的规则，例如 issue 状态值和 Markdown 写法。

- 最终落点改为 `AGENTS.md` 的 `<iris-project>` 块。
- `CLAUDE.md` 等已有入口镜像同一块；真正的正本只有 `AGENTS.md`。
- init 时种入一次，之后项目作者拥有内容。Iris 只检查状态，并且只给“仍是出厂默认”的内容提供升级；自定义内容不覆盖。
- 旧的 `.iris/CONVENTIONS.md` 只作为迁移来源，迁移前保留 `.bak`，不直接删除。

### 3. 用户层

只对当前机器和当前用户有效的事实，例如代理、资源限制和个人偏好。

- 继续放在 `~/.iris/CONVENTIONS.md`。
- 文件存在时才注入，Iris 不改写其正文。

## Agent 怎么拿到这些规则

每一段都直接放在标签里，标签外的文字归用户自己：

```text
<iris-software>软件层正文</iris-software>
<iris-project>项目层正文</iris-project>
<iris-user>用户层正文</iris-user>
<iris-focus>当前聚焦文档</iris-focus>
```

有 hook 的会话直接注入这四段；没有 hook 的 agent 至少可以从入口文件读到软件层和项目层。不会再依赖“请自行去读某个文件”的口头指针。

软件块带版本号和内容哈希。Iris 只解析自己拥有的标签块，不给用户标签外的内容建立格式约束。块的状态按下面处理：

- `ok`：内容是当前版本，什么都不做。
- `stale`：内容是 Iris 以前的版本，提示重新同步。
- `drifted`：内容被手工改过，重新同步前提示会覆盖并先留 `.bak`。
- `missing`：入口文件存在，但缺少对应标签块，提示补上。
- `no-entry`：文件不存在；`AGENTS.md` 可以创建，vendor 入口不创建。

项目层另有三种状态：当前出厂默认、旧版出厂默认、自定义。只有前两种允许升级，自定义项目永远不自动覆盖。

所有写入都要用户确认，写入前先备份；文件无法解析时拒绝覆盖。

## 当前代码已经做到的事

以下是第一版（项目层仍使用 `.iris/CONVENTIONS.md`）已经具备的能力：

- 软件、项目、用户三套模板已经拆开。
- 软件块支持生成、解析、哈希校验、状态判断和幂等同步，并保留标签外内容。
- hook 和设置页能展示软件层、项目层、用户层以及合成后的注入内容。
- init、同步和项目层升级都遵守“只在必要时写入、写前备份、不覆盖自定义内容”。
- 机器层模板可查询并经确认安装。
- 相关 IPC、ISA、设置页和第一批测试已经接通。

## 还缺什么

下面这些是最终决定落地前必须完成的工作：

- 把项目层从 `.iris/CONVENTIONS.md` 挪到 `AGENTS.md` 的 `<iris-project>` 块，并同步已有 vendor 入口。
- init 不再新建项目层 `.iris/CONVENTIONS.md`；发现旧文件时提供“迁移到入口块”的确认操作，保留 `.bak`。
- hook、设置页、扫描器和预览改为读取入口里的项目块；保留旧文件的一次性兼容读取。
- 把标签处理抽成可复用逻辑，同时支持 `<iris-software>` 和 `<iris-project>`。
- 更新项目初始化、软件提示词和扫描器测试，断言入口文件包含两个块。
- 定义书中关于作用域、注入链和项目层落点的描述要一起改，避免实现和文档再次分叉。
- 增加存量项目迁移检测：能识别旧项目里混入的软件规则，并给出迁移差异；不能靠猜测解析用户自定义内容。
- 每次模板更新都追加旧版本指纹，否则旧项目无法识别为“可升级”。
- 在 App 启动或打开项目时主动检查入口块，发现过期、漂移或缺失时提醒用户。

## 验收清单

- [ ] 新建项目后，`AGENTS.md` 同时有 `<iris-software>` 和 `<iris-project>`，不再生成项目层 `.iris/CONVENTIONS.md`。
- [ ] 已存在的 `CLAUDE.md` 能得到同样的两个块；不存在的 vendor 入口不被新建。
- [ ] 有 hook 的会话能收到 software、project、user、focus 四段标签内容。
- [ ] 手工改动 `AGENTS.md` 的项目块后，镜像入口显示 `drifted`，重新同步前会提示并备份。
- [ ] 项目层查看器显示入口中的项目块；出厂默认仍能正确判断为“当前”或“旧版”。
- [ ] `npm run typecheck` 和相关 `vitest` 测试通过。
- [ ] 确认 `.bak` 内容无误后，再清理本仓库遗留的备份文件。
