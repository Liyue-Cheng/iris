## 问题

Iris 要往 agent 的上下文里注入不少提示词，但早期没分级，全焊在一份人写的
`.iris/CONVENTIONS.md` 里，导致三个毛病：

1. **分不清谁拥有、谁注入。** 同一份文件里"文件夹语义"（软件级不变量，所有项目
   都一样）和"issue 状态机取值、md 风格"（项目级策略，每个项目可不同）混在一起，
   没人知道哪段该跟软件版本走、哪段是本项目自定义。
2. **注入靠"口头指针"，不可靠。** 入口文件只写"请去读 `.iris/CONVENTIONS.md`"，
   没 hook 的 agent（如 Codex）未必照做。
3. **没有可追踪边界。** 改了哪段、是不是出厂默认、软件升级后要不要重新同步——无从
   判断。

**期望**：

* 三层提示词都**落在硬盘上**，注入 = 把文件内容**直接插进来**，不靠口头指针。

* Iris 注入的每一段都包在 `<iris-xxx>` 标签里——**标签内 = Iris 管辖、可追踪，标签
  外 = 用户的，互不侵犯。**

* 能确定性地检测入口文件里的托管块是否缺失 / 过期 / 被改动。

## 方案

### 三层模型（归层试金石）

| 层      | 内容                              | 盘上文件                     | 所有者  | 版本化                     | 标签                |
| ------ | ------------------------------- | ------------------------ | ---- | ----------------------- | ----------------- |
| **软件** | 文件夹语义、focus 协议、写回作用域、注入兜底语义等不变量 | App 内置模板 → 落成入口文件里的托管块   | Iris | 随 App 版本（version + sha） | `<iris-software>` |
| **项目** | issue 状态机取值、md 风格、本项目特有约定       | `.iris/CONVENTIONS.md`   | 人    | 出厂默认可自动升级               | `<iris-project>`  |
| **用户** | 加密软件、代理、资源限制、个人偏好               | `~/.iris/CONVENTIONS.md` | 人    | 无                       | `<iris-user>`     |

判层口诀：「任何机器任何项目都成立」→ 软件层；「换机 checkout 后仍成立、但每个项目可
不同」→ 项目层；「换台机器这句话就不成立」→ 用户层。

这套机制属于**渲染/适配层**，不动协议本体（壳依然只设 `FOCUS_DOC`）。校验对象**只限
Iris 自己拥有的标签块**，绝不给用户写的结构立 schema。

### 注入两条腿，都打标签

* **静态腿**——项目根入口文件。`<iris-software>` 托管块**内联**软件层正文 + 版本戳，
  物理落在 `AGENTS.md`（Iris 标准入口，不存在则创建）和**已存在的** vendor 入口
  （`CLAUDE.md` 等，存在才维护、绝不新建）。这是无 hook agent 的兜底触达面。

* **动态腿**——SessionStart hook（`~/.iris/focus-context.ps1`）。有 hook 的 agent
  会话启动时把四段直接 cat 出来各包标签：`<iris-software>`（从 AGENTS.md 单源复述）/
  `<iris-project>`（cat `.iris/CONVENTIONS.md`）/ `<iris-user>`（cat
  `~/.iris/CONVENTIONS.md`，有才输出）/ `<iris-focus>`（cat `$FOCUS_DOC` 快照，

  > 32 KiB 降级为指针）。

**注入兜底语义**（写进软件层正文）：`FOCUS_DOC` + 回盘读文件**只是兜底**；agent 已从
hook 拿到的内容不要再回盘重读（除非有理由认为已变更）。

### 标签与校验（全程确定性：标签解析 + 哈希比对，零启发式）

`<iris-software version="…" protocol="1" sha="…">` —— `sha` 是**标签内容**的短哈希，
O(1) 检测块是否被手改。入口文件五态：

| 状态         | 判据                 | 处理                       |
| ---------- | ------------------ | ------------------------ |
| `ok`       | sha = 当前           | 无动作                      |
| `stale`    | 块是旧版但未被改（命中历史 sha） | 提示可重新同步                  |
| `drifted`  | 块被手改 / 内容未知        | 提示重新同步会覆盖（留 .bak）        |
| `missing`  | 文件在、无标签块           | 提示可注入                    |
| `no-entry` | 文件不存在              | AGENTS.md 走创建；vendor 不创建 |

### 项目层自动升级（只对"还是出厂默认"的项目）

`.iris/CONVENTIONS.md` 概念上三个版本：软件自带默认 / 用户自带默认
（`~/.iris/templates/CONVENTIONS.md`，init 时优先）/ 盘上真实自定义。

拿盘上文件 hash 比对内置的「历代出厂默认指纹集合」：命中当前默认 = 最新；命中历史默认
\= 可一键升级（经确认 + .bak）；都不命中 = 已自定义，**不碰**。只是成员测试，不给用户内容
立 schema。

### 一切写入经用户确认、写前留 `.bak`、解析不了的文件拒绝覆盖。

## 现状（2026-06-24，本仓库 dogfood 已验证）

### 已建成

* **模板三拆**（`iris-templates.ts`）：`SOFTWARE_PROMPT_TEMPLATE`（含注入兜底语义）、
  瘦身后的 `CONSTITUTION_TEMPLATE`（只剩状态机 + md 风格）、`MACHINE_CONVENTIONS_TEMPLATE`、

* **确定性核心**（`software-prompt.ts`，纯函数 + 单测）：标签 build/parse、内容
  `contentHash`、`classifySoftwareBlock`（ok/stale/drifted/missing）、`upsertSoftwareBlock`

* **注入适配**（`agent-injection.ts`）：`FOCUS_CONTEXT_SCRIPT` 四段打标签、单源复述软件块；
  `syncEntryFile`（写前 .bak、仅变化时写）；`assembleContextPreview`（合成预览，含出厂默认模板）。

* **项目生命周期**（`project-manager.ts`）：`initIris` 种入（有用户默认用用户默认，否则软件
  默认；从不覆盖已存在的人写宪法）+ 维护已存在 vendor 入口；`softwarePromptState`、
  `contextPreview`、`syncSoftwareEntry`、`upgradeConstitution`（仅 stale-default 可升、自定义

  IPC / ISA 打通；版本号经 `app.getVersion()` 注入。

* **设置「软件提示词」页**：软件层各入口五态徽章 + 经确认同步；项目层出厂默认升级状态 + 经确认

  `AGENTS.md` 只剩 `<iris-software>` 块；`CLAUDE.md` 删掉与软件块重复的 PM 协议前言、保留全部
  编码/技术内容。三份 `.bak` 待验收后删。

### 未建成 / 缺口

* **§7 存量宪法迁移检测（最大缺口）**：无任何代码检测"自定义宪法里仍残留软件层语义"并给
  迁移 diff。`classifyConstitution` 只做三态 hash 成员测试，识别不了"重叠/残留"这种中间态——
  存量项目一旦被改过就归 `customized`、彻底不被帮助。本仓库这次是**手工**清理的，换个存量项目
  仍要手工来。

* **历史指纹集合近空**：`HISTORICAL_SOFTWARE_PROMPT_SHAS = []`、`LEGACY_CONSTITUTION_DEFAULTS`
  仅 1 条。升级链路代码在，但目前只能识别 pre-治理 那一版单体宪法；今后每次改模板要记得 APPEND
  旧指纹，否则升级路径形同虚设。

* **无启动主动校验**：`softwarePromptState` 是被动按需查询（打开设置页才拉）。§4 设想的"App
  启动 / 打开项目 / 版本变化时主动扫描并提示"没有触发器——用户不开设置页就不会被提醒块过期/漂移。

## 方案变更（2026-06-24，产品负责人拍板）：项目层并入入口文件 `<iris-project>` 块

> **本节取代上文「方案」里项目层的落点。** 软件层 / 用户层不变；改的只是项目层物理家：
> 从独立文件 `.iris/CONVENTIONS.md` 改为入口文件里的 `<iris-project>` 托管块。

### 为什么改

取消独立的 `.iris/CONVENTIONS.md`，把项目层也以托管块形式直接放进入口文件（AGENTS.md /
CLAUDE.md），与软件层并列。理由：`<iris-software>` 与 `<iris-project>` 各有 XML 标签隔离，
放一起不混淆；agent 打开入口文件即可一眼看清"这个项目怎么管理"，少一个文件、少一跳注入。

这是**协议级**改动，覆盖定义书若干条文（见末节），需连定义书一并改。

### 新模型（三层落点）

| 层  | 标签                | 盘上落点（新）                                  | 所有者      | 版本化              |
| -- | ----------------- | ---------------------------------------- | -------- | ---------------- |
| 软件 | `<iris-software>` | 入口文件托管块                                  | Iris     | 随 App 版本（**不变**） |
| 项目 | `<iris-project>`  | **入口文件托管块**（原 `.iris/CONVENTIONS.md` 退役） | 人（种入一次后） | 出厂默认可升级          |
| 用户 | `<iris-user>`     | `~/.iris/CONVENTIONS.md`（**不变**）         | 人        | 无                |

`<iris-project>` 在 init 时由模板种入（`~/.iris/templates/CONVENTIONS.md` 用户默认优先，否则
软件默认 `CONSTITUTION_TEMPLATE`），之后**人拥有**：Iris 检测三态（current-default /
stale-default / customized），**只对仍是出厂默认的**提供升级，自定义的绝不覆盖——与今天
`.iris/CONVENTIONS.md` 的"App 只读"姿势一致，只是物理家从独立文件搬进入口块。

### 关键取舍：单一来源防漂移

可编辑正本 = **AGENTS.md** 的 `<iris-project>` 块。已存在的 vendor 入口（CLAUDE.md 等）由 Iris
把同一份块**镜像**进去（与软件块同款机制：内容一致、sha 追踪、被手改即报 drifted、经确认重新
同步）。改项目策略 → 改 AGENTS.md 的块；CLAUDE.md 的副本 Iris 替你同步。既满足"CLAUDE.md 里
AI 也直接读得到"，又不出现两份各自为政的漂移。**编辑认准 AGENTS.md；vendor 副本是镜像。**

> 待定子选择：若觉得镜像太重，可降级为"项目块只放 AGENTS.md，CLAUDE.md 仅留软件块 + 指针"——
> 更简单，但 CLAUDE.md 里读不到项目块正文（hook 注入仍能补上）。
