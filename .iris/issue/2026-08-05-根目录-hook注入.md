## 建议版本

### 问题定义

现在文档会话用 `FOCUS_DOC` 表示焦点，`focus-context.ps1` 也以它作为唯一的
输出开关。项目根和子工作区的 hub 会话虽然已经带有 `workspacePath`，但为了
保持“无聚焦兜底会话”的语义会删除 `FOCUS_DOC`，所以 SessionStart hook
完全没有输出 Iris 的软件层、项目层和用户层提示词。

这里不能把工作区根目录伪装成一篇文档：`FOCUS_DOC` 的含义是文档路径，伪造
路径会让 agent 尝试读取不存在的文件，也会破坏最近工作区和写回范围的判断。

### 方案

给 Iris 启动的 hub 会话增加一个独立的子进程环境变量：

* `IRIS_WORKSPACE_PATH`：项目相对路径；项目根使用 `.iris`，子工作区使用实际
  工作区路径（例如 `产品/客户端`）。该变量只在 Iris spawn 的 hub 会话中设置，
  不写入用户 shell 配置，也不改变当前 `FOCUS_DOC` 的协议。
* 文档会话继续设置 `FOCUS_DOC`；可同时设置 `IRIS_WORKSPACE_PATH` 作为元数据，
  但焦点文档仍由 `FOCUS_DOC` 唯一决定。

`focus-context.ps1` 的触发条件改为“`FOCUS_DOC` 或 `IRIS_WORKSPACE_PATH` 至少
一个存在”：

1. 两者都没有：认为是用户从外部打开的普通 agent，保持零输出。
2. 只有 `IRIS_WORKSPACE_PATH`：输出现有的 `<iris-software>`、`<iris-project>`、
   `<iris-user>` 三层，并新增一段运行时元数据：

   ```text
   <iris-workspace path="产品/客户端">
   本终端是 Iris 启动的工作区根会话；当前没有聚焦文档。
   工作区根（相对项目根）：产品/客户端
   </iris-workspace>
   ```

   不输出 `<iris-focus>`，也不把工作区路径当作 `FOCUS_DOC`。agent 可以知道自己
   属于哪个工作区，但仍需等待用户给出具体任务和文档目标。
3. 有 `FOCUS_DOC`：沿用当前四段注入；若同时有工作区变量，在首行元数据中补充
   工作区路径即可，不重复输出工作区块。

根项目和子工作区使用同一套脚本、同一套 hook 配置，不新增第二个 hook，也不依赖
   agent 是否支持额外启动参数。hook 仍然只属于用户自己的 agent 配置，Iris 的
   设置页不需要改变代写确认和 `.bak` 规则。

### 实现边界

* `src/main/session-manager.ts`：创建 hub 会话时设置并清理
  `IRIS_WORKSPACE_PATH`；文档会话按现有逻辑处理 `FOCUS_DOC`。
* `src/main/agent-injection.ts`：调整脚本开关、首行元数据和
  `<iris-workspace>` 输出；保留超过 32 KiB 的文档降级规则及 Codex 的非 JSON
  首字符约束。
* `src/renderer/lib/session-actions.ts`：继续传递已有 `workspacePath`，不新增
  UI 手势或改变会话锚定模型。
* 更新脚本快照/单测，覆盖项目根 `.iris`、嵌套工作区、文档会话和普通外部终端
  四种输入组合；设置页的静态预览增加“工作区会话无焦点文档”的说明。
* 不修改 `AGENTS.md`、`.iris/CONVENTIONS.md` 或 hook 配置格式；不改变 hub
  会话当前工作目录仍为项目根，工作区路径是上下文元数据而非 `cwd` 切换。

### 验收

- [ ] 在项目根节点新开带 hook 的 Claude/Codex 会话，收到软件、项目、用户三层和
  `<iris-workspace path=".iris">`，不出现 `<iris-focus>`。
- [ ] 在嵌套工作区新开会话，收到对应的工作区相对路径，且不会误报为项目根。
- [ ] 从文档开会话时，现有 `<iris-focus>` 内容和 `FOCUS_DOC` 行为不变；同时显示
  工作区元数据时不重复注入第二个 workspace 块。
- [ ] 在项目外或未由 Iris 设置变量的普通 agent 会话中，hook 仍然零输出。
- [ ] 脚本未安装、旧版、hook 代写/更新、Codex `/hooks` 信任审核流程均保持原行为。
