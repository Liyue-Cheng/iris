但是这个功能的bug还没有完全消失，AI创建的编辑标签的时候经常填写这个字段，然后，我手工删除会导致解析失败

已经有两个受影响的issue文件了

.iris/issue/2026-08-09-Git基础工作流可靠性缺陷.md

.iris/issue/2026-08-09-密集开发修改审计.md

然后你现在需要调查问题，然后针对修复受影响的文件，然后提示词什么的都需要告诉AI 本字段尚未启用，不要填写

## 2026-08-09 治理记录

已确认两个受影响文件把单行空数组与缩进 YAML 序列混在同一个字段下：
`labels: []` 后仍保留 `- ...` 子项，导致整个 frontmatter 解析失败。当前移除
并不完整：内置提示词仍宣称 `labels:` 可用，Issue/Report 集合、扫描模型、
本地视图偏好和 README 仍保留标签能力；通用 frontmatter 行级写回也没有消费
被替换字段原有的多行子节点。

本轮治理边界：彻底移除标签的创建、编辑、投影、展示、过滤和分组能力；合法的
历史 `labels:` 作为未知 YAML 原样保留，不做全库数据清洗；AI 不得新增或改写
该字段，除非用户明确要求修复或迁移已有标签元数据。

## 2026-08-09 实施结果

- 已从两个受影响 issue 中删除损坏的 `labels` 节点；两份 frontmatter 均已由
  `gray-matter` 验证，可正确读出原有标题和状态。
- 已移除 Issue/Report 的标签展示、过滤、分组和搜索投影，删除标签组件、颜色
  工具、扫描字段、类型字段、国际化文案及专用 frontmatter 序列 API。
- 本地集合视图偏好升级为 v3，旧的 `groupBy: label` 不再进入运行时。
- 通用 frontmatter 写回现在会整体替换顶层字段及其缩进续行，并保留 LF/CRLF
  风格；已覆盖多行序列和 CRLF 回归测试。
- 内置软件提示词已把 `labels:` 定义为“保留但尚未启用”，明确禁止 AI 新增、
  填写、编辑、规范化或删除，除非用户明确要求修复或迁移；README 和协议测试
  已同步。
- `npm run typecheck`、29 个 Vitest 文件共 189 项测试、`npm run build` 全部通过；
  `git diff --check` 通过。

- [ ] 在 Iris 设置页修复 `CLAUDE.md` 顶部损坏的旧提示词残片，并重新同步
  `AGENTS.md` 与 `CLAUDE.md`；确认每个入口仅有一份托管软件块，且旧的
  “`labels:` optional list” 文案不再存在。
