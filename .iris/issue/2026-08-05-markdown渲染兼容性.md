# Markdown 渲染兼容性缺口

## 现象

依据 `.iris/status/Markdown 渲染兼容性测试.md` 的人工验收结果，基础 CommonMark、GFM 表格/任务列表、代码块和安全过滤通过；以下能力当前无法使用或只显示源码：

* 本地/远程图片、图片链接及失效图片状态。

* Mermaid 流程图、时序图、状态图和饼图。

* 数学公式（行内、块级和 `math` 围栏）。

* 脚注与定义列表。

* GitHub 提示块及 `::: info` 容器提示块。

* `details`、`kbd`、`mark`、原生 HTML 表格等 HTML 扩展。

## 根因调查

1. 文档正文由 `src/renderer/components/doc/CrepeEditor.tsx` 中的 Milkdown Crepe 实例直接解析，当前只配置了 CodeMirror 和可选的 BlockEdit；没有 Mermaid、脚注、定义列表、容器提示块等解析/渲染插件。
2. 同一处配置将 `Crepe.Feature.Latex` 显式设为 `false`，因此数学公式不会进入 KaTeX/LaTeX 渲染链；`remark-math` 虽在依赖树中，但没有接入当前文档管线。
3. `react-markdown` 与 `remark-gfm` 出现在 `package.json`，但 `src/renderer` 没有对应的 `ReactMarkdown`/remark 使用点，不能产生任何运行时兼容性；这属于“依赖已安装、管线未接入”。
4. HTML 标签是否保留取决于 Milkdown 的 HTML 支持和安全策略。当前没有 `rehype-raw` 或等价的受控 HTML 节点配置，因此 `details`、表格等标签降级为纯文本是当前实现的预期结果；脚本和 `javascript:` 被过滤则说明安全边界有效，不能为兼容性修复而放开原始 HTML。
5. 图片失败不仅是 Markdown 语法问题，还需要渲染器把相对 URL 解析到当前文档目录，并为本地资源提供安全的 file/protocol 映射；现有代码没有看到该 URL 解析与错误占位处理。

## 修复建议

* 先确定唯一渲染策略：继续扩展 Crepe/Milkdown，或为只读预览建立 `react-markdown` + `remark-gfm` +（按需）`remark-math`/脚注插件管线；不要同时维护两套不一致的解析规则。

* 在启用扩展时逐项加入安全白名单：图片协议和相对路径解析、HTML 标签白名单、链接协议过滤、图片加载失败占位；禁止脚本、事件属性和 `javascript:`。

* Mermaid 使用独立代码块渲染器并提供错误降级；数学公式使用 KaTeX/MathJax 并保留源码降级；脚注、定义列表、提示块分别增加插件或稳定的普通文本降级。

* 为每项扩展补充自动化渲染测试，并在浅色/深色主题、窄屏和编辑/阅读切换下复测验收清单。

## 2026-08-09 Mermaid 复查

持续显示“图表渲染中”的根因是异步预览值没有通过 Milkdown 的响应式回调更新。
`renderMermaidPreview` 先把一个带加载文案的 `HTMLElement` 交给
`applyPreview`，Milkdown 的 `PreviewPanel` 随即用 DOMPurify 清洗并复制该节点的
HTML；页面持有的是副本。Mermaid 完成或报错后，当前实现只修改已经脱离页面的原
节点，因此屏幕副本会永久停留在加载状态。

现有单元测试只观察传给 `applyPreview` 的原节点，没有覆盖 `PreviewPanel` 的清洗复制
行为，所以测试通过但不能代表集成路径可用。正确的异步契约应当是：初次返回
`undefined` 让 Milkdown 显示 `previewLoading`，Mermaid 完成或失败后再次调用
`applyPreview` 提交最终字符串或节点。

当前 CSP 不是该现象的主因：Mermaid 核心和各图型 parser 已构建为应用自身的同源
JS chunk，符合 `script-src 'self'`；内联 SVG 样式与常见图片来源也分别由现有
`style-src 'unsafe-inline'` 和 `img-src 'self' data: blob: https:` 覆盖。即使未来
出现动态分包加载或 CSP 错误，当前脱离 DOM 的错误容器也会把错误提示一并隐藏，
因此修复后仍需用集成测试覆盖成功和失败回调。

* [x] 改为在 Mermaid 成功或失败后调用 `applyPreview`，并增加覆盖 Milkdown 清洗复制行为的集成测试。

实现已在 Mermaid 成功和错误分支重新调用 `applyPreview`。新增回归测试模拟 Milkdown
对 loading 元素的 DOMPurify 清洗复制，确认页面副本会被最终 SVG 替换；完整测试共
29 个测试文件、190 项测试通过，生产构建通过。开发实例正在运行，可直接进行应用内
人工复测。

第二次应用内复测表明，仅再次提交同一个 `HTMLElement` 仍不足以触发更新：Vue `ref`
会按引用相等跳过通知。实现已更正为初始阶段只返回 `undefined`，由 Milkdown 安装
`previewLoading`；成功或失败后再首次提交新建的最终节点。回归测试同步采用 Vue 的
同引用跳过语义。控制台同时发现 Milkdown 将越界 ProseMirror 选区直接派发给
CodeMirror，现已在 Iris NodeView 适配层限制到当前文档范围。完整测试更新为 29 个
测试文件、191 项测试，生产构建通过。

Mermaid 预览工具栏已调整为紧凑图标布局：编辑切换按钮只显示铅笔图标并排列在复制
按钮左侧，不再显示带“编辑”文字的大按钮。生产构建通过，开发实例已通过 HMR 加载样式。

表格中的连续长行内代码此前继承 Crepe 的 `display: inline-block`，整个代码串成为不可
拆分盒子并溢出单元格。表格专用样式现将行内代码恢复为可断行 inline，使用
`overflow-wrap: anywhere` 和 `word-break: break-all` 处理无断点 token；表格 wrapper
同时限制到编辑列宽并保留横向滚动兜底。生产构建通过。
