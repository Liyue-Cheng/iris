# Markdown 渲染兼容性缺口

## 现象

依据 `.iris/status/Markdown 渲染兼容性测试.md` 的人工验收结果，基础 CommonMark、GFM 表格/任务列表、代码块和安全过滤通过；以下能力当前无法使用或只显示源码：

- 本地/远程图片、图片链接及失效图片状态。
- Mermaid 流程图、时序图、状态图和饼图。
- 数学公式（行内、块级和 `math` 围栏）。
- 脚注与定义列表。
- GitHub 提示块及 `::: info` 容器提示块。
- `details`、`kbd`、`mark`、原生 HTML 表格等 HTML 扩展。

## 根因调查

1. 文档正文由 `src/renderer/components/doc/CrepeEditor.tsx` 中的 Milkdown Crepe 实例直接解析，当前只配置了 CodeMirror 和可选的 BlockEdit；没有 Mermaid、脚注、定义列表、容器提示块等解析/渲染插件。
2. 同一处配置将 `Crepe.Feature.Latex` 显式设为 `false`，因此数学公式不会进入 KaTeX/LaTeX 渲染链；`remark-math` 虽在依赖树中，但没有接入当前文档管线。
3. `react-markdown` 与 `remark-gfm` 出现在 `package.json`，但 `src/renderer` 没有对应的 `ReactMarkdown`/remark 使用点，不能产生任何运行时兼容性；这属于“依赖已安装、管线未接入”。
4. HTML 标签是否保留取决于 Milkdown 的 HTML 支持和安全策略。当前没有 `rehype-raw` 或等价的受控 HTML 节点配置，因此 `details`、表格等标签降级为纯文本是当前实现的预期结果；脚本和 `javascript:` 被过滤则说明安全边界有效，不能为兼容性修复而放开原始 HTML。
5. 图片失败不仅是 Markdown 语法问题，还需要渲染器把相对 URL 解析到当前文档目录，并为本地资源提供安全的 file/protocol 映射；现有代码没有看到该 URL 解析与错误占位处理。

## 修复建议

- 先确定唯一渲染策略：继续扩展 Crepe/Milkdown，或为只读预览建立 `react-markdown` + `remark-gfm` +（按需）`remark-math`/脚注插件管线；不要同时维护两套不一致的解析规则。
- 在启用扩展时逐项加入安全白名单：图片协议和相对路径解析、HTML 标签白名单、链接协议过滤、图片加载失败占位；禁止脚本、事件属性和 `javascript:`。
- Mermaid 使用独立代码块渲染器并提供错误降级；数学公式使用 KaTeX/MathJax 并保留源码降级；脚注、定义列表、提示块分别增加插件或稳定的普通文本降级。
- 为每项扩展补充自动化渲染测试，并在浅色/深色主题、窄屏和编辑/阅读切换下复测验收清单。

## 验收

- [ ] 图片（含相对路径、远程地址、链接图片和失效图片）按安全策略渲染。
- [ ] Mermaid 四类图表可渲染，语法错误时显示可读降级内容。
- [ ] 数学公式、脚注、定义列表和提示块可渲染或稳定降级。
- [ ] 允许的 HTML 标签可用，脚本、事件属性和危险协议仍不会执行。
- [ ] 自动化测试覆盖上述能力及主题、窄屏场景。
