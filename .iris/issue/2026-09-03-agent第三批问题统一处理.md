彻底治理方案（2026-09-03）：

普通终端仍由 `SessionManager` 管理，Iris Agent 仍由 `IrisAgentSessionManager` 管理；两者在 renderer
边界通过适配器投影成同一种 `SessionProjection`。左栏、右栏、状态点、选中态和关闭入口只依赖该投影。

* [x] 新增共享的 `SessionKey`、`SessionAnchor`、`SessionActivity` 和 `SessionProjection` 类型。

* [x] `SessionKey` 使用带类型的稳定键，例如 `terminal:<id>`、`iris-agent:<id>`，所有选择、菜单和回退逻辑禁止只使用裸 `id`。

滚动统一治理方案（2026-09-03）：

当前 Agent 消息区的问题不是简单地再补一次 `scrollTop = scrollHeight`，而是缺少统一的 Session 视口模型。普通终端已经有明确的“用户上滚后不抢回、回到底部后恢复跟随”语义，Agent 消息区应复用同一套视口状态机，但不把消息区伪装成 xterm。

一、统一边界

* `SessionProjection` 继续负责 Session 的身份、anchor、选择和生命周期；不把滚动位置塞进后端 Session 或 Agent 持久化数据。

* renderer 新增共享的 `SessionViewportState`，以 `SessionKey` 为键保存 UI 视口状态。每个 Session 至少保存 `mode`（`follow-bottom` 或 `free`）、`scrollTop`、最后观测的 `scrollHeight` 和 `clientHeight`。

* 普通终端和 Agent 消息区各自提供内容测量方式，但都接入同一个 `SessionViewportController`。controller 只处理视口状态、恢复、底部锚定和用户意图识别，不知道 PTY、Turn 或 Markdown 领域细节。

二、状态机和切换语义

* Session 初次出现时默认 `follow-bottom`，但已有视口记忆时必须优先恢复该 Session 上次状态。

* 用户滚动事件是唯一可以把 `follow-bottom` 切换为 `free` 的直接来源。离底部超过退出阈值后立即停止自动滚动；回到底部进入阈值后恢复 `follow-bottom`。

* 进入 `free` 后，新消息和内容高度变化都不能改变 `scrollTop`。切换到其他 issue 前先保存当前状态，切回来时恢复原位置，而不是重新把 `follow` 初始化为 `true`。

* `follow-bottom` 下切换回来必须在首次 paint 前恢复到底部；`free` 下切换回来必须在首次 paint 前恢复保存的位置。恢复动作使用 `useLayoutEffect` 或等价的 pre-paint 阶段，避免先显示顶部再跳转造成闪烁。

三、底部锚定和竞态处理

* 不再由每次 `turns` 引用变化直接创建互相取消的独立 RAF。controller 维护一个可合并的 pending frame，同一帧内的多次 projection patch 只执行一次滚动计算，避免流式 token 更新造成 RAF 饥饿。

* `follow-bottom` 模式下监听消息内容容器的 `ResizeObserver`，在 Markdown 换行、图片完成加载、卡片展开或字体/宽度变化后重新计算最大滚动位置并保持底部锚定。observer 只在跟随模式生效，`free` 模式只更新测量值，不写 `scrollTop`。

* 程序性恢复和用户滚动必须区分。controller 写入 `scrollTop` 时设置一次性 programmatic 标记，忽略该写入引发的 `scroll` 回调，防止恢复动作把 `follow-bottom` 错误改成 `free`。

* 底部判断使用带滞后的阈值，例如进入底部 24px、退出底部 32px，避免滚动条整数取整和尺寸微调在两个状态之间抖动。滚动行为保持 `auto`，不使用平滑动画掩盖状态错误。

* 明确处理浏览器原生 scroll anchoring：由 controller 负责底部锚定时，消息 viewport 使用稳定的 `overflow-anchor` 策略，避免浏览器锚点和应用锚点同时修正导致二次跳动。

四、更新链路约束

* Agent projection 更新继续由 revision 保证顺序，但视口 controller 不依赖 `turns` 数组引用作为唯一触发条件；它响应实际 DOM 尺寸变化，并可接收一个轻量的内容 revision 作为合并调度提示。

* Session 切换、Session 销毁和项目切换必须清理对应 `SessionKey` 的临时 observer、RAF 和事件监听；销毁后不得由迟到的回调写入新 Session 的 viewport。

* Agent 内部终端仍是 `AgentTerminal` 子资源，不创建独立的顶层滚动记忆键；只有对话消息区和普通终端各自作为顶层 SessionSurface 接入 controller。
