## 这件事到底要做什么

我们想让 Iris 里的 agent 具备两种能力：

1. **学会特定的做事方法**：例如按照公司的代码规范做代码审查，或者按照固定格式写周报。这类“做事说明书”叫 **Skill**。
2. **使用外部工具和数据**：例如查数据库、访问第三方服务、读取其他程序提供的数据。这些外部能力通过 **MCP** 连接。

可以把它们想成：Skill 是“说明书”，告诉 agent 应该怎么做；MCP 是“插座”，让 agent 能接上外部工具。两者可以一起用：Skill 负责指导步骤，MCP 负责提供实际操作工具。

## Skill 是什么

Skill 本质上是一个目录，里面有一个叫 `SKILL.md` 的文件。文件里用简单的文字说明：

- 这个 Skill 叫什么；
- 什么时候应该使用它；
- 使用时要遵守哪些步骤和规则。

agent 不会一次性把所有 Skill 的全文都读进来。它会先看到一个简短的目录，判断当前任务是否相关，只有需要时才读取对应的完整说明。这样可以避免每次对话都变得很长、很慢。

为了让用户不用重复配置，Iris 要直接识别已经在 Codex 或 OpenCode 中使用的 Skill 文件，不再发明一套 Iris 专属目录。主要会查找：

- 用户自己的 Skill 目录；
- 项目里的 `.agents/skills/`；
- OpenCode 常见的 `.opencode/skills/`；
- 当前项目及其上级目录中的这些目录。

如果不同位置有同名 Skill，离当前项目更近的版本优先。Iris 只读取和使用说明，不执行 Skill 目录中的脚本，也不会修改用户的文件。

## MCP 是什么

MCP 是一套让 agent 连接外部工具的通用标准。外部程序按照 MCP 规范提供能力，Iris 负责连接、查看它提供了哪些工具，并在 agent 需要时调用。

例如，一个 MCP 服务可以提供“查询订单”“搜索文档”或“读取项目管理数据”等工具。agent 调用后，Iris 把结果整理成它能理解的内容，再继续完成任务。

Iris 不应该再设计一套新的 MCP 配置格式，而是读取用户已经存在的配置：

- Codex 的 `$CODEX_HOME/config.toml`；
- OpenCode 的 `opencode.json` 或 `opencode.jsonc`。

这些配置通常会写明服务名称、启动命令、参数、环境变量，或者远程服务的地址。Iris 先只读导入和使用，不回写这些文件，避免和其他客户端互相覆盖。

## 我们准备怎么做

### 第一阶段：先让 Skill 能用

先完成最基础、风险最低的部分：

1. 找到 Codex、OpenCode 和项目中的 Skill 目录。
2. 读取每个目录里的 `SKILL.md`，检查名称和描述是否有效。
3. 按项目距离处理同名 Skill，近的覆盖远的。
4. 根据用户当前任务，列出可能相关的 Skill。
5. agent 确定需要后，再把对应 Skill 的正文加入当前会话。
6. 记录哪些 Skill 被找到、被加载，或因为格式错误而跳过，方便排查问题。

这一阶段不会执行 Skill 里的代码，也不会把所有 Skill 全部塞进每次对话。

### 第二阶段：把 Skill 接入对话

在 agent 开始一次会话时，先生成 Skill 的简短目录；当任务匹配到某个 Skill，或者用户明确要求使用某个 Skill 时，再读取它的完整内容，并作为这次会话的额外规则交给 agent。

设置界面之后可以显示 Skill 的来源、是否启用和最近一次扫描结果，但第一版以稳定读取为主。

### 第三阶段：接入 MCP 工具

1. 读取 Codex 和 OpenCode 的 MCP 配置，并转换成 Iris 内部统一的格式。
2. 启动和管理本地 MCP 服务，先支持最常见的命令行（stdio）方式。
3. 读取服务提供的工具清单，把这些工具加入 agent 可用的工具列表。
4. 统一处理超时、服务崩溃、重连、输出过长和敏感信息隐藏。
5. 以后再支持通过 URL 连接远程 MCP 服务。
6. 在界面中显示服务状态、可用工具、调用记录和错误。

外部资源不会自动注入对话，必须由 agent 明确请求；配置发生变化时，只影响新开的会话，避免当前会话中途改变工具集合。

## 做完后怎么确认没问题

- 用真实的 Codex 和 OpenCode Skill 目录测试，确认能找到并正确覆盖同名 Skill。
- 测试错误格式、重复目录和越界路径不会导致 Iris 读错文件。
- 用 Codex 和 OpenCode 的真实配置样例测试 MCP 配置读取。
- 使用本地测试 MCP 服务，确认工具列表、调用结果、超时和崩溃恢复都正常。
- 补充一份配置和使用说明，让用户知道文件放在哪里、Iris 会读取什么，以及哪些操作需要明确授权。
