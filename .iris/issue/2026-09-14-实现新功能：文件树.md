## 2026-09-20 视觉对比与改进建议（仅分析）

本轮需求：先对比 VS Code 和 Iris 的实现，不修改代码。以下基于 Iris 当前源码和 VS Code 官方仓库 main 分支源码；没有启动应用、截图或进行运行时视觉验收。VS Code 的主题、图标主题与用户设置会影响最终外观，以下不将其视为唯一固定样式。

### 对比结论

Iris 已有整行 hover、目录展开箭头、文件图标、截断和外部关联标记。主要改进空间在列表密度、文字可读性、层级线索和状态一致性；建议保留 Iris 配色与现有交互，借鉴 VS Code 的排版秩序。

| 维度 | VS Code | Iris 当前实现 | 建议 |
| --- | --- | --- | --- |
| 行密度 | Explorer 普通行固定 22px，工作台默认 13px 字号 | 13px 字号加上下各 4px padding，没有显式行高；按默认继承行高推算约 27.5px，未实测 | 先采用固定 24px 行高、13px 字号，兼顾中文与紧凑程度 |
| 字体 | Windows 使用 Segoe UI / Microsoft YaHei 等系统无衬线字体 | 继承应用字体；默认 LXGW WenKai，也支持用户覆盖 | 字体会影响观感，但首轮保留用户字体设置，先修正排版 |
| 文字层级 | 普通文件共享正常文字层级，特殊状态再装饰 | 所有非 Markdown 文件使用 `text-muted-foreground/60`，hover 也更弱，虽可点击却容易像禁用项 | 普通文件统一正常文字色；扩展名不决定可用性或亮度 |
| 层级辨识 | 树组件有专用缩进、箭头槽与缩进引导线 | 每层 12px 缩进，没有引导线；根节点与普通目录同样呈现 | 保留 12px 缩进，增加低对比度引导线，突出当前分支；根目录作为独立标题行 |
| 图标与对齐 | 专用箭头槽不收缩，文件图标由图标主题决定，可区分文件类型 | 12px 箭头、14px 图标、4px 间隔；仅区分 Markdown/其他文件；文件夹展开前后图标相同；目录箭头和图标未禁止收缩 | 统一固定槽位与 16px 图标，展开目录使用打开图标；少量常见类型图标即可 |
| 选中与焦点 | hover、活动选中、非活动选中、键盘焦点有独立主题样式 | 高亮路径来自当前文档，且只有 Markdown 使用选中样式；点击文件是系统打开，不更新树选择；焦点与 hover 近似 | 独立记录树选择，所有节点状态一致；hover 弱底色、selected 稍强底色、键盘焦点细描边 |
| 窄栏与长名称 | 树内容和图标布局有独立约束，标签支持悬浮信息 | 文件名可截断，但没有完整路径的可视 tooltip；文件夹图标可能被压缩 | 固定图标与尾部标记宽度，文字独占剩余空间；悬浮展示完整路径 |
| 视图标题与工具 | Explorer 有明确标题和与当前视图相关的操作 | 文件树复用 Lens 工具栏，排序与过滤仍操作 Lens，RawTree 不消费这些状态 | 文件树模式有明确“文件”标题；只展示对当前视图有效的操作 |

补充：当前目录与文件的同级文字起点在正常宽度下本来就对齐。目录的 `12px 箭头 + 4px gap` 对应文件额外的 `16px padding`，不应误诊为普遍错位；真正需要修正的是窄栏时目录图标可能收缩，以及用固定槽位保证后续一致性。

### 建议方案与优先级

第一步以收益最大的基础视觉调整为主：24px 固定行高、13px 字号、普通文件正常文字色、统一 16px 图标与固定箭头槽、轻微圆角和整行反馈。保留 Iris 主题色，不引入另一套硬编码配色。按 28px 到 24px 粗略估算，同等高度约能多显示 17% 的行；这只是排版估算。

第二步完善树的层级和状态：根目录使用略加粗的标题行；低对比度缩进线在悬浮树或相关分支活动时增强；目录展开图标有所变化；独立树选择与文档打开状态解耦。保持文件点击系统打开、拖动粘贴路径及现有右键操作，不在视觉调整中擅自改变打开行为。

第三步再补常见文件类别图标、完整路径 tooltip 和文件树专用工具栏。保留 External 关联标记，统一其右侧留白；可为关联信息补 tooltip。类型颜色宜少而克制，不需要先引入完整图标主题系统。紧凑文件夹、虚拟列表等扩展能力不作为本轮视觉方案的前提。

## 2026-09-20 排序与筛选适配（用户纠正）

上一轮隐藏文件树排序与筛选入口的处理不符合需求；用户明确要求保留功能并适配业务语义。本轮恢复入口及筛选输入框，使用现有左栏排序/筛选状态，按当前视图解释：Lens 继续按文档标题/名称筛选，文件树按文件和目录名称/项目相对路径筛选。

实施语义：同层目录优先，组内按名称自然排序（数字按数值排序）或文件系统修改时间从新到旧；相同修改时间按名称稳定排序。目录使用目录本身的修改时间，不把子文件内容修改时间冒充目录修改时间。扫描数据补充实际 mtime，读取失败降级为 0。

筛选忽略大小写和首尾空白，兼容 Windows 反斜杠路径；保留命中节点及祖先，目录命中时保留其内容，匹配路径默认展开。搜索中仍能手动折叠，更换搜索词重新展开匹配路径；清空搜索恢复搜索前的展开状态，空结果显示明确提示。排序、筛选 tooltip 和输入提示按视图显示对应的中英文文案。

验证结果：`npm run typecheck`（含 async boundary）通过；6 个相关测试文件、38 项测试通过，覆盖磁盘 mtime、目录优先、名称自然序、时间序与同时间回退、路径匹配、目录命中、祖先保留、空结果、控件状态驱动树排序和过滤、搜索展开状态恢复，以及原有打开/拖拽/右键交互。`git diff --check` 通过。没有运行构建或开发服务器。

边界：修改时间来自最近一次文件树扫描；沿用现有扫描刷新机制，未新增全工程文件监听，因此工程普通文件的外部修改不承诺立即刷新，重新进入文件树会重新扫描。目录时间为文件系统目录 mtime，不是子树最近活动时间。
