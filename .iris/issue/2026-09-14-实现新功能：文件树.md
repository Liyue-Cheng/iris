左上角的图标中，添加一个功能，文件树视图

显示这个工程中的所有文件

暂时不实现点击打开，文件可以拖动到文档中粘贴路径

这其实是一个很简单的功能，需要做的事情主要是视觉效果要设计好，要参考vscode文件树

## 实施计划
- [x] 定位左上角图标/侧边栏入口及现有文档拖拽能力
- [x] 添加文件树视图，展示工程文件并支持目录展开/收起
- [x] 实现文件拖拽到文档时粘贴路径，不实现点击打开
- [x] 完成针对性验证并记录结果
- [x] 文件点击使用系统默认程序打开
- [x] 文件右键菜单支持复制路径、默认程序打开和在文件管理器中显示
- [x] 优化文件树文件与目录的鼠标悬浮效果

## 实现结果
- 左栏新增 `Files` 文件树入口，展示整个工程根目录下的所有文件和目录（不再局限于 `.iris/`），支持目录展开/收起。
- 文件树状态与现有 `projectStore.rawMode/rawTree` 联动，切换时保留原有 Lens 视图。
- 文件节点均可拖动并携带项目相对路径；Markdown 文件继续支持点击打开，非 Markdown 文件保持不可点击，符合“暂不实现点击打开”。
- 新增中英文 tooltip 文案：`layout.fileTree`。

## 验证
- `npm run typecheck` 通过（Node、preload、web TypeScript 检查及 async boundary 检查均通过）。
- 根据补充需求，文件树数据源已从 `.iris/` 根调整为完整工程根目录。
- `npm run typecheck` 通过。
- 文件树 hover 调整后再次运行 `npm run typecheck`，通过。
- 未运行打包命令或开发服务器；视觉细节仍建议人工在应用中复核。
- 文件树根目录默认展开，根目录下的其他目录默认收起，用户可按需展开。
- 文件树中的所有文件点击后通过系统默认程序打开，包括 Markdown 文件；右键菜单提供复制项目相对路径、默认程序打开、在文件管理器中显示。
- 文件与目录行统一为更接近 VS Code 的整行悬浮反馈：背景和文字色平滑变化；不可预览文件也有明确但更弱的 hover；键盘焦点与 hover 使用一致反馈。
