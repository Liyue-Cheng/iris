## 2026-09-05 全面重写：先调研、后推翻一切

按你要求"网上调研设置页面设计标准，然后把现在的东西全部推翻重写，只改视觉效果不动业务逻辑"，本次未做任何妥协性小修，直接把 `SettingsView.tsx` 的视觉层整体重写。**零业务逻辑变更**：所有设置项、校验、IPC、状态形状、handler 与上次实现逐字一致。

### 调研：设置页面的设计标准

参考的主流范式（Apple HIG 的 settings 指南、macOS `Form` grouped 惯例、Linear/Stripe 的"左侧导航栏 + 内容列"模式）：

- **导航**：常驻左侧分类导航；当前分类用高亮标示。页头是页面标题 + 一段说明，不是一行小字。
- **不需要把每个设置框成一个卡片**。用"空白 + 小节标题"分组，而不是每个分组一个带边框的盒子——盒子套盒子正是原来显得狭窄逼仄的根源。
- **分组形式**：每类设置 = 多个 `Section`，每一行一项。行内左侧是标签 + 可选提示，右侧是控件；控件列要有足够的可用宽度。
- **视觉层级**：页面标题（一级）> 小节标题（二级）> 行标签（三级）> 提示文字（四级），用字号和字重区分，不用灰蒙蒙一片。
- **控件形态统一**：输入框、开关、分段选择器共用同一套高度、圆角、宽窄和状态色才协调。
- **内容列宽度**：约束在可读宽度内、大窗口时居中，避免无限拉伸；但保证控件列不挤压（原来是 672px 里又抽出 200px 标签列，控件只剩约 330px——复合编辑被夹爆）。

### 具体改动（仅 `src/renderer/components/settings/SettingsView.tsx`）

- **去掉每组的卡片框**：`SettingGroup` 从 `rounded-lg border bg-card/50 divide-y` 改为"小节标题 + `divide-y` 分隔线"，用小节标题承载层级，不再框死每一组。
- **内容列加宽**：`max-w-2xl` → `max-w-3xl`，左右 `px-8` → `px-10`，上下 `py-6` → `py-10`（底 `pb-20`）。行标签列固定 `12.5rem`，控件占据剩余全部宽度——复合编辑器（模型目录、启动器表格、项目工具栏动作）不再被塞进 330px 的窄栏。
- **层级**：页面标题 `text-sm` → `text-xl`；小节标题从灰 `text-[13px] text-muted-foreground` → `text-base font-semibold`；行标签加 `font-medium`；侧边栏 `w-48` → `w-56`、`p-3` → `p-4`、激活态 `bg-primary/10` + `aria-current`。
- **控件归一**：`ToggleSwitch` 加高到 `h-6 w-11`（thumb `h-5 w-5`）；`Segmented` 改为带底座的 `p-1` 容器 + 选中白/明胶囊；数字输入、`IconNameInput`、`PromptViewer` 的圆角尺寸统一。
- **成行改两列表单**：`AgentsPanel`、`PromptsPanel`、`IrisAgentSettingsPanel` 里的 `SettingRow` 从"单列堆叠"改为"标签列 + 控件列"的同一套网格，和普通设置行对齐。
- **去掉表格头**：`AgentsPanel` 不再是 `<table>`，改为与其它设置行一致的两列表单行，行内列对齐关系不变。
- **错误提示**：所有 `border-l-2` 的一根竖线改为完整的圆角警示块，阅读负担更低。

## 2026-09-05 补充二：模型目录的呈现整改

针对"已配置方案"下模型目录的不满，重新设计了该段的组织方式。改动仍只涉及
`SettingsView.tsx` 与 `resources.ts`（新增 i18n key），**零业务逻辑变更**——所有
handler、编辑状态、保存/获取/添加的 IPC 与语义原样保留。

- **每个方案独立一张卡**：顶部为方案名 + 供应商·URL + 右侧删除按钮；下方是模型目录，
  不再把方案信息、目录、工具栏、模型行全部挤进一个带边框的盒子里。
- **模型目录改成带列头的表格**：`模型` / `上下文窗口` / `输出预留` / 操作列头，行内
  显示名在上、模型 ID 在下，上下文窗口与输出预留是带单位的编号输入（数字裸露在无标签
  输入框里的困惑消除）。
- **工具栏归位**：`从供应商获取模型`、`手工添加模型 ID`、`添加模型` 排成一行，与
  `保存模型配置` 分离到表格头和页脚。
- **未保存 vs 已保存状态**：页脚显示 `未保存的修改` / `模型配置已保存`，保存按钮只在
  真有变更时可用（用 `editingModels[profile.id]` 与 `profile.models` 的深度比较计算，
  "获取模型"不会误判为脏）。
- **去掉硬编码中文**：原 JSX 里写死的中文（模型目录与上下文预算、预设、删除模型等）
  全部改为 i18n key，中英 catalog 成对加入，`locale.test.ts` 的中英对齐通过。

## 2026-09-06 补充三：移除模型目录窄框并放宽数字输入

根据复核反馈，上一版模型目录仍然保留了卡片式外框，且主内容继续受 `max-w-3xl`
限制；上下文窗口和输出预留列也过窄，导致数字输入框实际可用宽度不足。本次只调整
`src/renderer/components/settings/SettingsView.tsx` 的视觉布局，不改动状态、handler、
校验或 IPC 语义：

- 设置主内容改为 `w-full`，去掉固定最大宽度，让表单和模型目录使用窗口剩余空间。
- 已配置方案之间改用横向分隔线；模型目录移除圆角边框和背景框，保留标题、工具栏、列头和行分隔线。
- 上下文窗口列至少 `16rem`，输出预留列至少 `12rem`；上下文数字输入在组合控件中使用可伸展空间，快捷单位选择器略微加宽。
- 手工添加模型 ID 输入改为可伸展输入，避免在宽窗口中仍被 `max-w-xs` 限制。

## 2026-09-06 补充四：平衡普通文本框宽度

放宽主内容后，普通设置行和启动器/项目工具栏中的文本框继承了整行宽度，出现输入框过长的问题。
现将宽度策略拆开：模型目录继续使用窗口可用宽度；普通 `SettingRow` 控件限制在 `max-w-xl`，
启动器命令与项目工具栏编辑区分别限制在 `max-w-2xl` / `max-w-3xl`。这只是容器宽度约束，
未改变任何业务逻辑。
