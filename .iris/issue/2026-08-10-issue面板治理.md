## 目标

Issue 面板应是稳定的主从工作界面：左侧浏览和筛选 issue，右侧查看或编辑当前 issue。选择 issue 不离开当前模式，也不破坏编辑会话；同时让列表、详情留白和分隔符在不同窗口宽度及 UI zoom 下保持清晰、稳定。

## 当前实现

### 交互与会话

Issue 模式使用独立两栏布局，只显示左侧 `IssuePanel` 和右侧 `DocView`，不渲染全局导航树与终端。布局由 `ResizablePanelGroup` 管理，`autoSaveId` 为 `iris-issue-browser`：左栏默认 40%、最小 28%、最大 58%，右栏默认 60%、最小 38%。

选择一行只更新 collection 内的 `selectedPath`，详情继续复用完整 `DocView` 和现有 editor session。切换时沿用保存、冲突检查、navigation intent 和项目 scope 保护；快速切换不会被旧请求覆盖。删除当前文件只清空详情，Issue 模式保持不变。

详情 Header 和行右键菜单都提供“在默认界面打开”。该动作复用当前 editor session，不重新读取文档；返回 Issue 模式时恢复最近选择及列表的筛选、分组、活动行和滚动位置。

### Issue 列表

列表已经移除复选框、多选、批量状态栏和相关快捷键，当前详情路径是唯一选择状态。点击、`Enter` 和 `o` 均在右侧打开详情。

行首结构与 `GroupHeader` 一致：12px 左内边距、14px 图标槽、8px 间距。选中行在图标槽中显示 14px `ChevronRight`，普通行保留等宽空槽；Issue 标题与分组头中的 `Todo` 文本共用 34px 文字基线。该对齐效果已经用户确认。

标题、状态、工作区和日期使用统一的双层 CSS Grid。标题是唯一弹性轨道；其余列使用共享外层槽位和按当前筛选结果测量的内层内容轨道。不可见测量覆盖全部筛选结果，不受分组折叠影响；单元格、状态 trigger 和 Badge 均受轨道裁剪，不会覆盖相邻列。

## 已确认视觉规格

- Issue 模式保持“列表 + 文档”两栏，不恢复全局导航树或终端。

- Issue 行不恢复复选框、多选或批量操作轨道。

- 行标题和选中 chevron 继续采用 `GroupHeader` 的槽位结构与对齐基线。

- 标题保持主信息弹性列，状态、工作区和日期保持共享列级对齐。

## 新的页面结构理解

这次需要调整的不是某一个 padding 或者 `editorMaxWidth`，而是重新划清“分栏布局”和“栏内内容排版”的责任边界。期望的 DOM 层级是：

```text
IssuePage
└─ ResizablePanelGroup          只负责水平几何分配
   ├─ ResizablePanel (left)     只接收分配后的宽高
   │  └─ PaneViewport         填满 Panel，隔离溢出
   │     └─ IssuePanel        根据 Viewport 排版并内部滚动
   ├─ ResizableHandle           两个 Panel 之间独立的布局元素
   └─ ResizablePanel (right)    只接收分配后的宽高
      └─ PaneViewport         填满 Panel，隔离溢出
         └─ DocView           根据 Viewport 排版标头和编辑区
```

这个结构的关键契约是：

- 顶层尺寸只由 `ResizablePanelGroup` 、两个 `ResizablePanel` 和中间的 `ResizableHandle` 决定。外层不关心 issue 列表的列宽、文档行长、header 对齐或滚动条。

- `PaneViewport` 是必要的尺寸边界，应始终填满 panel，并具备 `min-width: 0`、`min-height: 0`和明确的溢出隔离。这样业务内容再宽也不能反向撑大 panel，拖动手柄时只会改变 viewport 尺寸。

- 尺寸传递应是单向的：页面可用空间 -> panel 分配尺寸 -> pane viewport -> 业务组件。内容可以用 CSS 容器尺寸或 `ResizeObserver` 调整自己，但不应用内容的理想宽度反过来定义外层布局。

- 手柄是两个布局 DIV 之间的独立兄弟元素，自己占据稳定的布局车道、命中区和视觉线。它不应覆盖任何一侧内容，也不应由列表滚动条或文档背景客串它的视觉表达。

- 左侧 `IssuePanel` 的根容器应填满左侧 viewport；工具栏固定，列表只在剩余空间内滚动。双层 Data Grid 根据左侧 viewport 实际宽度重排，不与右侧或手柄交换尺寸信息。

- 右侧 `DocView` 的 header、编辑器表面和滚动容器首先都应填满右侧 viewport。“编辑器表面占满右栏”与“文字保持合理行长”是两个不同层级的问题：前者是布局契约，后者应由表面内部的响应式 content inset/阅读列规则解决，不应再让 `.ProseMirror` 这个核心交互表面通过 `max-width + margin: auto` 缩成一个与外部 pane 脱节的居中块。

- header 和正文应从同一个右侧 viewport 推导水平 inset，不再各自复制一套 `max-width`、外边距和滚动条补偿。它们可以保持文字基线对齐，但这种对齐是栏内排版结果，不应影响外层分栏。

从这个角度看，当前实现虽然已经有两个 `ResizablePanel`，但 panel 直接承载 `IssuePanel`/`DocView`，而 `DocView` 内的 header、`.crepe-host`、`.milkdown` 和 `.ProseMirror` 又各自参与宽度、居中和滚动决策。所以“外层分栏已存在”不等于“布局层已经纯粹”。新方向的本质是补上明确的 pane viewport 边界，然后让左右内容对这个边界做响应式排版。

## 未解决问题

### Milkdown 留白

DevTools 实测 `.milkdown` 宽 979px，内部 `.ProseMirror` 宽 928px。后者受 `editorMaxWidth: 58rem` 限制，并通过 `margin: 0 auto` 居中：

- `979 - 928 = 51px`，形成左右各 25.5px 的外部留白。

- `.ProseMirror` 的 928px border box 内含左右各 24px padding，实际文本区为 880px。

- 从 `.milkdown` 边缘到文字起点实际为 `25.5 + 24 = 49.5px`。

`.crepe-host` 的 `scrollbar-gutter: stable both-edges` 位于 `.milkdown` 外层，不属于上述 51px 差值。问题本质是外层详情面与受最大宽度限制的阅读列之间缺乏合理的宽度契约，但不能简单放宽正文行长或再次引入已否决的三段式布局。

### 分隔符

Issue 模式复用通用 `ResizableHandle`。当前命中车道宽 4px、`hitAreaMargins: 0`，常态仅显示 1px 的弱分隔线；所有布局都未启用 `withHandle`。左侧列表滚动条紧贴拖动车道，视觉和指针操作互相竞争，因此在 Issue 主从场景中缺少清晰、稳定的可拖动提示。

## 历史决策

已否决的方向包括：保留全局导航的三栏布局、按容器宽度隐藏数据列、固定 `table/colgroup` 列模型，以及“左侧工作面 + 中间走廊 + 右侧阅读面”的自定义三段式布局。最后一种方案已经按用户要求完整回滚；下一轮不应在其基础上微调。当前代码以两栏 `ResizablePanelGroup` 和双层 Data Grid 为准。

## 2026-08-11 两层布局第一版

已按新结构落地第一版，未恢复三段式布局：

- Issue 两个 `ResizablePanel` 内部各自增加了填满宽高、设置 `min-width: 0`、`min-height: 0` 并隔离溢出的 `PaneViewport`。分栏系统只分配几何尺寸，`IssuePanel` 和 `DocView` 只适应各自 viewport。

- `IssuePanel` 根容器明确填满 viewport，工具栏与列表滚动区继续使用现有内部布局。左侧 viewport 增加 4px 右内边距，列表滚动条不再紧贴分隔符。

- Issue 详情使用独立的 fluid 排版模式。`DocView`、header、`.crepe-host`、`.milkdown` 和 `.ProseMirror` 的交互表面填满右侧 viewport，Issue 详情不再用 `.ProseMirror` 的 `max-width + margin: auto` 缩小整个编辑表面。普通文档界面仍保留原有 `editorMaxWidth` 阅读宽度。

- 主从手柄最终继续复用主界面的通用 `ResizableHandle`：常态不显示 grip，仅保留细分隔线与 hover/drag 反馈。左侧右内边距负责解决滚动条与手柄的视觉竞争。

用户检视初版后确认“比之前好”，并要求增加左侧右内边距、取消常驻 grip；上述两项已纳入当前实现。

验证结果：`npm run typecheck`、32 个测试文件共 213 项测试、`npm run build` 和 `git diff --check` 均通过。已在 1680x1016、125% 设备缩放的开发窗口中抓取画面检查，未发现内容重叠、越过 pane 或常驻 grip。默认/最小/最大分栏与 75%–150% UI zoom 的完整人工验收仍保留为待办。
