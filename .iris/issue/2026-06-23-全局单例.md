我们是不是做了全局单例？你现在研究一下。是怎么回事？

## 结论：没有违规

红线「实例级配置，不用全局单例」指的是 **front-cpu 的接线姿势**——不要用库内置的全局注册表，而是每个 `Pipeline` 实例自带配置（ISA / executors / adapters 全在 `new Pipeline({...})` 注入）。`src/renderer/cpu/index.ts:8` 的注释写明了这点：`instance-level dependency injection only, no global registries`，好处是单测隔离免费。

代码里**确有**的是「模块级共享实例」，但它们符合范式：

- `cpu/index.ts:19` `export const pipeline` —— 渲染进程级单例，所有 `pipeline.dispatch()` 走它（配置是实例级注入的，没用全局注册表）。
- `stores/*.ts`（editor/project/session/focus/styles…）—— 模块级单例 + 订阅集合，是 React 外部 store 的标准姿势。
- 主进程 `SettingsManager` 是机器级单例（共享）；`ProjectManager` / `SessionManager` 在 v1.1 起改为**每窗口一套**（见 [[2026-06-23-多窗口多项目]]）。

关键点：渲染层每个窗口是独立 JS 上下文，模块级单例**天然每窗口隔离**——这正是多窗口能成立的基础。
