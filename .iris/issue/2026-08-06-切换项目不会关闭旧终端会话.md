title: 切换项目不会关闭旧终端会话
status: Done
---
在同一个窗口里打开另一个项目时，旧项目的文件 watcher 会关闭，但旧项目创建的 PTY 会话不会一起关闭。它们仍然在原 cwd 里运行，也仍然保留原来的 FOCUS\_DOC。

用户层面的危险是：切到项目 B 后，项目 A 的 agent 还在后台跑；如果两个项目里有同名文档或同样的 workspacePath，右侧会话投影还可能把旧会话混进新项目视图里。用户以为自己在操作 B，实际上输入可能还送到 A 的终端。

当前代码证据：

* src/main/ipc.ts 的 PROJECT\_OPEN 只调用 projectManager.open 和 gitManager.open，没有触碰 sessionManager。

* src/main/project-manager.ts 的 open 会 close 旧 watcher，但不了解 SessionManager。

* src/main/app-main.ts 只有 disposeWindowContext 时才 sessionManager.shutdown。

* src/renderer/stores/session-store.ts reset 会接受 SESSION\_LIST 返回的所有会话，没有按当前 projectRoot 过滤。

需要处理：

* [x] PROJECT\_OPEN 时在 main 侧原子关闭或迁移旧项目会话。

* [x] SessionInfo/session projection 带上可校验的项目代际或根路径，renderer 不能只按 docPath/workspacePath 过滤。

* [x] 切项目后旧项目会话不可见、不可输入，并且有明确关闭路径。

* [x] 补“窗口内从项目 A 切到项目 B”的会话隔离测试。

## 实现更新（2026-08-08）

同窗口切换现在由一条 `project.open` CPU 指令协调。它持有窗口级项目写锁；文档、会话、Git、样式和项目提示词等项目级写操作持有同一资源的读锁。main 侧仍是权限边界，会校验 renderer 提交的 `{ root, generation }`，切换期间和旧代际请求都会被拒绝。

main 会先完整预检目标目录，再进入不可回滚的前向提交：关闭旧代际的全部 PTY、切换 ProjectManager/GitManager、递增代际并持久化窗口绑定。预检失败保持旧项目不动；进入提交后，prompt/Git watcher 或最近项目持久化的次要失败只记录降级，不会让 main 已切到 B 而 renderer 回滚到 A。

SessionInfo、会话事件、会话列表、文件 watcher 和 Git 事件都携带项目 scope。renderer 的会话投影和所有异步响应会同时校验根路径与代际；终端输入、resize 和 replay 在 main 再校验 session 归属，因此旧会话不可见也不可继续输入。同根重复打开保持原代际、编辑器和会话投影。

同一目录的 Windows 大小写差异、junction 和符号链接别名会在预检时通过 `realpath` 收敛；预检后会再次做同项目判断，不会因为路径别名误关终端或递增代际。

自动验证：`npm test -- --run` 通过，共 12 个测试文件、88 个用例；Node 与 preload 类型检查通过；Web 在关闭未使用检查后通过。标准 Web 类型检查仍被并行 Git UI 文件 `src/renderer/components/git/ResourceRow.tsx` 中未使用的 `Undo2` 导入阻断，与本 issue 无关。
