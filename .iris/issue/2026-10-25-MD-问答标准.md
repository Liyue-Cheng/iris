## 2026-10-25 Agent 理解

### 问题本质：两类东西被塞进了同一种语法

agent 需要用户介入的事其实有两类：

| | 待办 / 验收项 | 待决问题 |
|---|---|---|
| 用户要做的 | 去做一件事、确认一件事 | 提供信息、做出选择 |
| 结果形态 | 二值：做了 / 没做 | 开放内容：一个答案 |
| 合适的语法 | `- [ ]` checkbox | 需要一个能写答案的位置 |

checkbox 只适合前者。拿它装问题，打勾只能表达“看过了”，答案没有落点，于是用户只能在终端里回答，答案没回到 issue——这与“详细方案、结果写回 issue”的追溯要求冲突，下次会话也看不到当时的决定。

### 为什么 agent 总用 checkbox：根源在我们自己的协议

`src/main/iris-templates.ts` 的软件协议写的是：

> When an item requires human review, verification, approval, **or follow-up**, represent it with one GFM task checkbox …

以及 In Review 规则里的 “add one unchecked task per remaining item”。“approval / follow-up” 范围太宽，agent 自然把“需要用户回答的问题”也归进去。协议目前只给了 checkbox 这一种“需要人介入”的表达方式，所以这不是 agent 不守规矩，而是协议缺了一类。

产品层面还有一个副作用：扫描器（`extractTodos`）会把未勾选项收进待办面板，`checkTodo` 可以一键勾掉——对问题来说，这等于“没回答就关闭了”。

### 对 `Q: / A:` 方向的看法

方向是对的：问题和答案都留在文档里，空 A 表示未答、非空 A 表示已答，agent 不需要额外状态就能判断。但裸写 `Q:` / `A:` 有几个细节要定：

1. **编号**：`Q1`、`Q2`……便于用户在终端里简答“Q2 选 B”，也便于 agent 回写时对应。
2. **问题要自带上下文**：为什么要问、影响什么、不回答时 agent 的默认做法。否则用户得翻上文才能回答。
3. **选项**：大量问题其实是选择题，应允许列选项并标推荐项，用户只填一个字母即可。
4. **答案边界**：多行答案到哪里结束？Markdown 里连续文本行会并成一个段落，所见即所得编辑器里也容易和下一个问题粘连。需要一个视觉和结构上都清晰的答案区（比如引用块或下一个 `Q` 前的空行约定）。
5. **位置与历史**：统一追加在一个“待确认问题”小节，符合 issue 追加历史的原则；已答的 Q/A 不删，本身就是决策记录。
6. **边界**：不是所有问题都要进 issue。只有影响方案、阻塞工作、需要留档的问题写进 issue；终端里一来一回的澄清可以留在会话。

一个可能的样式（仅示意）：

```markdown
## 待确认问题

**Q1.** 待答问题存在时 issue 状态用什么？
影响：决定 agent 提问后是否停下。不回答的默认：保持 In Progress。
- A. In Review（推荐）
- B. 保持 In Progress

> A：
```

### 需要改动的地方（仅列出，暂不实施）

- 软件协议（`iris-templates.ts`）：把“需要人做/验收的事 → checkbox”和“需要人回答的问题 → Q/A 格式”拆开；In Review 规则同步区分。对应的 `software-prompt` 测试和本仓库入口文件同步。
- 可选的产品层（后续）：扫描器识别空 A 的问题，在左栏/issue 列表显示“N 个待答问题”；待办面板不再能“勾掉”问题。V1 可以先只改协议，靠纯文本约定跑起来。

## 待确认问题

> 下面直接用上面提出的格式试运行，请在 `A：` 后填写。

**Q1.** 格式选型：裸写 `Q: / A:`，还是上面示意的“加粗编号 + 引用块答案”，或其他？
影响：决定协议文本和后续扫描器的识别规则。不回答的默认：采用示意样式。

> A：

**Q2.** 本次范围：只改协议文本，还是同时做产品层识别（待答计数、待办面板排除问题）？
不回答的默认：先只改协议。

> A：

**Q3.** 存在未答问题时 issue 状态怎么定？
- A. 改为 In Review（复用现有“等人”的状态）
- B. 保持 In Progress
- C. 允许 agent 设为 Blocked（需要放宽协议现有限制）

不回答的默认：A。

> A：

**Q4.** 问题被回答后，agent 是否需要把结论整理进正文（如“决策”小节），还是 Q/A 原地保留即可？
不回答的默认：原地保留，必要时在后续方案里引用 Q 编号。

> A：
