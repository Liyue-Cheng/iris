title: md渲染器不稳定
status: Canceled
---
右键点击程序其他地方的时候，会影响到md的解析，会导致渲染结果出现跳动，你对md渲染器的稳定性进行全面研究

## 研究结论

当前 Markdown 编辑器为 Milkdown Crepe + ProseMirror，挂载入口在
`src/renderer/components/doc/CrepeEditor.tsx`。右键菜单通过 Radix
`ContextMenuTrigger` 包裹整个编辑器；在编辑器外右键时，焦点会离开
ProseMirror，`DocView` 的 `onBlur`/`window.blur` 会立即调用
`editorStore.save()`。若正文已有未保存改动，保存内容来自 Crepe 最近一次
`markdownUpdated` 序列化，文件监听随后再读盘并触发投影检查。

已确认的稳定性保护：

- `mountCrepeSerially` 按 DOM root 串行化 `create()`/`destroy()`，React
  StrictMode 或文档切换不会并发操作同一 Crepe 实例。
- `editorStore` 在写盘前登记完整内容，并以字节比较吞掉自身 watcher 回声；
  正常情况下不会因自己的保存再次重载编辑器。
- Crepe 只在 `(path, generation, blockEdit)` 变化时重建，不会因每次正文
  序列化导致 React 重挂载。

## 最可能的故障时序

1. 在 WYSIWYG 中编辑正文，Crepe 产生新的序列化结果并标记 dirty。
2. 在编辑器外右键，Radix 菜单改变焦点；失焦处理立即保存当前序列化文本。
3. 保存引起布局/滚动容器重算，或与 ProseMirror 尚未完成的输入/选择事务
   同帧发生，用户看到内容高度、光标或渲染结果短暂跳动。
4. 若文件监听读到的内容与 `lastWritten` 不一致（例如外部格式化程序、
   多次快速写入或竞态），`handleDiskChange` 会把干净会话重新 `openSession`，
   这是可见跳动的真正重载路径。

右键本身不会改变 Markdown AST；需要区分“视图重排/滚动跳动”和“正文被
重新解析或被外部写回”。当前代码没有对右键事件做事务冻结或保存节流，
因此第一类现象仍可能发生。

## 建议验证

- [ ] 在正文无未保存改动时，在编辑器外连续右键；记录是否仍跳动。若仍跳动，优先检查 CSS 高度/滚动容器和 Radix focus 行为。
- [ ] 在有未保存改动时右键，观察控制台是否出现 `真实外部修改 → 重载编辑器`；同时记录 `markdownUpdated`、`doc.save` 和 `fs.iris.changed` 时间戳。
- [ ] 使用 Perf 面板确认右键瞬间是否出现 renderer long task、Crepe destroy/create 或滚动位置变化。
- [ ] 以同一文件在 WYSIWYG 与 Source 模式交替验证，判断问题是否仅存在于 ProseMirror/Crepe。

## 修复方向（待实现）

- 将“编辑器外右键”与普通窗口失焦保存解耦，至少延迟到菜单关闭且当前
  ProseMirror 事务完成后再保存。
- 对 watcher 重载增加会话 revision/写入序列校验，避免旧读盘结果覆盖较新的
  内存序列化。
- 为右键前后的滚动容器高度、`scrollTop`、Crepe 实例生命周期增加回归测试，
  覆盖快速连续右键和右键后立即粘贴两条路径。
