## 检查结论

记录中的 Vitest 不是测试失败，而是被 Iris Agent 的终端宿主强制终止。Windows 退出码 `-1073741510` 等于 `0xC000013A`，表示进程收到 Ctrl+C/Ctrl+Break；捕获输出中的 `^C` 也与此一致。

根因在 `src/main/agent/tool-host.ts`：每条 Agent 终端命令的超时被 `Math.min(Math.max(input.timeout ?? 3000, 1), 3000)` 硬性封顶为 3000ms。定时器到期后调用 `AgentCommandPty.abort()`，而它直接执行 `node-pty` 的 `pty.kill()`。因此：

* `npx vitest run src/main/agent/pi-adapter.test.ts` 刚完成 npm/Vitest 启动就到达 3 秒限制，被主动终止。

* `git diff --check; git diff -- ...` 需要扫描当前大量未提交改动，仍在输出 CRLF 警告时就超过 3 秒，所以同样以 `0xC000013A` 结束，后半段 `git diff -- ...` 也未必来得及执行。

* 命令传入的 `timeout` 无法解决这个问题，因为任何大于 3000ms 的值都会被再次截断为 3000ms。

`npx tsc --noEmit -p tsconfig.node.json` 则是另一个问题：该命令没有启动。`looksInteractive()` 对整条命令搜索 `node` 等关键词，`tsconfig.node.json` 中的 `node` 误命中了交互式 Node 检测，因此宿主在启动进程前就返回了 `Interactive terminal commands are not supported...`。

在 Iris 外部终端重新执行同一 Vitest 命令已通过：15 个测试全部通过。这进一步排除了 Vitest 自身失败。
