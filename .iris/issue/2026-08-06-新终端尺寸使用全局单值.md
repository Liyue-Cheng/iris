---
title: 新终端尺寸使用全局单值
status: Done
---
新建终端时会使用“上一次 TerminalView fit 出来的尺寸”，避免先按 120x30 启动再 resize。这个优化有用，但现在这个尺寸是 renderer 进程里的一个全局单值，不区分项目、窗口、工作区、右栏宽度或根视图/文档视图。

如果用户刚在很窄的文档右栏里用过终端，再切到全宽根终端新建会话，新 PTY 可能仍按窄尺寸启动；反过来也一样。随后虽然会 resize，但启动横幅、进度条和 TUI 首屏已经按错误尺寸画过一遍。

当前代码证据：

* src/renderer/stores/session-store.ts 的 lastTerminalDims 是模块级变量。

* src/renderer/lib/session-actions.ts 的 openSession/openWorkspaceSession 直接读取 getLastTerminalDims。

* 该值没有按 anchor、窗口布局或项目 root 分区。

需要处理：

* [x] 按窗口/项目/布局区域记录终端尺寸，而不是全局一个值。

* [x] root hub、workspace hub、doc right pane 至少不要互相污染初始尺寸。

* [x] 新 session 启动后仍保留首次 fit 校验，但不要依赖错误历史尺寸。

* [x] 补“窄文档终端后新建全宽根终端”的测试或手工验收。

## 2026-08-06 实现

终端尺寸历史已改为 renderer 窗口内按项目 root 和布局区域分区。布局区域分为 root hub、各 workspace hub 和 doc right pane；workspace hub 还按 workspace path 隔离。没有对应历史尺寸时回退到 120x30，不再读取其他区域最后一次 fit 的结果。

`TerminalView` 根据 session 的不可变 anchor 把每次有效 fit 回写到对应分区。创建 root、workspace 和文档 session 时使用同一套分区规则读取初始尺寸；创建后的首次 fit、最小尺寸保护和 PTY resize 通知流程保持不变。

验证：`npm run typecheck` 通过；`npm test` 通过（9 个测试文件、79 项测试）。新增回归测试覆盖窄文档右栏尺寸不会污染根 hub，以及项目和 workspace hub 之间的隔离。
