在 Iris 左栏提供轻量级的 Git Source Control 工作流，参考 VS Code 的资源组模型，先完成“查看状态 → 暂存 → 提交”的闭环，再逐步补齐开发者日常需要的 Git 操作。

## 当前实现

### 主进程与 IPC

- 每个窗口拥有独立的 `GitManager`，仓库根目录随项目上下文切换。
- 使用受限的 `execFile('git', args)` 执行 Git 命令，固定项目根 `cwd`、超时和 `windowsHide`；文件路径校验在 manager 内完成。
- `git status --porcelain=v1 -z --branch` 投影为 `GitSnapshot`，包含分支、HEAD、ahead/behind、detached 状态，以及 `merge`、`index`、`workingTree`、`untracked` 四组资源。
- 监听工作树和 `.git` 关键变化，事件只做防抖失效通知，renderer 收到 `evt:git:changed` 后重新拉取快照。
- 已接入状态、刷新、暂存、取消暂存、提交和本地分支切换 IPC；提交沿用用户的 Git hooks、签名和配置。

### Renderer

- `git-store` 维护快照、加载状态、错误和当前操作，不把 Git 状态混入 `project-store`。
- 暂存、取消暂存、提交和分支切换注册为 `git.*` ISA 指令，通过 FrontCPU `pipeline.dispatch` 执行，并在 `git:repository` 资源上串行调度。
- Git 状态刷新保持为只读投影查询，不进入 CPU 流水线，遵循项目现有的 CQRS 边界。
- `LeftPane` 挂载可折叠 Source Control 面板；收起时显示当前分支和变更数。
- `SourceControlPanel` 支持分组展开/收起、组级和文件级暂存/取消暂存、提交输入框、刷新、本地分支切换。
- 非 Git 仓库、无 HEAD、detached HEAD、冲突和命令失败保留为可见状态，不降级为空列表。

## 后续开发

按以下顺序继续，完成一项后在本节勾选并补充验证结果：

- [ ] **锁定领域测试**：为 porcelain `-z` 解析补充修改、删除、新增、重命名、冲突、特殊路径和无 HEAD 测试。
- [ ] **补齐 manager 集成测试**：使用临时仓库覆盖 status、stage、unstage、commit、分支切换、重命名和冲突；验证路径越界、锁文件和 hook 失败的错误语义。
- [ ] **补齐 store 测试**：覆盖 Git 失效事件重新拉取、操作串行化、过期响应不能覆盖新快照、刷新和操作失败后的恢复。
- [ ] **改善资源交互**：抽出稳定的 command descriptors，接入资源行/组标题菜单，为后续快捷键、右键菜单和多选操作保留统一入口。
- [ ] **增加 diff 工作流**：点击资源打开工作树/暂存区 diff，并明确无 HEAD、二进制和重命名文件的展示方式。
- [ ] **增加历史与分支能力**：提交历史、分支创建/删除、stash，以及 pull/push/sync；远端认证和冲突解决器另行拆分。
- [ ] **完善状态同步**：覆盖 watcher 边界、`.git/index.lock` 和 fsmonitor cookie 过滤、窗口重新聚焦，以及仓库切换和 watcher 生命周期。
