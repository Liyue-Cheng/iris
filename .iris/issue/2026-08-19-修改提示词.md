## 2026-08-19 调研：提示词体系盘点与修改建议

### 一、调研范围与已验证事实

本次调研覆盖软件提示词全链路，以下结论都基于代码与磁盘现状核对，不是印象：

- 真源与副本：`SOFTWARE_PROMPT_TEMPLATE`（`src/main/iris-templates.ts`）是唯一真源；
  `AGENTS.md` 与 `CLAUDE.md` 的 `<iris-software>` 块是它的逐字镜像。已实测：两端各
  6718 字符，与内置模板逐字一致（无属性、无漂移、无重复）。
- 四层结构：`<iris-agent-base>`（工具契约，来自 Pi 0.84.1 的窄改编，
  adaptationVersion=3）、`<iris-software>`（不变量协议）、`<iris-project>`（项目指令，
  真源在 `.iris/settings.json` 的 `prompts.project`）、`<iris-anchor>`（焦点文档快照 /
  workspace hub 元数据）。
- 两条交付路径：
  - 嵌入 Iris Agent：`session-manager.preparePrompt()` 每轮用内置模板 + settings 的
    project + 焦点文档原文组装（`src/main/agent/session-manager.ts:553` 一带），软件层
    不读入口文件。
  - 外部 CLI（Claude 等）：读入口文件里的受管块（静态层），SessionStart hook
    （`~/.iris/focus-context.ps1`）只交付 workspace/focus 动态层。
- 一致性机制：sha 校验 + drift 分类 + 会话启动门禁 `assertProjectSettingsReady()`；
  测试锁定状态机值、骨架与模板不变量（`software-prompt.test.ts`）。
- 本仓库项目层提示词（`.iris/settings.json`）与 `AGENTS.md`/`CLAUDE.md` 的
  `<iris-project>` 块内容一致。

### 二、发现的问题

按影响面排序，每条给出证据：

#### P1（值得改，措辞级或行为级）

1. **工作规则 1 与动态快照说明互相矛盾。** 规则 1 说 “If `$FOCUS_DOC` is set, read it
   first”；而 “How context reaches you” 一节说注入过 `<iris-…>` 快照就不要重读磁盘。
   两条都是不变量，字面读起来冲突（尤其嵌入 Agent 每次都收到 `<iris-anchor>`）。当前
   靠模型“读完全文再理解优先级”兜住，不应该靠这个。
2. **没有“如实声明验证”的规则。** 整份提示词没有要求 agent 区分“已验证”和“假设”。
   改代码后声称成功但不说明验证到什么程度，是这类工具最常见的信任事故。
   `iris-agent-可观测性` 是工程侧兜底，协议层缺一条行为约束。
3. **“方案/结果写回 issue”只存在于本仓库项目层。** 这是文档型 PM 工具的核心工作方式，
   却只是 `<iris-project>` 里的自定义经验，新项目不会自动获得。

#### P2（结构性，需决策）

4. **嵌入 Agent 与外部 CLI 存在不对称。** 嵌入会话的 software 层用内置模板（不看入口
   文件），但门禁仍检查入口健康；锚点正文没有大小上限（hook 对 >32KiB 降级为指针，
   `readAnchorText` 没有）。
5. **缺少跨边界/不可逆操作的请示规则。** intent 声明只保证“可见”，不保证“已授权”。
   安装、删除项目外文件、改全局配置这类动作，协议层没有要求先问。
6. **仓库自身入口文件没有 CI 守护。** 模板正文改了之后 `AGENTS.md`/`CLAUDE.md` 可能
   悄悄失步（当前恰好同步，但没有任何测试检查“仓库自己的入口”）。改文案的人很容易
   漏掉手动重同步。

#### P3（编辑/措辞级）

7. 状态骨架只给了 issue 一个完整示例，report/status 只在括号里提，建议补全三个骨架。
8. “How context reaches you” 整节以外部 CLI 视角写（“read from this entry file”），对
   嵌入 Agent 不准确（实际用内置模板），建议补一句说明两条路径承载同一正文。
9. “Any folder containing typed folders is a workspace” 没有说明嵌套 workspace，建议
   明示 “nearest enclosing”。
10. 模板用 TS 模板字符串承载，正文里的反引号都要写成反斜杠转义形式，改文案容易写错；这个保持
    现状（有 drift 分类兜底），不建议为它重构。

### 三、建议修改方案（具体到措辞）

下面每条给出位置、改动、理由和影响面。**本轮只调研和给方案，没有改代码**，按决策后
再实施。

1. **修规则 1**（软件层 Working rules）
   - 改为：Use the injected focus snapshot (`<iris-anchor>` / `<iris-focus>`) as the
     source of truth when present; otherwise, if `$FOCUS_DOC` is set, read it first —
     its path tells you both its type and its workspace. Then wait for the user's
     instruction — loading context is not a task.
   - 理由：消除与 “How context reaches you” 的字面冲突。
   - 影响：改 `SOFTWARE_PROMPT_TEMPLATE` → `AGENTS.md`/`CLAUDE.md` 需重同步；相关测试
     断言若涉及该句需同步。

2. **新增“验证声明”规则**（软件层 Working rules，建议放第 8 条）
   - 草案：Do not report success without verification. When you changed the codebase,
     run the checks the project guidance allows, and say exactly what you verified and
     what you did not. Distinguish “verified” from “assumed”.
   - 理由：P1-2；放进软件层而不是基础提示词，避免动 Pi 改编指纹。
   - 影响：同上，需重同步。

3. **“写回 issue”提升为软件层（决策项）**
   - 草案：When your task is driven by an issue (the anchor or `$FOCUS_DOC` is an
     issue), prefer recording the design and the outcome in that issue's body (append,
     per issue semantics) rather than only in chat.
   - 决策：进入软件层（所有项目受益）还是保持项目层（自定义偏好）？若提升，可删掉本
     仓库 `<iris-project>` 里的重复条目。

4. **跨边界请示规则（决策项）**
   - 草案：Ask before actions with irreversible side effects beyond the project
     boundary (package installs, deletions outside `.iris/`, global configuration).
   - 决策：“越界”的定义要在规则里说清，避免每步都问。

5. **嵌入/外部不对称（决策项）**
   - (a) 嵌入 Agent 也读入口文件 → 会话内容会受 drift 影响，与门禁一致；
   - (b) 保持内置模板，并在 “How context reaches you” 写明“嵌入 Agent 用内置模板、
     外部 CLI 用入口文件”。
   - 锚点正文：给 `readAnchorText` 加与 hook 一致的 32KiB 降级（推荐），或保持全量注入
     （长文档每轮开销大）。

6. **CI 守护（工程级，建议直接做）**
   - 在 `software-prompt.test.ts` 加一条：读仓库根 `AGENTS.md`（及参与列表里的
     `CLAUDE.md`），断言 `classifySoftwareBlock` 为 `ok`。模板改动后测试立刻指出需要
     重同步的入口。
   - 理由：当前失步只能靠设置页/门禁在运行时暴露，开发期就该拦住。

7. **补三个骨架示例**（软件层 “What the app parses”）
   - 把括号说明改成三个紧凑代码块（issue/report/status），与 `docSkeleton()` 保持
     测试锁定。

8. **补 “How context reaches you” 的交付路径说明（措辞级）**
   - 补一句：The same canonical text reaches you either from this entry file (external
     agents) or from the session assembler (embedded Iris Agent)。

9. **workspace 嵌套明示（措辞级）**
   - 补：Workspaces may nest; use the nearest enclosing one for write-back scope。

### 四、明确不改的部分

- 状态机值和骨架（测试锁定，UI 硬编码，改不动）。
- `labels:` 保留段（与现状一致，`提示词治理盘点` 等 issue 已按此维护）。
- 正文保持英文（模型兼容性更好，与 App i18n 无关）。
- hook 只交付动态层的分工（前几轮治理已定型，不倒退）。
- 项目层提示词的真源在 `.iris/settings.json`，`<iris-project>` 只是投影（已定型）。
