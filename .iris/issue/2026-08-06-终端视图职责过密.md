TerminalView 现在不是一个单纯的 React 视图。它同时管 xterm 创建、WebGL/Search/WebLinks addon、IME 私有 API workaround、剪贴板安全策略、OS 文件拖入、文档拖入、ResizeObserver、字号持久化、replay、seq 去重、搜索栏和上下文菜单。

这会让下一次修终端问题很难判断改动边界。比如输入策略、replay 协议、viewport/resize 和 UI 搜索栏本来是不同层的问题，现在都挤在同一个 effect 和同一个组件里。

当前代码证据：

* src/renderer/components/terminal/TerminalView\.tsx 约 1000 行。

* 同一文件里同时出现 WebglAddon、SearchAddon、IME \_core 访问、paste/drop、ResizeObserver、SESSION\_SCROLLBACK、SESSION\_INPUT 和字号设置。

* 当前没有专门覆盖 TerminalView 或 terminal transport 的测试。

需要处理：

* [ ] 先定义 terminal-transport、terminal-replay-controller、terminal-input-policy、terminal-viewport 的边界。

* [ ] 把 xterm 私有 \_core workaround 隔离到版本适配层。

* [ ] 搜索栏和上下文菜单留在 UI 层，输入/粘贴安全策略独立可测。

* [ ] 拆之前先补最小契约测试，避免机械拆文件后行为漂移。

## 处理建议（2026-08-06）

这次不以“把一个文件拆成多个文件”为目标，而是把 TerminalView 收缩为 UI 和生命周期组合根。核心逻辑应做成不依赖 React、DOM 或真实 xterm 的 TypeScript 控制器，通过 fake ports 在现有 Node 测试环境中验证。

建议边界：

* `terminal-transport` 只封装 `SESSION_INPUT`、`SESSION_RESIZE`、`SESSION_SCROLLBACK`、`SESSION_OUTPUT`、base64 编解码和取消订阅；不负责 replay 排序、fit 或 xterm。

* `terminal-replay-controller` 负责先订阅后取快照、hold queue、seq 去重、分块写入、parser fence、超时与失败降级；不直接访问 `window.api` 或 DOM。

* `terminal-viewport` 负责 ResizeObserver、trailing debounce、最小尺寸、replay gate、输入前 flush pending fit 和尺寸持久化；不处理 replay 数据。

* `terminal-input-policy` 以纯决策覆盖大文本、ESC、多行粘贴、文件路径 shell 元字符、路径 quoting 和剪贴板换行；对话框展示与 `term.paste()` 调用仍由外层执行。

* `xterm-compat` 集中探测 `_core` 形状、安装 IME workaround、降级和清理，TerminalView 不再直接访问 xterm 私有字段。

* `terminal-session-runtime` 组合 transport、replay、viewport 和 xterm，并统一销毁。replay 与 viewport 存在真实的协议耦合，例如 snapshot 请求期间尺寸变化后需要决定是否重取一次快照；这类跨层时序由 runtime 协调，不让两个控制器反向依赖。

搜索栏、上下文菜单及拖放事件入口保留在 React UI 层；SearchAddon 等 xterm 能力由 runtime 暴露命令和状态回调给 UI。

实施顺序：

* [ ] 先补 replay、viewport、input policy 和 xterm compat 的最小契约测试，使用注入的 transport、terminal sink、时钟和尺寸端口，暂不引入整套 React/xterm mock。

* [ ] 先提取 input policy 与 xterm compat，保持现有行为不变，并移除 TerminalView 中的安全规则细节和 `_core` 访问。

* [ ] 建立 typed terminal transport，再迁移 replay 状态机；第一轮不同时修改 main 侧 replay 协议。

* [ ] 提取 viewport controller，并覆盖 debounce、尺寸下限、replay 期间 resize 抑制、输入前刷新和 replay 结束后的 deferred fit。

* [ ] 引入 terminal session runtime 完成组合，最后再收薄 TerminalView；搜索栏和上下文菜单只做必要的 UI 拆分。

最低行为契约：

* [ ] replay 请求期间到达的输出不丢失、不重复，`seq <= lastSeq` 被过滤，失败时 hold queue 仍按序释放。

* [ ] snapshot 尺寸变化最多重试一次；dispose 后异步 replay、确认框和定时器不得继续写入旧 terminal。

* [ ] resize debounce 合并通知，小于 20×5 的尺寸不发送，输入发生前刷新 pending fit。

* [ ] ESC、大于 1 MB、无 bracketed paste 的多行文本和危险文件路径分别产生正确的确认决策。

* [ ] xterm `_core` 形状变化时只禁用对应 workaround，不阻断 terminal 挂载，dispose 能恢复 monkey patch。

完成时，TerminalView 中不应再直接出现 IPC channel、replay queue、ResizeObserver 或 `_core`；行数下降只是结果，不作为唯一验收标准。
