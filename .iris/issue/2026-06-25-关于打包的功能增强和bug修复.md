现在还是有很多bug的，首先就是只要不升级版本，就无法重新打包，打包会卡住，然后就是没有打包安装版本

## 根因

输出目录是 `dist/release/${version}`，重打**同一个版本**时这个目录被复用。上一次
打出来的 `win-unpacked\Iris.exe`（以及签名过的 node-pty 原生二进制）经常仍被占用——
旧的 Iris 还开着、杀软在扫刚签名完的 exe、句柄没释放等。electron-builder 要覆盖却
删不掉，就无限重试，表现为「卡住」。升版本号之所以能绕过，是因为换成了一个全新的空
目录，没有任何锁——`alpha.1~.5` 加手动的 `alpha2-rebuild` 都是被这个 bug 逼出来的。

## 改动

* `scripts/clean-release.mjs`（新增）：打包前带重试地强删 `dist/release/<version>`，
  扛住杀软那种瞬时锁；真删不掉时（确有进程占着）几秒内**明确报错**提示关闭正在运行
  的 Iris，而不是无限卡死。

* `package.json`：`dist` 脚本接入清理步骤，并改用 `electron-builder --win`（去掉
  `--win portable` 的限制，让配置里的全部 win 目标都打出来）；补 `author` 字段。

* `electron-builder.yml`：`win.target` 增加 `nsis`，与 `portable` 并存；新增 `nsis`
  配置块（向导式安装、装到当前用户免提权、可改安装目录、桌面/开始菜单快捷方式、卸载
  保留用户数据）。

已用当前版本 `0.0.2-alpha.5`（盘上已存在该版本）实测重打：清理步骤成功，未卡住，
`portable.exe` 与 `setup.exe` 两个产物均正常产出。

## 手工验收

* [x] 不升级版本号，连续两次 `npm run dist`，第二次不卡住

* [x] `Iris-<version>-setup.exe` 能正常安装、启动、卸载

* [x] 故意让一个旧 Iris 开着且占用本版本输出目录时，`npm run dist` 几秒内明确报错（而非卡死）

* [x] 免安装版 `portable.exe` 仍可正常运行
