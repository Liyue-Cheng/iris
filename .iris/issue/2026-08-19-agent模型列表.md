我看到很多模型是实际上不可用的的，一看就没有调用真正的模型列表，这是不可以的，你需要调用，然后展示可用模型

## 排查结论

问题属实。当前自定义供应商注册逻辑直接复制 Pi 内置的 OpenAI 或 Anthropic 静态模型目录，`runtime.getAvailable()` 只检查供应商是否配置了认证，并不会向供应商查询模型。因此每个自定义供应商都会显示整份模板模型列表，其中大量模型实际并不存在。

## 实施方案

- 注册自定义供应商前调用供应商的真实模型列表接口：OpenAI 兼容接口使用 `/models`，Anthropic 接口使用 `/v1/models`。
- 仅注册和展示接口实际返回的模型，不在查询失败时回退到模板的整份静态目录。
- 已在内置目录中的模型沿用准确元数据；供应商新增模型补充运行所需的保守元数据。
- 查询失败通过模型目录的错误字段反馈，避免把“接口失败”伪装成“模型可用”。
- 增加针对性测试，覆盖真实列表过滤、未知新模型、多个供应商隔离及密钥不泄漏。

## 实施结果

已将自定义方案的模型注册改为先用该方案自己的 Base URL 与 API Key 请求模型目录。OpenAI 兼容方案请求 `/models` 并使用 Bearer 认证；Anthropic 兼容方案请求 `/v1/models` 并携带 `x-api-key` 和 `anthropic-version`。仅响应 `data[].id` 中的模型会被注册：内置目录已有的模型继续采用其元数据，服务端新增模型使用保守的文本输入、128k 上下文、16k 输出和零成本元数据。

目录请求失败、返回非 JSON、缺少列表或列表为空时不再回退显示模板模型；模型目录会返回脱敏错误。Provider 设置目录本身不发出模型请求，避免无关设置刷新因网络错误不可用。测试覆盖两个 OpenAI 方案各自仅展示远端返回的模型，以及 Anthropic 方案查询失败时没有模型且 API Key 不会出现在错误中。
