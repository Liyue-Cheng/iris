## 背景

当前项目提示词直接存放在项目根 `AGENTS.md` 及已经存在的 `CLAUDE.md`、`GEMINI.md`
等入口文件的 `<iris-project>` 块中。Iris 需要在多个入口之间识别唯一正文、维护内存
baseline、处理外部修改和解决冲突，实际上形成了多个候选真相源。

已确认将 Iris 项目设置统一保存到 `.iris/settings.json`，并把项目提示词迁移到该文件。
入口 Markdown 中的 `<iris-project>` 此后只作为面向不同 agent 的派生镜像，不再参与
真相选举。

## 目标模型

```json
{
  "version": 1,
  "prompts": {
    "project": "项目级提示词正文"
  },
  "toolbar": {
    "actions": []
  }
}
```

* `.iris/settings.json` 是所有 Iris 项目级 App 设置的唯一真相源。

* `~/.iris/settings.json` 继续保存机器级设置，两者不能混用。

* `prompts.project` 保存项目提示词正文。

* `toolbar.actions` 等其他项目设置与提示词共用同一个有版本的项目设置文件。

* `<iris-software>` 的真相源仍是 App 内置模板，因为它是软件协议，不属于项目设置。

* SessionStart hook 仍只生成 workspace、焦点文档等动态上下文，不重复注入静态提示词。

## 单向投影

项目提示词采用单向投影，不再执行入口文件之间的双向锁相：

```text
.iris/settings.json / prompts.project
  -> AGENTS.md / <iris-project>
  -> 已存在的 CLAUDE.md / <iris-project>
  -> 已存在的其他 vendor 入口 / <iris-project>
```

1. 设置页保存项目提示词时，先带 expected revision 原子更新 `.iris/settings.json`。
2. JSON 提交成功后，把新正文投影到 `AGENTS.md` 和所有已经存在的 vendor 入口。
3. 运行期间新建已知 vendor 入口时，watcher 自动投影当前项目提示词。
4. vendor 入口被删除时不重新创建；`AGENTS.md` 是标准入口，可由 Iris 恢复。
5. 某个入口投影失败时，JSON 仍然是真相；设置页显示该入口待同步并允许重试。
6. 多窗口同时编辑时使用 revision 校验，过期窗口不得覆盖较新的项目设置。

## 外部修改

入口文件中的 `<iris-project>` 是派生结果。外部手工修改该块时，Iris 不能再静默把修改
导回 JSON，否则入口文件会重新成为真相源。

设置页检测到镜像漂移后提供两个显式动作：

* “从项目设置恢复”：使用 `.iris/settings.json` 覆盖入口镜像。

* “将此版本导入项目设置”：用户确认后，将所选正文写入 JSON，再重新投影所有入口。

入口文件块外的用户正文始终原样保留。投影只修改首个合法的 Iris 托管块；重复同名块
应作为错误报告，不能静默遗留多个版本。

## 旧项目迁移

首次打开没有 `.iris/settings.json` 的旧项目时执行一次性迁移：

* 所有入口都没有 `<iris-project>`：项目提示词初始化为空。

* 只有一个唯一非空正文：将正文导入 JSON，然后重新投影所有现有入口。

* 多个入口正文不同：保留所有文件并进入迁移冲突，不自动选择或覆盖。

* 用户选择一个版本后，原子创建 JSON，再以它为真相重新投影入口。

* JSON 一旦存在，后续打开项目不再扫描入口文件决定项目提示词真相。

现有 `.iris/styles.json` 是已经退出运行链路的遗留文件，不作为此次迁移来源。后续若恢复
项目级样式配置，也应迁入 `.iris/settings.json` 的独立字段。

## 运行约束

* Iris 打开项目时先读取和校验项目设置，再完成入口投影，之后才允许从 Iris 启动终端。

* 设置页保存必须区分“JSON 已提交”和“入口投影完成”，不能把部分投影误报为全部成功。

* 外部直接修改 JSON 后，Iris watcher 重新校验并投影入口；非法 JSON 不覆盖上一次磁盘
  内容，也不执行任何项目命令。

* Git 中的 JSON 是评审项目设置的主要文件；入口镜像可一同提交，供不通过 Iris 启动的
  agent 直接读取。

* 项目设置中的命令属于可执行内容，其机器级信任记录不能写进项目 JSON。
