看看现在的主页 UI 设计，你认为合适吗？还是你觉得太单调了？

## 调研范围修正（2026-09-02）

本 issue 讨论的是**已经打开项目后的默认工作台**，不是未绑定项目时的 `WelcomeView` 欢迎页。

当前“主页”涉及两个相邻但不一致的状态：

1. 项目打开完成后，`projectStore.handleOpened()` 将视图初始化为 `{ kind: 'doc', path: null }`。
2. 此时中间区域由 `DocView` 显示“请选择文档”，右侧由 `RightPane` 显示项目根的无会话启动台。
3. 用户点击左侧项目根节点后，视图才切换为 `{ kind: 'root' }`；右侧终端变为独占右侧区域，左侧项目根下显示根 hub 会话。

因此问题不是欢迎页是否单调，而是**项目默认落点是否应该就是一个有意设计的根 hub 页面**。

## 当前实现盘点

### 页面结构

* 外层是稳定的左右可调整布局：左侧 `LeftPane` 默认约 25%，右侧 `RightArea` 约 75%。
* 左侧是 Lens Tree：项目根、子工作区、`status`/`issue`/`report`/`misc` 类型分组，以及项目根或 workspace 下的终端会话。
* 普通文档视图是“编辑器 + 终端”分栏；根 hub 视图是“左侧文档树 + 右侧全宽终端”。
* 根节点的会话直接列在项目根名称下，不再单独增加“终端”分组；这是此前主页重设计已经确定的交互。

### 当前默认态

* 中间的 `DocView` 在没有选中文档时只有一行居中的空提示，没有项目名称、项目状态或下一步解释。
* 右侧启动台有项目根/文档上下文文案、Agent 启动按钮、可选的启动器搜索和帮助文字；没有会话时不会自动创建 PTY。
* 只有显式点击某个 Agent 或左侧项目根节点后，用户才会看到真正的根终端。
* 项目名同时出现在标题栏、左侧根节点和右侧启动台上下文中；信息并非缺失，而是分散且层级不统一。

### 已有优点

* 根 hub 的终端优先方向与产品定义一致：文档和 PTY 是两个第一公民，打开项目后可以直接进入真实终端。
* 左侧会话行带工作中/空闲/退出状态点，并支持切换和关闭；它确实承担了注意力调度面板的职责。
* 根 hub、子工作区 hub、文档终端使用不同会话锚点，切换不会混淆上下文；右区布局也保持稳定，不会因为视图切换重挂载终端。
* 启动台坚持“明确点击后才创建会话”，不会打开项目就偷偷运行 Agent，符合 detach 而非 dispatch 的产品原则。

## 主要问题（按优先级）

1. **默认状态语义不清（高）**：项目刚打开时仍是 `doc/path=null`，用户看到的是文档空态而不是项目主页；必须额外点击项目根，才能进入设计上真正的根 hub。
2. **中间区域浪费且缺少层次（高）**：`DocView` 的“请选择文档”既不是有用的项目摘要，也不是根 hub 的启动说明；在宽屏下会形成大面积无信息空白。
3. **首次行动路径不够集中（中）**：右侧启动台拥有启动 Agent 的按钮，左侧根节点又是进入根终端的入口，两个区域共同承担“开始工作”，主次关系不够明确。
4. **项目上下文反馈不足（中）**：默认页没有把项目根、当前 workspace、活跃 issue、未完成 Todo、Git 分支/变更等已有投影组织成一个可扫描的状态摘要。用户只能从左侧树和工具栏图标零散推断项目状态。
5. **空态视觉过于通用（低）**：`SquareTerminal + 两段小字 + 启动器按钮` 能完成操作，但品牌和项目记忆感弱；它更像一个控件占位，而不是项目工作台的入口。
6. **信息密度存在两端问题（低）**：左侧树可能很密，右侧无会话时却很空；当前页面没有在两者之间建立平衡的“项目级信息层”。

## 设计判断

主页应被定义为**项目根 hub 的工作台**，而不是另一个欢迎页或营销式 dashboard。它的首要任务是让用户快速恢复项目上下文并决定下一步：打开根终端、继续某个已有会话、进入待办/issue，或选择一篇文档。

建议保留现有三栏产品骨架、左侧 Lens Tree 和右侧真实终端，不增加独立导航栏，不把项目内容复制成第二棵树，也不引入与文件系统脱节的数据库式摘要。

## 建议方案

### P0：让默认落点和根 hub 统一

* 项目打开成功后直接进入 `{ kind: 'root' }`，而不是先进入 `{ kind: 'doc', path: null }`。
* 根 hub 没有会话时，右侧显示专门的“项目根启动台”；中间不再渲染“请选择文档”的文档空态。
* 点击左侧项目根节点、从集合视图返回、项目重载恢复时，都复用同一套 root hub 语义，避免出现多个看起来相似但行为不同的空页面。

### P0：重做无会话启动台的信息层级

右侧保持终端独占布局，但空态按以下顺序组织：

1. 项目名称和当前 workspace 上下文。
2. 一句明确的状态说明，例如“项目根没有活动会话”。
3. 唯一首要动作：选择一个启动器打开根终端。
4. 次要动作：查看 Todo、打开 issue 集合或选择文档；这些动作应调用已有入口，不新造业务。
5. 当已有根会话时，启动台消失，直接显示终端；会话切换仍通过顶部 banner 和左侧会话行完成。

不建议为每个 Agent 都做同等重量的彩色 CTA。Agent 清单是用户可配置的，按钮应保持统一的次级样式；实验性 Iris Agent 可保留显著标识，但不能改变根 hub 的信息结构。

### P1：增加轻量项目摘要，而不是复制 dashboard

可以在根 hub 无会话时增加一层紧凑摘要，数据只使用现有扫描投影：

* 当前项目根路径（可截断，支持复制/定位）。
* 各类型文档数量，至少突出活动 issue 和未完成 Todo。
* Git 当前分支及变更数量；Git 不可用时显示明确的无仓库状态。
* 最近一次扫描/项目打开错误只在确实存在时出现。

摘要应是无卡片或轻分隔的横向信息行，服务于决策，不应变成多张统计卡片。点击摘要项直接进入已有集合视图或 Git 面板。

### P1：改善左侧根节点的注意力层级

* 根节点名称、根会话和类型分组保持现有顺序；根会话仍直接挂在根节点下，不增加“终端”标题。
* 根节点当前选中时只突出根节点；具体会话选中时只突出会话行，保持现有“同一时刻只有一处高亮”的规则。
* 当根会话存在活动输出或等待输入状态时，左侧状态点应比普通文档状态更容易扫描，但不使用持续闪烁或大面积高亮。
* 项目根下没有文档时，类型分组的空态应低调显示，不要把一堆“空”文本推到主页视觉中心。

### P2：品牌与视觉表达

* 可以增加 Iris 的品牌识别，但应放在根 hub 的空态标题、状态点和终端启动台语气中，而不是加入欢迎页式插画或大面积装饰。
* 视觉基调继续沿用现有 Rose Pine/SaaS 主题 token、紧凑圆角和低对比边界；不要新增渐变、装饰性圆形、背景插画或与项目状态无关的动效。
* 无会话时允许有少量留白，让终端区域看起来是“等待开始的工作区”；但留白中必须有明确项目上下文，不能只显示通用“请选择文档”。

## 不建议的方向

* 不把项目默认页改成未打开项目时的欢迎页，也不在这里重复“打开项目文件夹/近期项目”。项目已经打开，用户需要的是继续工作。
* 不恢复项目 README 作为默认中栏内容。此前主页重设计已经明确删除 README 中栏，根视图终端独占是有意决策。
* 不增加类似 Linear/Notion 的多列 dashboard、活动时间线或自动生成的项目叙述。Iris 的状态真相来自文件和现有投影，主页不应凭空计算一套新的项目模型。
* 不自动启动 Agent 或 PTY。启动仍必须是用户明确动作。

## 实施顺序

1. 先修正项目打开、恢复和返回路径的默认视图，使其统一进入 root hub；补充 view 状态回归测试。
2. 再重做 `RightPane` 在 root hub 无会话时的空态层级，复用现有启动器和集合入口。
3. 根据人工验收结果决定是否加入紧凑项目摘要；摘要应先验证信息价值，再确定具体字段。
4. 最后调整文案、间距和主题对比度，不先做大范围装饰重绘。
