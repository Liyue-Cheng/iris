# Agent 后台任务日志弹窗

来源：2026-09-09 讨论「Task 要不要套用新的终端弹窗交互」。本 issue 只做设计，暂不执行。

## 目标

把 Agent 终端的新交互（标题行图标 → 独立弹窗、不跳转、不抢焦点）同构地用到后台 Task 上，
但不照抄终端实现——两者的输出真相源不同：

- Agent 终端：main 内存里的 headless xterm 镜像，可 `replay` 全量快照。
- 后台 Task：磁盘上 append-only 的原始 PTY 日志文件（`task-manager.ts` 的 `logPath`），只能按字节游标分页拉取。

## 现状盘点

- Task 已经是独立卡片（`session-model.ts` 的 `taskCard()`，id 为 `task-card:<taskId>`），不再并入信息检索卡片。
- 「查看日志」目前把 `task_get` 返回的**模型面向 JSON** 在 renderer 里反解出 `output`，再塞进卡片内联 `<pre>`——UI 依赖模型协议形状，属于耦合。
- 状态是活的：`AgentTaskManager.onChanged → IrisAgentSessionManager.onTaskChanged → commitAndEmit`，已通过 session 投影事件实时到达 renderer；日志内容没有推送，只能拉。
- `task_start` 不创建 terminal workspace，所以「超过阈值不跳转」对 Task 天然成立；要补的是「日志不塞进对话流」和「入口统一」。
- `IrisAgentTaskView` 没有 `cwd`，`taskSummary()` 与 `publicTask()` 都显式剥掉了它；弹窗头部要展示 cwd 就得补投影。
- 没有保留策略：`tasks.json` 和 `logs/<taskId>.log` 只增不减，菜单/列表入口会随使用时间膨胀。

## 交互设计

1. **标题行第二个图标**（任务图标）：仅当本 session 有任务时出现；存在 `queued/starting/running` 时常亮 + 数量徽章；单任务点击直接开弹窗，多任务展开菜单（活动任务在前，其余按创建时间倒序，超过 N 条给「查看全部」）。
2. **`AgentTaskDialog`**：与终端弹窗共用外壳（抽 `AgentWorkbenchDialog`：图标 + 标题 + 状态徽章 + 副标题 + 右侧动作 + 主体），差异只在头部副标题和主体。
   - 头部：任务标题、状态徽章（排队中 / 启动中 / 运行中 / 已完成 / 失败 / 已取消 / 已丢失）、短 `taskId`（等宽、可复制）、cwd、`outputBytes`。
   - 动作：取消（仅活动态）、在文件管理器中显示日志（复用 `shell.reveal-path`；日志在 userData 下是绝对路径）。
3. **卡片瘦身**：删掉内联「查看日志」和 `<pre>`，改成「打开任务」按钮（与终端的「查看终端输出」同构），保留取消按钮。
4. **取消要有过程态**：点击后按钮进入「取消中…」禁用态，直到状态落到 `canceled/failed/succeeded/lost`；`lost` 不显示取消。

## 日志视图（与终端最大的差异点）

- 主视图建议**只读 xterm**（复用 `BrowserXtermAdapter`，只调 `term.write()`，不接 replay/runtime/viewport）：任务日志本身就是 PTY 字节流，`\r` 进度条、ANSI、TUI 都能正确呈现，视觉也和终端弹窗一致。
- **增量拉取**：记录 `lastCursor`，弹窗打开且任务处于活动态时每 1 秒 `task_get(cursor)` 只追加新字节；进入终态后停止轮询。首屏取尾部 `maxBytes`（如 256 KB）。
- **向上翻历史**：xterm 不适合前插内容，采用「`maxBytes` 翻倍后整体重放」的策略（256 KB → 512 KB → …，上限如 4 MB）；超过上限只显示尾部并提示「日志过大，请在文件管理器中打开」。
- **降级**：`outputBytes` 超过阈值（如 8 MB）时不尝试全量渲染，只给尾部 + 明确提示。
- 关闭弹窗只停止轮询，不取消任务、不影响日志落盘。

## 协议与数据层配套

- 新增 renderer 面向的 typed IPC（如 `iris-agent:task-log`），返回 `{ task: IrisAgentTaskView, data, nextCursor, truncated }`；`task_get` 的 `outputText` 是给模型看的 JSON，UI 不应再反解它。
- `IrisAgentTaskView` 增加 `cwd`（项目相对路径）；`taskSummary()` / `publicTask()` 同步放开该字段。
- 抽一份状态标签单一真相源（如 `renderer/lib/agent-status.ts`：`taskStatusLabel` / `terminalStatusLabel` / 徽章色调），替换 `BackgroundTaskCard`、`terminalMenuState`、`TerminalStateBadge` 三处各自硬写的字符串映射。

## 与 Agent 语义的边界（不能混）

- 任务终态仍生成标准终态 Intent 进 mailbox；弹窗只影响「人怎么看」，不改调度、不进 provider 上下文。
- Stop / Pause 不隐式取消后台任务（保持现有语义）；弹窗里的取消是显式动作。
- `lost` 只投递一次终态 Intent 的语义不变；弹窗不得因为「看起来在跑」而重新 spawn。

## 保留与规模

- 建议给 Task 加保留策略（例如每 session 保留最近 20 条终态记录 + 日志 7 天），否则 `tasks.json` 和日志目录无界增长。这会删除日志文件，属于破坏性策略，需明确授权后再做。
- 菜单默认只展示活动任务 + 最近 N 条终态，其余走「查看全部」。

## 实施顺序与工作量粗估

1. 协议与投影：`cwd` 进投影 + typed `task-log` IPC + 状态标签单一源（约 0.5 天）。
2. `AgentWorkbenchDialog` 外壳抽取，终端弹窗回归验证（约 0.5 天）。
3. `AgentTaskDialog` 日志视图：增量轮询、尾部翻页、超限降级（约 1 天）。
4. 标题行任务图标 + 菜单 + 卡片瘦身（约 0.5 天）。
5. 测试：task-manager 分页/终态、投影 `cwd`、renderer 渲染快照（约 0.5 天）。

## 验收标准

- [ ] 命令超过阈值、任务状态变化都不引起界面跳转或抢焦点。
- [ ] 标题行任务图标：无任务时不出现；有活动任务时带数量徽章；多任务可从菜单选择。
- [ ] 弹窗能实时增量显示运行中任务的日志，也能回看已结束任务；终态后停止轮询。
- [ ] 日志过大时明确降级，不阻塞 UI，并给出去文件管理器打开的出口。
- [ ] 取消按钮有过程态；`lost` 不提供取消。
- [ ] 卡片不再内联渲染日志；UI 不再反解 `task_get` 的模型 JSON。
