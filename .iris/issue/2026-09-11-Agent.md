## 实现方案（2026-09-11）

### 1. 目标与原则

保留卡片作为内部数据单元，只改变 Agent 内容流的视觉和交互。新界面采用连续对话时间线：用户和 Agent 消息是主内容，工具操作以轻量内联条目呈现。

- 用户输入靠右，Agent 回复靠左纯文本。
- 操作默认收敛，点击后查看详情。
- 保留现有卡片 ID、时间戳、父子关系、工具类型和执行状态，不改动编排、持久化和恢复逻辑。

### 2. 时间线节点

渲染层把卡片映射为 `UserMessage`、`AgentMessage`、`ActivityGroup` 和 `ActionItem`。按原始时间戳排序，相同时间以卡片 ID 稳定排序。典型顺序为：用户消息、Agent 流式文本、操作组、终端/长程任务、最终回复。

### 3. 消息样式

用户消息使用右侧气泡，最大宽度 70%，窄屏为 85%，长文本自然换行。Agent 回复使用左对齐纯文本，不加卡片边框、阴影或大背景，支持 Markdown、代码块、表格和链接。流式输出持续更新同一个消息节点；生成中显示低干扰光标或脉冲指示器。

### 4. 信息获取与文件操作

信息获取、文件读取、文件修改、搜索等相邻事件合并为 `ActivityGroup`。遇到新用户消息、Agent 大段文本、终端操作或长程任务时结束当前组。每组默认最多显示 5 条：前 4 条完整显示，第 5 条半透明并带渐隐遮罩，同时显示“还有 N 项操作”入口；点击后展开全部。失败条目始终保留清晰的错误状态。

文件条目显示状态、文件名/相对路径、创建/修改/删除/重命名类型和可选变更摘要；点击后打开现有 diff 或文件详情。

### 5. 终端操作与长程任务

终端操作和长程任务复用相近的紧凑 `ActionItem` 组件，但保留各自详情数据。左侧为固定宽度状态指示器，右侧内容最多两行。

- 终端：第一行显示命令，第二行显示工作目录、退出码、耗时或简短结果。命令允许占两行；超过两行时在视觉层截断并显示省略号，完整命令和日志保留在详情中。
- 长程任务：第一行显示任务名称或摘要，第二行显示进度、阶段、耗时或下一步信息；超过两行同样省略。
- 状态统一支持排队、运行中、已完成、失败、已取消，并同时使用图标、颜色和文字。
- 点击整条条目打开详情弹窗。终端弹窗显示完整命令、标准输出/错误和执行时间；长程任务弹窗显示目标、阶段、进度、事件时间线、相关文件、终端记录和错误信息。
- 运行中任务按后端能力提供取消；失败项提供重试，重试创建新卡片，不覆盖历史记录。

### 6. Fork 处理

移除所有可见 Fork 按钮、快捷键和右键菜单入口；保留底层字段、接口和事件类型，以兼容历史数据并支持未来重新设计。

### 7. 组件与数据实现

在现有卡片渲染入口增加视图模型层：`buildTimeline(cards)` 负责排序和节点生成，`mergeActivities(cards)` 负责操作合并，`getActionPreview(card)` 负责两行摘要，`getActionDetail(card)` 负责弹窗数据。主要视觉组件为 `TimelineMessage`、`ActivityGroup`、`ActionItem` 和 `ActionDetailDialog`。截断、虚化和折叠只发生在渲染层，禁止修改原始命令、日志和路径。

未知卡片类型降级为通用 `ActionItem`，历史会话无需迁移数据即可使用新渲染器。

### 8. 响应式与无障碍

桌面端保持舒适阅读宽度；小于 640px 时用户气泡宽度提升到 85%，操作条目允许命令自然换行。所有条目支持键盘聚焦、Enter/Space 打开详情，状态图标提供文本标签和 `aria-label`。虚化条目必须同时显示文字入口，不能只依赖透明度或颜色。

### 9. 实施顺序与验收

1. 盘点卡片类型、状态枚举、事件流和 Fork 入口。
2. 增加时间线视图模型，实现用户气泡和 Agent Markdown 流式消息。
3. 实现操作合并、五条预览、第五条虚化和展开。
4. 实现终端/长程任务两行条目及统一详情弹窗。
5. 隐藏 Fork 可见入口，接入响应式和无障碍属性。
6. 验收消息左右对齐、操作合并与展开、两行截断、弹窗详情、状态同步、历史恢复、窄屏和键盘操作。
