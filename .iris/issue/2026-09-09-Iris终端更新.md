我们现在换一个新的交互逻辑：

取消iris agent的terminal标签页系统，然后这样做：

1：终端没有在预定秒数结束的时候，不做任何跳转

2：然后标题右边给一个可以点击的命令行图标，点击之后，弹出一个单独的弹窗显示这个终端（画的好看一点）

然后是运行命令中的查看终端输出也用这个逻辑

标签页系统完全撤销

## 方案设计（2026-09-09）

### 现状与根因

- `IrisAgentView` 顶部有一条 `对话 | 终端` 标签栏，`selectedTerminalId` 直接替换整个面板内容。
- 命令跑满 `displayThresholdMs`（默认 3 秒）后 main 侧发 `shown`，投影出 `revealed: true` 的终端；renderer 里一个 `useEffect` 看到新增的 revealed 终端就 `setSelectedTerminalId`，于是界面自动跳走。
- 退出后的 Agent 终端无法回看：`releaseTerminal` 在每次 terminal 工具结算时 `dispose()` 并 `terminals.delete()`，随后 `replayTerminal` 直接抛 “output is no longer persisted”，renderer 降级成空白终端。

### 交互设计

1. **不跳转**：删除“新增 revealed 终端就自动选中”的 effect。命令超过阈值后界面停留在对话区，只有卡片状态和标题行图标变化。
2. **标题行图标**：`Iris Agent` 标题右侧放一个命令行图标按钮，作为 Agent 内部终端的唯一入口。
   - 没有任何 revealed 终端时不显示。
   - 有终端在运行时常亮/呼吸，提示“有活动终端”，但不改变焦点和滚动位置。
   - 只有一个终端时点击直接打开弹窗；有多个时点击展开菜单（命令、状态），选择后打开弹窗。
3. **终端弹窗**：新建 `AgentTerminalDialog`，复用现有 xterm 生命周期（replay / runtime / viewport / 右键菜单 / Ctrl+F 搜索）。
   - 头部：终端图标、命令（等宽、截断）、状态徽章（运行中 / 已退出 · 退出码 N / 超时 / 已取消）、cwd；右上角关闭。
   - 主体：xterm 铺满，尺寸 `w-[min(1100px,92vw)] h-[min(760px,78vh)]`，`p-0`、圆角、溢出裁剪。
   - Esc / 点击遮罩 / 关闭按钮关闭；关闭只是卸载视图，PTY 与镜像仍在 main 侧存活，下次打开重新 replay。
4. **卡片入口复用同一弹窗**：执行命令卡片的“查看终端输出”和检索失败行的终端图标都改成打开弹窗，不再切换面板。
5. **标签页系统撤销**：删除标签栏、`hiddenTerminalIds`、`selectedTerminalId` 面板切换状态和 `terminalTitle` 标签逻辑。

### main 侧配套：让弹窗在命令结束后仍然可读

- `releaseTerminal` 不再立即 `dispose + delete`，而是保留已结束的终端记录（镜像仍可 replay），并按 session 限制保留数量（默认 6 个，超出淘汰最旧的）。
- 新增 `releaseSessionTerminals`：关闭 session / 关闭项目时真正 dispose 并删除全部终端；Stop / 暂停仍只 `abortSessionTerminals`，不丢掉已结束终端的镜像。
- `shutdown` 同时 dispose 运行中和已保留的终端。

### 验收

- [ ] 命令超过 3 秒后界面不发生跳转、焦点和滚动位置不变。
- [ ] 标题右侧图标在无终端时不出现；运行中带活动指示；多个终端可从菜单选择。
- [ ] 弹窗能实时显示运行中的终端，也能回看已结束终端；Esc / 遮罩 / 关闭按钮均可关闭。
- [ ] 执行命令卡片的“查看终端输出”打开同一个弹窗，不再切换面板。
- [ ] 标签栏、隐藏终端集合和面板切换状态已从代码中移除。
- [ ] 关闭 session / 关闭项目 / 应用退出后不再保留终端镜像。

## 项目根多 agent 的终端隔离核查（2026-09-09）

问题：项目根同时开多个不同 agent（Claude Code / Codex / 自定义 launcher / Iris Agent），终端呈现有没有好好隔离？

### 结论：隔离是结构性的，六层都成立

1. **进程/PTY 层**：`createConfiguredSession` 每次 spawn 一个新 PTY，`randomUUID()` 作 sessionId；`sessions: Map<sessionId, SessionRecord>`，每个 record 各自持有 pty、headless mirror、output pump、OSC/协议解析器、activity 状态机和 flight recorder（`terminal-session-manager.ts`）。
2. **输出路由**：`handlePtyData` 只写自己的 `managed.output` 与 `managed.mirror`；`sessionOutput` 载荷带 `sessionId` + scope，renderer 订阅和 main 的 quiet-waiter 都按 sessionId 过滤（`terminal-session-manager.ts:831`、`:886`）。
3. **渲染层**：`ProjectedSessionView` 渲染 `<TerminalView key={projection.id}>`，同一时刻只有一个 xterm 在挂载；切换会话是卸载 + 重放，不存在两个 agent 共用一个 xterm 缓冲。
4. **环境层**：`FOCUS_DOC` 与 `IRIS_WORKSPACE_PATH` 互斥且显式 `delete`，根 hub 会话不会继承上一个文档会话的焦点（`terminal-session-manager.ts:288-296`；`terminal-session-manager.test.ts:194-225` 四个用例覆盖，含“stale FOCUS_DOC 被清掉”）。
5. **选择/几何**：`sessionViewStore` 按 `scope.root + generation + anchorKey` 隔离；`lastTerminalDims` 按 projectRoot + 布局域隔离（`session-store.ts`）。
6. **多窗口**：每个窗口有自己的 manager 实例和 broadcasts，事件不跨窗口（`app-main.ts:133`、`ipc.ts:1442`）。

### 三处真实缺口（不是串流，是这次改动放大/暴露的）

**A. Agent 终端输出没有 attach 门控、合批和背压（最值得修）**

- 普通终端：`ipc.ts:1495` 用 `shouldForwardTerminalOutput(attachment, e)` 做单挂载门控，main 侧 `attachOutput` 还会主动关掉其它会话的投递；输出走 `TerminalOutputPump`（合批 + seq + ack），并有 flow controller 在高水位 pause/resume PTY。
- Agent 终端：协议里没有 attach/detach/ack（`protocol.ts:162-164` 只有 replay/input/resize），`session-manager.ts:1602` 每个 PTY chunk 直接 `emit('terminalOutput')`，`ipc.ts:1506` 无条件 send；renderer 侧 `IrisAgentTerminalTransport.acknowledge()` 是空实现。
- 后果：命令跑起来后，即使没有任何弹窗在看，每个 chunk 仍要过一次 IPC + base64 序列化；renderer 落队时 main 没有背压手段。新交互让“没人看终端”成为常态，这个问题从偶发变成默认路径。
- 修法：给 Agent 终端加 attach/detach（按 terminalId，不必是全局单挂载），未挂载时只写 mirror 和日志文件、跳过 IPC；顺带把 chunk 合批（复用 output pump 的思路），并让 renderer 返回 ack。

**B. 长命令不再被自动 resize，会停在 80x24**

- `command-pty.ts:62`、`:102`：PTY 和 mirror 都以 80x24 起步。
- 旧行为：3 秒后标签自动打开 → `fit()` → resize 到面板宽度（约 120 列），TUI/表格按面板宽度排版。
- 新行为：不跳转就不 fit，命令一直按 80 列输出，直到用户打开弹窗才 resize（运行中的程序会被重排一次）。
- 建议：spawn 时用右栏已知尺寸（`getLastTerminalDims` 的 root-hub 桶）作为初始 cols/rows，让输出从 t=0 就是最终宽度，同时消掉弹窗打开时的那次 reflow。

**C. 同一 anchor 下的同名会话缺乏稳定判别**

- 根目录连开两个同一 launcher 的会话：`title = terminalTitle ?? displayName`，在 OSC 标题相同（或尚未到达）时，左栏两行文字完全一样；右栏下拉也只靠 `1/2` 计数区分。
- cwd 在根 hub 下都是 projectRoot，不能当判别；建议补创建时间或短 session id。

### 已核查、确认不需要改的两点

- **已结束终端的回放宽度**：settled 后 `resize()` 直接返回（`command-pty.ts`），mirror 保持退出时的尺寸；实测 headless xterm 的 `resize` 不做 reflow，所以这是忠实回放而不是错位。
- **`attachOutput` 的全域单挂载**（`terminal-session-manager.ts:944`）：同时只挂一个普通终端是当前 UI 的硬约束，而 Agent 弹窗走的是另一条通路（attach 为空实现），两者互不抢流。但将来若支持多个普通终端同屏，这条会静默掐掉另一个的流。

## 缺口 A 实现结果（2026-09-09）

范围：只修缺口 A（门控 + 合批 + 背压）。B、C 未动。

### 三条链路的同构对照

| | 普通终端 | Agent 终端（本次之前） | Agent 终端（现在） |
| --- | --- | --- | --- |
| 挂载门控 | `shouldForwardTerminalOutput` + `attachOutput` | 无 | 每 terminalId 一个 attachment，未挂载不发 IPC |
| 合批 | `TerminalOutputPump`（8ms + seq） | 每个 chunk 直接 emit | 同一个 batcher，8ms |
| 背压 | flow controller → PTY pause/resume | 无 | 同一套 flow controller → PTY pause/resume |
| 消费端 ack | `SESSION_OUTPUT_ACK` | 空实现 | `IRIS_AGENT_TERMINAL_ACK` |

### 改动

- `src/main/terminal/output-pump.ts`
  - 抽出泛型 `TerminalOutputBatcher<P>`（合批、seq、in-flight、ack、flow 回调），`TerminalOutputPump` 变成它的薄封装，普通终端行为与测试不变。
  - 序列语义明确为**投递序号**（不是字节偏移）：`flush()` 后 `replayBoundarySeq` 即快照边界。
- `src/main/agent/command-pty.ts`
  - `output` 事件改为携带原始 `bytes: Buffer`，不再在 PTY 层 base64（一次编码推迟到真正要发 IPC 时）。
  - 新增 `mirrorBackpressure` 选项与内部 `TerminalFlowController`：mirror 积压和 renderer 未 ack 都会 pause PTY，两者都解除才 resume；`setOutputBlocked('renderer', …)` 由会话管理器驱动。
  - `replay()` 不再返回序列（序列归 batcher 所有）。
- `src/main/agent/session-manager.ts`
  - 每个终端持有 batcher，初始 `deliveryEnabled = false`；`handleTerminalEvent` 只 `enqueue`。
  - 新增 `attachTerminalOutput` / `detachTerminalOutput` / `acknowledgeTerminalOutput`（同步校验 scope 与 session 归属，不进 session 变更队列）。
  - `replayTerminal` 在插入 mirror fence **之前、同一 tick** 内 `flush()` 并冻结边界，避免 fence 等待期间到达的 chunk 被当陈旧数据丢掉。
  - 结算时 `dispose({ flush: true })` 把尾巴送给仍挂着的弹窗；关闭 session / 关闭项目 / 退出释放 batcher。
- `src/shared/protocol.ts`、`src/main/ipc.ts`：新增 `iris-agent:terminal-attach|detach|ack` 三个通道与处理器。
- `src/shared/types.ts`：`IrisAgentTerminalOutputPayload.cursor` → `seq`，`IrisAgentTerminalReplay.cursor` → `seq`（它们从来只用做去重序列，改名以免被误读成字节偏移）。
- `src/renderer/terminal/terminal-transport.ts`：`attach` / `detach` / `acknowledge` 变成真实 IPC，每个挂载点一个 `attachmentId`。
- `src/main/agent/tool-host.ts`：前台终端开启 `mirrorBackpressure`；`task-manager.ts` 不动，后台任务的 mirror 永远不会暂停。

### 效果

- 没有弹窗时：每个 chunk 只写 headless mirror 和日志文件，不 base64、不发 IPC；下次打开弹窗靠 mirror 快照完整回放，没有丢字节。
- 弹窗打开但 renderer 落队时：未 ack 字节超过 384 KB 就 pause PTY，回落到 96 KB 以下 resume——与普通终端同一套阈值。
- 挂载是**按 terminalId**而不是窗口单挂载，所以不同 Agent 终端的弹窗互不影响；重新挂载会换新的 attachmentId，旧视图的迟到 detach 不会误关新视图。

### 已知取舍

- 被 pause 的 PTY 仍在计入该次 `terminal` 调用的硬 `timeout`。pause 窗口由 ack 往返决定（毫秒级），但极端情况下会在 renderer 长时间卡顿时表现为更早超时；这是“宁可让生产者等消费者”的取舍，与普通终端一致。
- 若 detach 的 IPC 丢失且窗口仍活着，投递会保持开启直到命令超时；不会无限期遗留（终态/关闭/退出都会释放）。
