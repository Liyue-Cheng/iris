现在我们的状态机已经有了很多状态，但是状态之间的视觉效果风格还远没有统一，然后你需要做的事情就是给我一个统一方案。要是目前颜色表中没有足够多的颜色，你其实是可以稍微扩展一些的

## 2026-08-11 统一方案

### 结论

所有文档状态统一使用同一种无边框 `soft pill` 徽章：浅色语义背景、左侧实心圆点和状态原文。状态之间只通过语义色与文字区分，不再用 `solid`、`outline`、`dot` 等不同结构表达状态。交互入口只额外显示下拉箭头和焦点环，不改变徽章本体。

当前颜色表已经覆盖中性、信息、强调、危险、警告和成功六类语义，不需要为了凑齐状态数量增加装饰性色相。实现时应增加一层稳定的状态语义 token，避免 `StatusBadge` 继续直接依赖 Rose Pine 的历史颜色名；只有现有主题中某个语义色经对比度验证不合格时，才调整该主题对应 token。

### 现状与问题

当前 `StatusBadge` 虽然已经是各入口共享的组件，但九个官方状态混用了四种模板：

* `Todo`、`In Progress`、`In Review`、`Blocked`、`Active` 使用 `soft`；
* `On Hold`、`Canceled` 使用 `outline`；
* `Done` 使用 `solid`；
* `Backlog` 使用 `dot`。

这让填充强度、边界、圆点和文字颜色同时变化，结构差异压过了状态语义。`In Review` 与 `On Hold` 还共用金色，只能依靠不同模板区分；同一个状态在可编辑与只读场景中也容易因为箭头、尺寸和容器样式显得像不同组件。

### 统一视觉语法

* 形态：全部为无边框圆角胶囊，统一采用轻量填充；每个状态都带 6px 实心圆点。
* 层级：状态徽章整体保持低到中等强调，不使用整块高饱和实色。`Done` 不再成为页面上最重的元素，`Blocked` 通过危险色获得足够注意力。
* 文字：继续逐字显示磁盘中的 `status:` 值，不翻译、不缩写。文字色由语义色与当前主题前景色混合得到，避免浅色主题中的黄色、青色文字对比度不足。
* 尺寸：保留 `md` 和 `sm` 两档，但固定高度、圆点、间距和水平内边距；尺寸变化只影响整体密度，不改变结构。`md` 高 22px、12px 字号，`sm` 高 19px、11px 字号。
* 交互：只有可编辑徽章显示下拉箭头；hover 使用同色背景的小幅加深，键盘 focus 使用外部焦点环。hover、focus、菜单展开均不得改变徽章尺寸。
* 截断：自由状态和长状态沿用最大宽度与省略号，截断时提供完整值 tooltip。未知状态仍合法，不影响编辑和写盘。

### 状态配色

| 文档类型 | 状态 | 语义色 | 设计含义 |
| --- | --- | --- | --- |
| issue | `Todo` | Neutral / 中性灰 | 尚未开始，不抢占注意力 |
| issue | `In Progress` | Info / 青蓝 | 正在流动和执行 |
| issue | `In Review` | Accent / 紫 | 已离开执行阶段，等待判断 |
| issue | `Blocked` | Danger / 红 | 明确异常，需要注意 |
| issue | `On Hold` | Warning / 琥珀 | 尚未解决但主动退出行动队列 |
| issue | `Done` | Success / 绿 | 已完成 |
| issue | `Canceled` | Neutral / 中性灰 | 已终止并降噪，由文字与所在分组区别于 `Todo` |
| report | `Active` | Info / 青蓝 | 当前报告 |
| report | `Backlog` | Neutral / 中性灰 | 已退出活动视图 |
| 任意 | 未知值 | Neutral / 中性灰 | 安全降级，不赋予不存在的产品语义 |

`Todo`、`Canceled`、`Backlog` 和未知值共用中性色是有意的语义分组：它们都不应靠高饱和色争夺注意力，具体含义由始终可见的原文表达。颜色不是唯一信息通道，因此不必为每个状态强行分配唯一色相。

建议新增的只是语义别名，而不是新颜色：

| 状态 token | 现有主题色来源 |
| --- | --- |
| `--status-neutral` | `--rp-muted` |
| `--status-progress` | `--rp-foam` |
| `--status-review` | `--rp-iris` |
| `--status-blocked` | `--rp-love` |
| `--status-hold` | `--rp-gold` |
| `--status-done` | `--rp-pine` |

### 实施边界

* `src/renderer/components/ui/status-badge.tsx` 继续作为官方状态到视觉语义的唯一映射点，但映射结果收敛为语义色，不再为不同状态选择不同结构模板。
* `src/renderer/components/ui/badge.tsx` 保留通用模板能力供标签或其他场景使用；状态徽章固定走统一结构，避免影响非状态组件。
* 在主题层定义 `--status-*` 别名，并让前景、背景、圆点和交互态从同一语义色派生。不要在左栏、Issue 面板、报告时间线或文档头部分别写颜色 class。
* 左栏、Issue 面板只读单元格、状态编辑菜单、文档头部和报告时间线全部继续复用 `StatusBadge`；容器只负责尺寸与可编辑性。
* 不改变状态机、状态存盘值、活动/解决分类、终端收尾行为、排序规则或 i18n 约定，也不恢复项目级样式配置。

### 实施与验收清单

* [x] 将九个官方状态和未知值统一为同一种 `soft pill` 结构，并把 `In Review` 从 Warning/金色迁到 Accent/紫色。
* [x] 增加 `--status-*` 语义 token，统一派生文字、背景、圆点、hover 和 focus 样式。
* [x] 固定 `md`、`sm` 两档尺寸，确保下拉箭头、长文本和状态切换不会引发布局跳动。
* [x] 更新徽章语义测试，覆盖全部官方状态、未知值降级以及“所有状态结构一致”的约束。
* [ ] 在深色与浅色主题下检查正文文字对比度；目标为 WCAG AA 4.5:1，圆点和色相不作为唯一信息通道。
* [ ] 在左栏、Issue 面板的显示与编辑态、文档头部、状态菜单和 Report 时间线逐项验收，确认同一状态跨入口视觉一致。
* [ ] 检查 `In Review` / `On Hold`、`Blocked` / `Canceled`、`Active` / `Backlog` 能在常见色觉差异下通过文字和位置可靠辨认。

### 非目标

本轮不统一 Git 状态、终端会话圆点、设置诊断标签或自由 label 的视觉样式。它们表达的是不同领域语义，强行共用文档状态映射反而会再次混淆。

## 2026-08-11 第一版实现

九个官方状态与未知值已经收敛为统一的无边框 `soft pill`。徽章固定为 22px 和 19px 两档高度，保留左侧圆点、原始状态文字和可编辑场景的下拉箭头；hover 只加深背景，键盘 focus 使用不占布局的外部轮廓。

主题层新增六个 `--status-*` 语义别名。`In Review` 使用 Accent/紫色，`On Hold` 使用 Warning/琥珀色，`Blocked` 使用 Danger/红色，`Done` 使用 Success/绿色；低注意力状态与未知值统一使用中性灰。通用 `Badge` 的其他模板仍保留，不影响非文档状态场景。

根据第一次反馈，原方案中的 1px 同色边框已经移除；通用 `outline` 模板改用不占尺寸的内描边。

验证结果：完整 Vitest 通过，共 32 个测试文件、213 项测试；`npm run typecheck` 和 `npm run build` 通过。视觉与主题对比度验收仍保留在上方清单，等待实际界面确认。
