正确的行为，应该是拖进去之后粘贴路径，但是现在显然完全没有实现这一点，经常出现拖进去之后没有反应的情况，你现在把这条链路排查一遍

## 2026-08-09 排查记录

问题已确认，且可视化模式与源码模式各有一条不同的错误链路。

### 当前链路

1. `DocView` 只负责切换 `CrepeEditor` 与 `SourceEditor`，编辑器容器没有应用层的
   `dragover` / `drop` 处理，也没有统一的“系统文件转路径”能力。
2. 可视化模式落入 Crepe 自带的 Milkdown upload plugin。该插件会接管所有带
   `DataTransfer.files` 的 drop，但 Crepe 的 uploader 随后只筛选 MIME 为 image 的文件。
   因此图片会走现有 `importAsset()` 链路并插入受管图片，非图片则返回空节点列表；事件已经
   被判定为处理完成，最终表现为静默无反应。
3. 源码模式落入 CodeMirror 默认 drop 行为。CodeMirror 对文件调用 `FileReader.readAsText()`，
   文本文件会错误地把全文插入编辑器；包含二进制控制字节的文件会被过滤，最终静默无反应。
4. 终端已有一份正确方向的参照实现：识别 `types` 中的 `Files`，读取 Electron 文件绝对路径后
   再插入终端。但它直接读取 Electron 31 的非标准 `File.path`，能力没有抽到 preload，也没有
   被 Markdown 编辑器复用。

“经常没有反应”因此不是偶现：非图片拖入可视化模式、二进制文件拖入源码模式都会稳定复现；
文本文件拖入源码模式还存在插入文件内容而非路径的隐性错误。

### 修复边界

系统文件 drop 应在两种编辑模式的默认处理器之前被 Iris 显式接管；clipboard 图片粘贴仍保留
现有资产导入语义，避免影响 companion assets 链路。路径解析应通过 preload 暴露
`webUtils.getPathForFile(file)`，不再新增对 renderer 中非标准 `File.path` 的依赖。两种编辑器
分别使用自己的坐标到文档位置 API，在实际 drop 位置插入纯文本路径，并支持一次拖入多个文件。

- [x] 在 preload 提供统一、安全的系统文件路径解析能力，并让终端与 Markdown 编辑器复用。
- [x] 可视化模式在 Milkdown upload plugin 之前接管系统文件 drop，在落点插入路径。
- [x] 源码模式覆盖 CodeMirror 默认的“读取文件全文”行为，在落点插入路径。
- [x] 明确并测试多文件路径之间的分隔规则，以及含空格、中文和换行边界的文件名。
- [ ] 回归确认剪贴板图片仍导入 companion assets，编辑器内部块拖拽不受影响。
- [ ] 分别在可视化模式和源码模式人工验证文本文件、图片、二进制文件及多文件拖入。

## 2026-08-09 实现记录

拖放治理已收口到 `DocView` 的 capture 阶段。Iris 文档自定义 MIME 与 OS `Files` 在这里
统一解析为有序路径列表；单文件原样插入，多文件每行一个。普通文本、URL 和编辑器内部拖动
不进入该分支。已识别的文件 drop 会在到达 Milkdown upload plugin 或 CodeMirror FileReader
之前停止传播，因此系统图片也插入路径；clipboard paste 没有被该治理层接管。

preload 通过 Electron `webUtils.getPathForFile()` 提供受限同步桥接，renderer 不再读取非标准
`File.path`。Crepe 与 CodeMirror 各自只注册一个“坐标转文档位置并插入文本”的适配器，插入
继续触发现有 dirty、撤销和自动保存链路。路径解析失败或编辑器尚未 ready 时，文档区域显示
本地化错误，不会回退到上游默认文件处理。

自动化验证通过：新增 5 项拖放协议测试；全量 Vitest 共 28 个测试文件、179 项测试全部通过；
TypeScript 三进程检查、生产构建和 Electron 启动冒烟均通过。

## 2026-08-09 drop indicator 生命周期回归

首版统一治理在 capture 阶段允许 `dragover` 继续传播，却对最终 `drop` 调用了
`stopPropagation()`。Milkdown 与 CodeMirror 因而能够创建悬浮落点横线，却收不到用于清理
横线的 `drop` 事件；OS 文件松手后也不保证再产生目标内的 `dragleave`，横线会永久残留。

治理函数现只调用 `preventDefault()`，用于取消 Milkdown 图片上传和 CodeMirror 文件全文读取；
原始 `drop` 仍传播到两种编辑器的 lifecycle observer，使其正常清除 drop indicator。新增回归
测试断言路径插入成功、默认行为被取消且 `stopPropagation()` 未被调用。全量 Vitest 当前共
29 个测试文件、186 项测试全部通过，TypeScript 三进程检查与生产构建通过。
