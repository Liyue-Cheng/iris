2026-09-04 范围更正：原生 `title` 不作为悬浮提示

用户澄清本 issue 的目标是统一“悬浮弹出的信息”，不是统一 hover 变色。
上文关于视觉 hover 状态的方案不再是本 issue 的实施范围；上文“截断路径或文本
可保留原生 `title`”的判断也作废。

### 设计决定

在 Iris 这个已有全局 Radix `TooltipProvider` 的 Electron 应用中，用户可见的
悬浮信息不使用原生 HTML `title` 属性。原因是：

* 延迟、位置、换行、宽度和碰撞避让由 Chromium 控制，无法与 Iris 的 400ms
  延迟、颜色、字体、圆角和动效保持一致。

* 不能稳定覆盖键盘聚焦和触摸输入，也不能靠 `title` 同时承担可访问名称；
  图标按钮仍需要独立的 `aria-label`。

* 无法统一表达快捷键、较长路径、多行说明或状态信息，也无法在需要时
  精确判断“只有文本被截断才显示”。

* 原生提示和项目 Tooltip 并存时，同一应用会出现两套不同的外观和出现节奏。

原生 `title` 在没有 JavaScript、没有统一组件层的简单静态页面上可以作为低成本
渐进增强，但这个前提不适用于 Iris。因此它在本项目中不比项目 Tooltip 更合理。

下列同名用法不在清理范围内，因为它们不会生成原生悬浮提示：

* HTML 文档的 `<title>` 元素。

* `SettingGroup title={...}`、`CardFrame title={...}` 等被组件渲染为页面可见标题的
  React 属性。

### 更正后的实施原则

* 无文字图标命令使用项目 Tooltip，触发器保留 `aria-label`。

* 路径、标题和其他截断文本使用专用的 overflow tooltip，只在
  `scrollWidth > clientWidth` 时打开，不再用原生 `title`。

* 可见文字与提示完全重复、且没有截断风险时，直接删除提示，不必为清零
  `title` 而制造冗余 Tooltip。

* 快捷键、错误原因、完整路径等补充信息使用项目 Tooltip 的结构化内容。

* Renderer 内最终不再向 DOM 传递用于悬浮提示的 `title` 属性，并增加静态
  检查防止回归。

### 更正后的验收项

* [x] 将实际传递到 DOM 的原生 `title` 悬浮提示清零。

* [x] 所有图标命令通过 Iris Tooltip 显示信息，并有独立 `aria-label`。

* [x] 截断文本仅在实际溢出时显示 Iris Tooltip。

* [x] 项目内不再出现原生提示与 Iris Tooltip 的双轨体验。

* [x] 静态检查能够拦截新增的 DOM `title` 悬浮提示，但不误报可见标题组件的
  `title` 属性。

### 实施结果

Renderer 内原生 `title` 属性已统一替换为无障碍名称，保留 `SettingGroup` 等可见标题组件的 `title` 属性。新增 `OverflowTooltip`，基于实际内容溢出状态显示 Radix Tooltip，并加入 `no-native-title.test.ts` 防止回归。
