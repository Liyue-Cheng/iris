# 默认提示词与提示词管理

本文记录当前代码实际使用的默认提示词、它们落在磁盘上的位置，以及 Iris 如何初始化、注入、检查和升级它们。

当前协议版本为 `2`（issue/report 写入纪律对调、frontmatter schema 与 todo 收集机制进入软件层）。项目层仍然使用 `.iris/CONVENTIONS.md`；把项目层搬进 `AGENTS.md` 的 `<iris-project>` 块，是 issue 中已经决定但尚未实现的后续改动。

## 一览

当前有四类会进入 agent 上下文的内容：

* **软件层**：正文来自 `SOFTWARE_PROMPT_TEMPLATE`，写入项目根的 `AGENTS.md`，以及已经存在的 vendor 入口，包在 `<iris-software>` 中，由 Iris 维护。

* **项目层**：正文来自 `CONSTITUTION_TEMPLATE`，写入项目根的 `.iris/CONVENTIONS.md`，包在 `<iris-project>` 中，初始化后由项目作者维护。

* **用户层**：正文来自 `MACHINE_CONVENTIONS_TEMPLATE`，写入 `~/.iris/CONVENTIONS.md`，包在 `<iris-user>` 中，由用户维护。

* **当前文档**：由环境变量 `FOCUS_DOC` 指定的聚焦文档，包在 `<iris-focus>` 中，属于当前用户/agent 的工作上下文，不是固定模板。

还有一个不直接注入的种子文件：`~/.iris/templates/CONVENTIONS.md`。它是用户为新项目准备的项目层默认；存在时优先于 Iris 内置的 `CONSTITUTION_TEMPLATE`。

## 默认提示词

### 软件层：`SOFTWARE_PROMPT_TEMPLATE`

代码位置：`src/main/iris-templates.ts`。

这是 Iris 自己拥有的通用规则，正文写入入口文件的 `<iris-software>` 块。内容包括：

* Iris 项目的基本定义：PM 文档都是 `.iris/` 下的 Markdown，文件夹名称决定文档类型。

* 四类目录的职责与写入纪律：`status/` 是镜像（自由重写，保真）、`issue/` 是工作记录（正文倾向追加，未经要求不改写已有内容）、`report/` 是有日期的交付物（新鲜期自由修改，过时另写新篇）、`misc/` 是人的草稿区。

* **App 解析的 frontmatter schema**（“What the app parses”）：`title:`、`status:`、`labels:`、`reflects:` 四个硬键的用途，新建 issue 的骨架范例，以及 todo 收集机制——App 会把 `.iris/` 下所有 GFM task checkbox 收进待办面板，待人处理的事项必须写成 checkbox。

* 会话上下文如何到达 agent：`FOCUS_DOC`、SessionStart hook，以及 `<iris-software>`、`<iris-project>`、`<iris-user>`、`<iris-focus>` 四类标签。

* 兜底规则：hook 已经注入的内容不必重新读盘，只有怀疑文件发生变化时才回读；没有 hook 时才使用 `FOCUS_DOC` 和入口文件作为兜底。

* 七条不变量：先读聚焦文档、写回最近 workspace、结束改码工作前核对 `status/` 文档并 restamp、不得擅自创建文件、issue/report 命名、信任过期 status 文档、禁止越界写文件。

模板版本由 `PROTOCOL_VERSION`（当前为 `2`）和 App 版本写入块属性。正文的短哈希由 `software-prompt.ts` 计算，当前哈希是 `e24e98a5b8d2`。

软件块的格式如下：

```text
<iris-software version="<app-version>" protocol="2" sha="<body-sha>">
软件层正文
</iris-software>
```

#### 软件层当前完整正文

````text
This project is managed with Iris — an AI-native, document-centric PM tool.
All PM artifacts are plain markdown files under `.iris/`, in typed folders.
The rules below are Iris's invariant protocol: they ship with the app and do
not vary per project. Project-specific policy lives in `.iris/CONVENTIONS.md`;
machine-specific facts live in `~/.iris/CONVENTIONS.md`.

## Folder semantics

Typed folders — `status/`, `issue/`, `report/`, `misc/` — may appear at any
depth. Any folder containing typed folders is a **workspace**; a document's
type is decided by the nearest enclosing typed folder.

- `status/` — Current state of the codebase — a mirror, not a record: rewrite
  freely, keep in sync with reality. Every status doc carries
  `reflects: <git-commit-sha>` in frontmatter.
- `issue/` — Things to do, bugs, open questions — the working record of a
  problem. Treat the body as a record: prefer appending updates; do not
  rewrite or delete existing content unprompted (frontmatter transitions and
  checkbox flips are always fine). Mark resolved via `status:`; never delete
  the file.
- `report/` — Dated deliverables: analyses, reviews, summaries. Edit freely
  while a report is fresh; once reality has moved on, prefer a new dated
  report over reshaping an old one.
- `misc/` — Human scratch space. Do not touch unless asked.

## What the app parses

Frontmatter keys are read literally — use exactly these (unknown keys are
ignored, and a misspelled key silently drops the field):

- `title:` — display title; falls back to the filename when absent.
- `status:` — drives the issue/report lenses; values are defined in
  `.iris/CONVENTIONS.md`.
- `labels:` — optional list; feeds the filter chips.
- `reflects:` — status docs only: the git commit sha the doc reflects.

A new issue starts as (a report starts with `status: Active`; a status doc
carries `reflects:` instead of `status:`):

```
---
title: <short title>
status: Todo
---
```

The app also collects every GFM task checkbox (`- [ ] …`) across `.iris/`
docs into a todo panel, where the user tracks open items and checks them
off. Anything that awaits someone's action — acceptance checks, things for
the user to verify or decide, follow-ups — must be written as task
checkboxes, one per discrete item, never as prose or plain bullets: a
pending item written as prose is invisible to the panel.

## How context reaches you

Iris spawns your terminal with the environment variable `FOCUS_DOC` set to the
document the user is focused on (path relative to project root), and — for
agents with a SessionStart hook — injects a snapshot of the relevant files
directly, each wrapped in an `<iris-…>` tag:

- `<iris-software>` — this block (Iris protocol; app-owned, versioned).
- `<iris-project>` — `.iris/CONVENTIONS.md` (project policy).
- `<iris-user>` — `~/.iris/CONVENTIONS.md` (machine facts, if present).
- `<iris-focus>` — a snapshot of `$FOCUS_DOC`.

**The `FOCUS_DOC` env-var and reading these files from disk are a FALLBACK.**
If you already received a file's contents via the injected `<iris-…>` blocks
above, do not re-read it from disk — unless you have reason to believe it
changed (the injection is a snapshot taken at session start; the file may be
edited during the session, including by you). Agents without a hook fall back
to reading `$FOCUS_DOC` and the referenced files themselves.

## Working rules (invariant)

1. **Focus protocol.** If `$FOCUS_DOC` is set, read it first; its path tells you
   both its type and its workspace. Then wait for the user's instruction —
   loading context is not a task.
2. **Write-back scope.** Write results into the nearest workspace enclosing
   `$FOCUS_DOC`. Do not create new workspaces unless asked.
3. **Stamping.** Status docs do not update themselves. Before ending any
   work that changed the codebase, list the write-back workspace's
   `status/` docs, update those your changes falsified, and restamp their
   `reflects:` with current `git HEAD` — the change is not done until the
   mirror is true again. After a git merge, do not hand-merge status docs —
   regenerate and restamp.
4. **No unsolicited files.** Never create a new file — reports included —
   unless the user explicitly asks. Editing the focused document is always
   fine, as are frontmatter updates (e.g. `status:` transitions) on existing
   docs.
5. **Naming.** New files in `issue/` and `report/` use a `YYYY-MM-DD-<slug>`
   prefix.
6. **Trust calibration.** Before relying on a status doc, compare its
   `reflects:` stamp to `git HEAD`; a large gap means treat it as a weak prior
   and verify against the code.
7. **Off-limits.** Never modify `.iris/CONVENTIONS.md` (the human-authored
   contract) or this `<iris-software>` block. Never write outside typed
   folders. Never touch code directories unless explicitly asked.

For project-specific policy — the issue/report state-machine values and the
markdown style to write in — read `.iris/CONVENTIONS.md`.
````

### 项目层：`CONSTITUTION_TEMPLATE`

代码位置：`src/main/iris-templates.ts`；默认文件是 `.iris/CONVENTIONS.md`。

这份模板只写项目自己的约定，不重复软件层规则：

* frontmatter 固定为 `protocol: 2`。

* `status:` 是 frontmatter 字段。issue 的状态值为 `Todo`、`In Progress`、`In Review`、`Done`，旁支状态为 `Blocked`、`Canceled`。

* report 的状态值为 `Active`、`Backlog`。

* agent 不得擅自把 issue 置为 `Done` 或 `Canceled`，也不得擅自把 report 置为 `Backlog`；最多推进到 `In Review`，关闭由用户决定。

* Markdown 使用普通 CommonMark，匹配编辑器的 remark 序列化默认值。（checkbox 规则已在协议 2 移入软件层——它描述的是 App 的 todo 收集功能，不随项目变化。）

项目文件第一次由 `initIris` 创建，之后归项目作者所有。Iris 只在文件仍是某个出厂默认时提供升级，不覆盖自定义内容。

#### 项目层当前完整正文

```text
---
protocol: 2
---

# Iris Project Conventions

This file is the **project layer**: policy that may differ per project. The
invariant protocol (folder semantics, frontmatter schema, focus protocol,
write-back scope) is owned by Iris and injected separately as the
`<iris-software>` block — you do not need to restate it here. Keep this
file short.

## State machine (`status:` field)

`status:` lives in frontmatter. The stored value IS the displayed value —
write it exactly as shown (deviate only when reality demands).

- Issues: `Todo` → `In Progress` → `In Review` → `Done`, with `Blocked` /
  `Canceled` as side states.
- Reports: `Active` / `Backlog`.

**Never resolve an issue unprompted.** A transition to `Done` or `Canceled`
(and a report to `Backlog`) removes it from the active lens — those are the
user's call. Advance up to `In Review` on your own when reality warrants;
closing one out waits for the user to ask.

## Markdown style

Write plain CommonMark; the app's editor serializes with fixed remark
defaults — match them to keep diffs quiet.
```

### 用户层：`MACHINE_CONVENTIONS_TEMPLATE`

代码位置：`src/main/iris-templates.ts`；目标文件是当前用户目录下的 `~/.iris/CONVENTIONS.md`。

模板要求这里记录“事实”，不要写项目规则，内容包含可按本机实际情况删改的占位项：

* 文件加密方式和受影响目录。

* 网络代理和包管理器镜像。

* 机器类型、快照和临时目录是否持久化。

* 内存等资源限制。

* 权限限制，例如没有 sudo。

* Node/Python 等工具链来源和版本限制。

* 可选的个人写作偏好，例如 issue/report 使用中文。

用户层文件是人写的。Iris 只提供一次安装模板的动作，不解析正文，也不覆盖已存在的文件。

#### 用户层当前完整正文

```text
# Machine Conventions (this machine only — not in git)

## Environment facts

State **facts**, not rules. Keep this file the shortest of the three.

<!-- 按本机实情删改下面的条目；不适用的整行删掉 -->

- Encryption: this machine runs <NAME> transparent file encryption.
  Files created outside whitelisted dirs (<DIRS>) get silently
  encrypted; corrupted-looking build artifacts are usually this, not
  your code. Workaround: <HOW>.
- Network: outbound traffic requires proxy `http://127.0.0.1:<PORT>`;
  npm/pip use mirrors <URLS>.
- Machine: corporate VM; snapshots nightly — `/tmp` does not persist.
- Resources: 8 GB RAM — do not run the full test suite in parallel.
- Permissions: no sudo on this box.
- Toolchain: node via nvm; system python locked at 3.9.

## Personal preferences (optional, keep short)

- Write issue/report documents in Chinese.
```

### 历史默认与升级识别

`LEGACY_CONSTITUTION_DEFAULTS` 现在保存两份旧版项目默认，只用于判断旧文件是否仍是未修改的出厂默认，以便提示升级：

* 第一份是拆分前的“单体宪法”：把目录语义和 agent 工作规则也写进了项目文件。

* 第二份是 protocol 1 的拆分版：三层拆分之后、issue/report 纪律对调之前的出厂 constitution（report 仍是 append-only，checkbox 规则还留在项目层）。正文即上一节“项目层当前完整正文”的前一版，末尾多一段“手工验收必须写成 GFM task checkbox”的要求。

软件层历史哈希列表 `HISTORICAL_SOFTWARE_PROMPT_SHAS` 已建立，当前含一项：`787bcd6a3a44`（protocol 1 正文）。修改软件模板时必须把旧哈希追加进去，否则旧的软件块只能被判断为漂移，不能识别为可安全升级的旧版；这条纪律由测试守护（归档不得含当前哈希、格式必须是 12 位十六进制）。

## 会话注入

### 静态入口文件

`agent-injection.ts` 的 `syncEntryFile` 负责把软件块写进入口文件：

* `AGENTS.md` 是 Iris 标准入口，不存在时可以创建。

* `CLAUDE.md`、`GEMINI.md`、`.cursorrules`、`.windsurfrules`、`.clinerules` 和 `.github/copilot-instructions.md` 只在原文件已经存在时维护，Iris 不主动创建它们。

* 只替换 `<iris-software>` 块，标签外的用户内容原样保留。

* 没有变化就不写文件；有变化且文件原本存在时，先写同名 `.bak` 再写入。

软件块通过标签解析和正文哈希检查，状态为：

* `ok`：正文是当前模板。

* `stale`：正文匹配已记录的旧模板。

* `drifted`：哈希对不上，或正文不是已知版本。

* `missing`：文件存在但没有软件块。

* `no-entry`：入口文件不存在；仅 `AGENTS.md` 可以创建。

### SessionStart hook

`installFocusScript` 把生成的 PowerShell 脚本写到真实的 `~/.iris/focus-context.ps1`。脚本使用 UTF-8 BOM，兼容 Windows PowerShell 5.1，并在输出端强制 UTF-8。

当 `FOCUS_DOC` 未设置时，脚本不输出任何内容。设置后，它按当前工作目录读取并输出：

1. `AGENTS.md` 中的软件块（正则抽取，作为唯一软件层来源）。
2. 项目 `.iris/CONVENTIONS.md`，包成 `<iris-project>`。
3. 用户 `~/.iris/CONVENTIONS.md`（存在才输出），包成 `<iris-user>`。
4. `FOCUS_DOC` 指向的聚焦文档，包成 `<iris-focus>`；文件超过 32 KiB 时只输出提示，让 agent 回读文件。

脚本还会输出项目根、聚焦路径和“已注入内容无需重复回读”的说明。聚焦文档不存在时输出路径和缺失提示，不会伪造正文。

目前可安装 SessionStart hook 的 CLI 是 Claude Code、Gemini CLI、Qwen Code、Cursor CLI 和 Codex CLI。Iris 会读取各自用户配置，显示 `cli-not-found`、`not-configured`、`stale` 或 `configured`。安装 hook 时合并 JSON，不替换其他设置；已有配置先备份，配置无法解析则拒绝覆盖。

## 初始化和管理流程

### 初始化项目

IPC `project:init` 调用 `ProjectManager.initIris`，按以下顺序工作：

1. 创建 `.iris/status`、`.iris/issue`、`.iris/report`、`.iris/misc` 四个目录。
2. 如果 `.iris/CONVENTIONS.md` 不存在，优先写入 `~/.iris/templates/CONVENTIONS.md`，否则写入 `CONSTITUTION_TEMPLATE`；已有文件完全不动。
3. 从机器默认种入 `.iris/styles.json`（已有项目样式不覆盖）。
4. 同步 `AGENTS.md` 的软件块，并维护已经存在的 vendor 入口。

### 新建文档骨架

`createDoc`（UI 的“新建文档”）落盘的 frontmatter 骨架由 `software-prompt.ts` 的纯函数 `docSkeleton` 生成：issue 带 `status: Todo`，report 带 `status: Active`，status 文档带 `reflects:` 空占位（建档时盖章是撒谎，但必填键从出生起就可见）。骨架与软件层提示词里的范例同源，一致性由测试锁定，两边不可能各自漂移。

### 查询状态和预览

`software-prompt:state` 是只读查询，返回：

* 当前 App 版本和软件正文哈希。

* `AGENTS.md` 以及每个已存在 vendor 入口的软件块状态。

* 项目文件是 `missing`、`current-default`、`stale-default` 还是 `customized`。

`software-prompt:preview` 是只读预览，展示软件层实际入口块、项目层实际文件、项目出厂默认、用户层文件，以及按 hook 顺序拼好的完整注入文本。入口尚未写入软件块时，软件层显示将要写入的出厂正文。

### 用户确认后的写入

* `software-prompt:sync-entry`：同步指定入口的软件块。只允许 `AGENTS.md` 或已存在的 vendor 入口。

* `software-prompt:upgrade-constitution`：只接受 `stale-default` 的项目文件；当前默认、自定义或缺失文件都会拒绝升级。升级前保留 `.bak`。

* `machine:install-conventions`：只在 `~/.iris/CONVENTIONS.md` 不存在时使用 `wx` 创建模板；已存在就失败，不覆盖。

* `agent:install-focus-script`：写入或刷新 App 生成的 focus 脚本。

* `agent:install-hook`：把 Iris 的命令合并进一个 CLI 的用户级配置。

这些 IPC 动作都由设置页的“软件提示词”或 agent 配置界面触发；查询和预览不写磁盘，写入动作需要用户明确确认。

## 当前已知边界

* 项目层还不是入口文件里的 `<iris-project>` 块；hook、预览、状态查询和升级都仍读取 `.iris/CONVENTIONS.md`。

* 软件块当前只维护首个匹配块。

* 本仓库盘上的 `AGENTS.md` 和 `CLAUDE.md` 仍携带 protocol 1 的软件块（哈希 `787bcd6a3a44`），现在应被识别为 `stale`，待在设置页执行再同步；`.iris/CONVENTIONS.md` 仍是 protocol 1 出厂默认，应被识别为 `stale-default` 并提示升级。升级前左栏会显示宪法 protocol 与 App 支持版本（2）不一致的提示。

* `softwarePromptState` 是按需查询，当前没有在 App 启动或打开项目时主动提醒过期/漂移。

* 注入脚本和 hook 安装是 Windows PowerShell 路径，未提供 POSIX 版本。
