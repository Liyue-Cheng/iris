# 终端兼容性测试

项目级终端兼容性套件位于 `scripts/terminal-compat/`。它由一个无依赖的
Windows/ConPTY 终端探针和一组剪贴板、拖放夹具组成，用来验证 Iris 作为终端宿主时的
显示、输入、滚动、恢复和会话隔离能力。自动探针只负责产生可重复的输入、序号和
sentinel，不能用脚本正常退出或截图代替人工交互验收。

## 文件

* [terminal-compat.mjs](../../scripts/terminal-compat/terminal-compat.mjs) 产生确定性的
  Unicode/字宽、ANSI 色彩、OSC 查询、持续输出、normal-buffer 行内重绘、
  alternate-screen TUI、原始输入观测和退出进程 sentinel。

* [clipboard-fixtures.ps1](../../scripts/terminal-compat/clipboard-fixtures.ps1) 向剪贴板写入
  普通、Unicode、多行、ESC 和大于 1 MiB 的测试内容，也可以在
  `%TEMP%\iris-terminal-compat-drop-files` 创建含空格、中文和 shell 元字符的拖放文件。

运行环境需要 Windows、正在测试的 Iris、Node.js 22.19 或更高版本，以及用于夹具脚本的
PowerShell 7。套件没有额外 npm 依赖，不要求构建，也不需要运行 `npm run dist`。

脚本中的 `IRIS_*`、`PASS`、`FAIL`、`BLOCKED` 等 ASCII 标记是稳定的检索和
故障定位边界，因此不翻译。

## Iris Agent 内部终端

Iris Agent 的 terminal tool 与普通项目终端分属不同 Session 投影，但共用 ConPTY、headless xterm
解析、raw artifact、replay、输入和 resize 语义。Agent 命令没有执行 timeout，也不分类或拒绝交互
命令；运行满 3 秒只在当前 Agent 内 reveal 同一个 PTY。自动测试覆盖真实 Windows ConPTY 的完整输出
持久化和 reveal，以及状态机层的交互输入、监督、继续、取消、非零退出、ANSI/OSC、UTF-8 分片、
旧记录和重启恢复。真实 TUI 的视觉、IME、WebGL 和人工操作仍使用下方矩阵验收，自动测试不替代它。

## 结果记录

每个 Iris 构建和 renderer 分别保存一份结果，至少记录：

| 字段 | 记录值 |
| --- | --- |
| Git commit 和工作区是否 dirty | |
| Iris 版本与运行方式 | 开发版 / 安装版 |
| Windows 版本和 build | |
| GPU 和驱动版本 | |
| shell 命令 | PowerShell / cmd / 其他 |
| Node.js 版本 | |
| renderer | DOM / WebGL / auto |
| 主题 | |
| 终端字体、字号和行高 | |
| 显示缩放 | 100% / 125% / 150% / 其他 |

每项填写 `PASS`、`FAIL` 或 `BLOCKED`。失败记录必须包含运行命令、会话布局、
第一个错误序号或 sentinel、输入是否仍可用、切走再切回是否恢复，以及相关 main 日志。
视频或截图只能作为补充，不能代替操作过程和 sentinel 核对。

## 运行命令

从仓库根目录的 Iris PowerShell 终端执行：

```powershell
node scripts/terminal-compat/terminal-compat.mjs help
node scripts/terminal-compat/terminal-compat.mjs visual
node scripts/terminal-compat/terminal-compat.mjs protocol
node scripts/terminal-compat/terminal-compat.mjs input --bracketed off --seconds 120
node scripts/terminal-compat/terminal-compat.mjs input --bracketed on --seconds 120
node scripts/terminal-compat/terminal-compat.mjs inline --seconds 90
node scripts/terminal-compat/terminal-compat.mjs tui
node scripts/terminal-compat/terminal-compat.mjs stream --seconds 30 --rate 50 --payload-bytes 256 --stderr-every 137
node scripts/terminal-compat/terminal-compat.mjs stream --seconds 60 --rate 400 --payload-bytes 2048 --stderr-every 500
node scripts/terminal-compat/terminal-compat.mjs exit --code 23
```

从另一个 Iris 会话或外部 PowerShell 写入剪贴板夹具：

```powershell
pwsh -NoProfile -File scripts/terminal-compat/clipboard-fixtures.ps1 -Case plain
pwsh -NoProfile -File scripts/terminal-compat/clipboard-fixtures.ps1 -Case unicode
pwsh -NoProfile -File scripts/terminal-compat/clipboard-fixtures.ps1 -Case multiline
pwsh -NoProfile -File scripts/terminal-compat/clipboard-fixtures.ps1 -Case escape
pwsh -NoProfile -File scripts/terminal-compat/clipboard-fixtures.ps1 -Case large
pwsh -NoProfile -File scripts/terminal-compat/clipboard-fixtures.ps1 -Case plain -CreateDropFiles
```

如果本机执行策略阻止夹具脚本，可以在该次 `pwsh` 命令中加入
`-ExecutionPolicy Bypass`。这个覆盖只作用于当前辅助进程。

## 测试准备

- [ ] 修改任何设置前，填写环境记录表。

- [ ] 以待测源码或安装包正常启动 Iris。

- [ ] 在项目根创建会话 A，在一个文档上创建会话 B，在另一个文档或 workspace 上创建
  会话 C。完成生命周期测试前保留三个会话。

- [ ] 在“设置 > 终端 > Renderer”中明确选择 DOM，执行 T01-T12；然后明确选择 WebGL
  再执行一次。`auto` 只能作为额外 smoke，不能证明实际使用了哪个 renderer。

- [ ] 深色和浅色主题各执行核心矩阵。Unicode/IME 用例使用生产字体，并在条件允许时增加
  一种非默认 Windows 显示缩放。

## 核心用例

### T01：静态渲染、字宽、颜色、标题和链接

运行：

```powershell
node scripts/terminal-compat/terminal-compat.mjs visual
```

- [ ] 所有字宽样例的右侧 `|` 位于同一单元格列；组合字符不额外占一格，CJK 和 emoji
  不覆盖下一行。

- [ ] 线框、多语言、16 色、256 色、truecolor、粗体、淡色、斜体、下划线、反色和删除线
  均可区分。

- [ ] carriage-return 行最终显示 `PASS`；wrap marker 正常换到下一物理行，不覆盖相邻文本。

- [ ] 会话标题变为 `IRIS-COMPAT visual`，切到 B 再切回 A 后仍属于 A。

- [ ] 普通 URL 和 OSC 8 链接按 Iris 链接策略打开，不让 Electron 当前窗口离开 Iris。

- [ ] `Ctrl+F` 能找到 `VISUAL PROBE COMPLETE`；Enter、Shift+Enter、大小写切换和
  Esc 的行为正确，Esc 后焦点回到终端。

- [ ] 选中文本后，Ctrl+C、Ctrl+Shift+C 和 Ctrl+Insert 精确复制 Unicode 内容并清除选择；
  没有选择时 Ctrl+C 仍向运行中的程序发送 SIGINT。

### T02：main 所有权下的 OSC 10/11 回复

运行：

```powershell
node scripts/terminal-compat/terminal-compat.mjs protocol
```

- [ ] OSC 10 和 OSC 11 均输出 `PASS`，值符合 `rgb:rrrr/gggg/bbbb`；分片发送的控制序列
  不显示为乱码。

- [ ] 会话保持打开时切换主题并重新运行，回复使用当前前景色和背景色，而不是旧主题颜色。

- [ ] A 可见时运行一次，从 B 切回 A 后立即再运行一次，两次均通过。

### T03：键盘、IME 和原始输入

在 A 中运行：

```powershell
node scripts/terminal-compat/terminal-compat.mjs input --bracketed off --seconds 120
```

- [ ] 拉丁字符、方向键、Home/End、Backspace、Tab、Esc 和中文 IME 均能输入。

- [ ] 每次已提交输入只在一条 `IRIS_INPUT` JSON 字符串中出现一次；IME 预编辑文本不会被
  当作多次不完整输入发送。

- [ ] receiver 运行时 resize 并切换会话，输入仍只进入 A。按 Ctrl+C 后 receiver 正常结束。

### T04：剪贴板安全与 bracketed paste

在 B 或外部 PowerShell 加载夹具，再向 A 的
`input --bracketed off` receiver 分别使用 Ctrl+V、Ctrl+Shift+V、Shift+Insert、
右键菜单和“右键直接粘贴”模式。

- [ ] `plain` 和 `unicode` 各到达一次，完成后焦点回到 A。

- [ ] `multiline` 在 bracketed paste 关闭时要求确认；取消发送 0 字节，接受后仅发送三行一次。

- [ ] `escape` 始终出现 ESC 警告；取消发送 0 字节且不改变标题。只允许在 raw receiver
  中接受，禁止在真实 shell 提示符直接接受。

- [ ] `large` 出现大于 1 MiB 警告；普通测试取消。专门压力测试接受时，必须同时看到
  begin/end marker。

- [ ] 确认框打开时尝试切换会话。如果对话框允许切换，随后接受不得写入新会话或已销毁
  runtime；若模态设计阻止切换，将此子项记为手工不可达，并保留 controller disposal
  自动测试作为证据。

然后运行：

```powershell
node scripts/terminal-compat/terminal-compat.mjs input --bracketed on --seconds 120
```

- [ ] 再粘贴 `multiline`，不得出现“非 bracketed 多行”警告；receiver 中
  `\u001b[200~` 和 `\u001b[201~` 各出现一次。大文本与 ESC 警告仍然有效。

### T05：文档和 OS 文件拖入

在“设置 > 终端”中分别测试两种文档拖入模式：

- [ ] 内容模式：把 `.iris/misc/Markdown 渲染兼容性测试.md` 拖入 raw receiver。
  文档快照只进入目标会话，并遵守与剪贴板相同的多行/大文本确认策略。

- [ ] 路径模式：拖入同一文档，只插入一次正确引用的项目相对路径，不读取正文。

创建 OS 文件夹具：

```powershell
pwsh -NoProfile -File scripts/terminal-compat/clipboard-fixtures.ps1 -Case plain -CreateDropFiles
```

- [ ] 分别单个和多选拖入生成的文件。空格、中文、单引号、分号、`&` 和方括号都必须作为
  数据正确引用；危险路径确认列出真实路径；取消发送 0 字节。

- [ ] 只在 raw receiver 中接受危险路径，确认 `IRIS_INJECTION_FAIL` 只是文件名文本，
  没有作为命令执行；多选路径顺序与 OS 拖入顺序一致。

### T06：normal-buffer 行内 TUI 与 history freeze

运行：

```powershell
node scripts/terminal-compat/terminal-compat.mjs inline --seconds 90
```

- [ ] 向上滚动数页并停止操作至少 10 秒。可见 viewport 保持稳定，不跳到底部，也不累积
  不完整动画帧。

- [ ] frozen 状态下执行搜索和复制，两者都不能恢复实时绘制。

- [ ] 用 End 或滚动条回到底部，viewport 用一份完整当前面板 resync，并继续更新。

- [ ] 再次进入 frozen 后按普通输入键，resync 与输入保持一致，不重复 durable log。

- [ ] live 和 frozen 状态都进行变窄、变宽 resize；允许正常 reflow，但不得空白、保留旧列宽
  或覆盖历史行。

- [ ] 结束时可见 `IRIS_INLINE_END`，shell 提示符可继续使用。

### T07：alternate-screen TUI

运行：

```powershell
node scripts/terminal-compat/terminal-compat.mjs tui
```

- [ ] 边框稳定、spinner 持续更新，resize 后 rows/columns 正确，方向键产生 escape bytes，
  中文 IME 只提交一次，`c` 能切换强调色，粘贴会增加 bracketed-paste 计数。

- [ ] 快速调整文档/终端分栏和整个窗口大小，不出现残留、错位或空白。

- [ ] 切到 B 停留 10 秒再回 A；A 只显示一个当前 TUI 帧，不重放动画，也不出现 WebGL
  空白或图集损坏。

- [ ] 按 `q` 或 Ctrl+C 后正常 buffer 和进入 TUI 前的 scrollback 完整恢复。

### T08：持续输出、attachment 和 replay

基线命令：

```powershell
node scripts/terminal-compat/terminal-compat.mjs stream --seconds 30 --rate 50 --payload-bytes 256 --stderr-every 137
```

- [ ] `SEQ`/`END` 单调递增，stderr sentinel 插入合理，最终序号和 final sentinel 精确，
  提示符、搜索、选择和 resize 均可用。

- [ ] 在 A 中把同类命令运行 90 秒，切到 B 至少 20 秒。B 不得收到任何 A 输出；回到 A 后
  从一致 snapshot 恢复，继续到 final sentinel，并能输入。

- [ ] 临近结束时快速切换 A/B/C 至少 20 次。旧 detach 不会清空新选择的会话，输出不会跨
  会话标签。

### T09：高水位和 renderer 停顿恢复

约 50 MiB 的专用压力命令：

```powershell
node scripts/terminal-compat/terminal-compat.mjs stream --seconds 60 --rate 400 --payload-bytes 2048 --stderr-every 500
```

- [ ] 运行期间滚动、resize、搜索并切换会话，不出现串会话、永久空白或进程异常退出。

- [ ] 在 DevTools 中暂停 renderer JavaScript 5-10 秒再恢复。暂停期间 UI 停止属于预期；
  恢复后必须排空积压，无进程退出、输出串线、永久 PTY pause 或 final sentinel 丢失，输入
  重新可用。5000 行 scrollback 淘汰本身不等同于字节丢失。

- [ ] 若窗口触发 unresponsive，记录 main 的 unresponsive/responsive 日志和终端诊断：
  process/activity、mirror pending、renderer pending/in-flight、last seq/ACK、blocker 和
  最近 flight-recorder 事件。

- [ ] 所有消费者降到低水位后 blocker 被移除且 PTY resume。

### T10：exited session 与因果最终输出

在 C 中依次运行：

```powershell
node scripts/terminal-compat/terminal-compat.mjs exit --code 23
exit $LASTEXITCODE
```

- [ ] stdout、stderr 和 `IRIS_EXIT_FINAL_SENTINEL code=23` 全部可见后，会话才进入 exited。

- [ ] 切走再切回后标题和 scrollback 仍保留，输入不再发送给已退出 PTY。

- [ ] 关闭 exited session 只移除 C，不影响 A 或 B。

### T11：复制、搜索、清屏、焦点和字体变化

- [ ] 使用保留的 visual/stream 输出，覆盖右键菜单 Copy、Paste、Clear、Search 和所有已定义
  键盘绑定。

- [ ] 用 Ctrl+滚轮走到字号上下限，并在设置中更改字体和行高。布局稳定收敛，没有 resize
  风暴。

- [ ] 输出活跃时切换主题；复制、粘贴和菜单关闭后输入焦点仍在终端。

- [ ] Clear 或切换会话后搜索装饰不残留；“右键直接粘贴”模式另行重复一次。

### T12：WebGL context loss 与 DOM fallback

- [ ] 明确选择 WebGL，并在 alternate TUI 可见时用 Chromium DevTools 或环境的标准 GPU
  测试方法触发 WebGL context loss。

- [ ] Iris 释放 WebGL addon 后仍留下可用的 DOM terminal；输入、resize、stream、选择、
  搜索、切走再切回和退出 TUI 均正常。

- [ ] 如果环境无法可靠定位 xterm 的活动 WebGL canvas，记录 `BLOCKED`，不能猜测通过。

## 真实程序矩阵

确定性探针通过后，再验证真实程序；它们覆盖探针不会模拟的 shell 集成：

- [ ] PowerShell：命令编辑、PSReadLine 历史、Tab 补全、多行编辑、Ctrl+C、原生子进程输出
  和返回提示符。

- [ ] `cmd.exe`：命令编辑、`dir`、中断长命令、Unicode 输出和退出回配置 shell。

- [ ] Git：`git log --graph --decorate --oneline -30` 和带颜色的 `git diff`。

- [ ] 已安装 Codex 时：输入 prompt、持续响应、向上查看历史、resize、生成期间切换会话、
  取消和正常退出。不要为了此项单独安装 Codex。

- [ ] 团队实际使用且已经存在的一个 alternate-screen 程序，例如 Vim、Neovim 或其他 TUI。
  不为宣称兼容而额外安装依赖。

## 通过标准

一个 renderer/build 只有同时满足以下条件才算通过：

- [ ] T01-T11 全部通过；只有无法注入 context loss 时，T12 才允许为 `BLOCKED`。

- [ ] OSC 查询在实时切换主题前后都通过。

- [ ] 粘贴和拖入结果不跨 session lifetime，任何取消操作都发送 0 字节。

- [ ] resize 和会话切换后，history freeze/resync 与 alternate-screen restore 保持一致。

- [ ] 基线和高水位测试到达精确 final sentinel；renderer 暂停后能排空并恢复，没有永久
  PTY pause。

- [ ] exited session 保留全部因果最终输出，并可独立关闭。

- [ ] DOM 与 WebGL 分别有结果记录；`auto` 通过不能替代任一明确 renderer。

任何失败都应建立 issue，并附上本目录中的最小复现命令、环境记录、预期/实际结果，以及
第一个有效的 flight-recorder 或 sequence 证据。
