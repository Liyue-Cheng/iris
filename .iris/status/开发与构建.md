# 开发与构建

Iris 是一个 Windows 优先的 Electron 应用，使用 TypeScript、React 18、electron-vite、Vitest、i18next 和 react-i18next。依赖与本地运行基线是精确锁定的 Electron 43.4.0，项目要求 Node.js 22.19 或更高版本，CI 使用 Node.js 24。实际 Electron runtime、第三方声明、typecheck、全部单元测试、生产 build、产品元数据和启动 smoke 已验证通过；编辑器、IME、拖放、剪贴板、普通交互 PTY、外部 Agent CLI 和 Windows 安装产物仍需按升级风险 Issue 人工检查。日常命令均在仓库根目录执行。

Iris Agent 使用精确锁定的 `@earendil-works/pi-coding-agent@0.84.1`，只通过
`src/main/agent/pi-adapter.ts` 的包根导入。electron-vite 把 Agent Worker 构建为独立
`out/main/agent-worker.js`，与主进程共用 Electron 的 Node runtime。Worker RPC 当前为 protocol v12；
`ready` 屏障核对 protocol、Worker epoch、Transcript revision、Pi 实际加载消息数和 deterministic
history digest。Session 命令和 worker 事件由 main 的单 Session mutation mailbox 串行化；Host 实例身份
和 Worker epoch 隔离旧 worker，但执行段身份不进入领域模型。

main-only `AgentSessionAggregate` 是 Agent 的 canonical state。Turn 表示一条从 Send 到最终回复的连续
串行执行链，直接承载 running/pausing/paused/fulfilled 状态和暂停原因；Continue 从 committed Transcript
重建 worker 并继续同一个 Turn。Provider Call 和 Attempt 分离。人工 Stop、provider failure、Worker
crash、协议/Store 错误共用暂停屏障：先终止并隔离 worker，再提交 paused。Timeline 使用 Session-global ordinal
统一保存 User、Reply 和 Tool Activity；identity 与顺序只追加，Activity 内容和状态单调结算。Reply 在
首个可见 delta 时创建，terminal 后拒绝迟到 delta；无文本失败不创建 Reply。Rewind 只把最后一个
Turn 标为 removed，Effect Ledger 中已发生的文件、终端及外部副作用事实继续保留。

Send 接受用户输入后，main 先生成稳定的 Turn/User Activity identity，提交 canonical Session 并广播
`starting` 投影，再组装 prompt、保存可读 artifact 和等待 Worker ready。用户气泡与“启动中”因此不受
模型目录、Worker 冷启动或 prompt IO 延迟影响；准备失败会暂停同一个 Turn，不创建 Renderer 乐观副本。

Provider Transcript、Timeline、Turn Control、Tool Operation Ledger 和 Effect Ledger 是分开的真相源。
只有 committed provider frame 进入下一次 Worker history；失败 Attempt 的 Reply 仍留在 Timeline 并
标记 excluded。assistant frame 显式归属 ProviderCall，Tool Activity 通过 committed assistant 中的
provider toolCallId 归属 ProviderCall，tool result frame 只归属 toolCallId；不从 worker 的可变当前 ID
推断父关系。内部 access/read/write/exec 以 operationId
持久化和幂等结算，重复 operation 返回已记录结果而不重新执行副作用；Provider tool result 到达后
Tool Activity 才进入 terminal。文件前后内容与 terminal output 位于 Session-owned artifact，Effect Ledger
只保存 hash 和相对 artifactRef；文件写入在 artifact intent 落盘后执行，重启可按目标 hash 补记已发生 Effect。

Store 根目录为 `<userData>/iris-agent-v3/`，schema version 为 2。每个 Session 独立保存 append-only event transaction
`journal.ndjson`，静止时写原子 `snapshot.json` 加速恢复；journal 的严格递增 revision、previousHash 与
记录 SHA-256 形成哈希链。主进程在 journal append + flush 后才广播同 revision projection；末尾半写经
验证后截断，中段 malformed、hash 或 revision 断链会拒绝加载。首次 v3 加载只删除精确位于 userData 下的
`iris-agent-v2/`、`iris-agent-sessions/` 和 `iris-agent-output/`，写入幂等 `manifest.json`；不迁移旧 Session，也不删除
provider profile/API Key、项目 `.iris/`、源码、Git 状态或既有外部副作用。

Renderer 以 `IrisAgentSessionInfo.turns[].cards` snapshot 初始化，随后只消费连续 revision 的 Session、
Turn 和按 Activity ID card patch；revision 跳号重新拉取 snapshot。它不接收 raw Provider history，也不执行
message/tool merge、领域排序、legacy sequence 或 provider 可见性判断。连续 read 与
information terminal 由 main projection 聚合为本地获取卡；文件与 operation terminal 分别展示 diff
和命令；每个 Reply 保持独立生命周期。Stop partial A 后 Continue 会保留 stopped A，并在同一 Turn 中
追加 Reply B。Pause/Continue 控件只存在于 Session control 区。

Agent terminal 由 main 按 Session/terminal ID 持有同一个可输入 PTY。命令没有执行 timeout；3 秒定时器
只 reveal Agent 内部 Terminal 标签并从 raw artifact/mirror 回放，20 秒监督只在有新增纯文本观察时直接
调用 model runtime。正常和错误判断不进入 Transcript，suspicious 判断保留进程并等待用户继续观察或
终止。raw PTY 字节只用于 artifact、replay 和实时终端；Worker、卡片和监督只接收有界的 xterm 纯文本
投影。非零退出码默认失败，调用方可用 `successExitCodes` 显式声明允许值；实际 exit code 始终保留。
旧 terminal activity 不解析 `resultSummary`，只从既有 terminal Effect 派生可确定的只读回放入口。

Iris Agent 的 provider 配置采用用户级“模板 + 方案”模型。设置页提供 OpenAI、Anthropic 及两种
兼容模板，方案分别保存名称、Base URL 和 API Key；同一模板可添加多个方案。每个方案注册为独立
Pi runtime provider，Agent Session 保存并显示精确的方案/model，Fork 继承后可独立修改。新建
Session 的创建和显示不等待 model catalog；Renderer 随后异步选择机器级
`experimental.irisAgentDefaultModel` 记忆的健康模型，或在无历史的新 Session 中回退到 catalog
首个健康模型。catalog 在 main 内按配置 generation 缓存并 single-flight，自定义供应商并行发现且
独立隔离错误；部分失败时保留健康模型、显示具体错误并允许强制刷新。Worker 只注册已选 profile/model，
Base URL 直接从 profile 解析，不会为发送消息再次发现全部供应商。选择模型成功即更新默认值。Key
不进入项目、Session、provider catalog 或 model catalog；Worker 在 provider context artifact 落盘前
也把 profile Key 纳入已知 secret 脱敏。添加或删除方案会拒绝仍在运行的 Session，成功后回收旧
Worker、失效 model catalog 并向所有窗口广播更新。兼容模板必须提供有效 HTTP(S) Base URL。

Iris Agent 当前是默认关闭的实验功能，由机器级 `experimental.irisAgent` 设置显式启用；关闭时
会话面板不显示“用 Iris Agent 打开”的菜单项和空状态按钮，但不会强制终止已经存在的 Agent Session。

Provider transport 使用 Windows 系统代理：Electron main 按所选模型的真实 Base URL 调用
`session.defaultSession.resolveProxy()`，把 `DIRECT` 或解析后的 HTTP(S) proxy 通过 protocol v12
传给 Worker；Worker 使用生产依赖 `undici@6.26.0` 的 `ProxyAgent` 发起请求并在 runtime 销毁时关闭
dispatcher，不导入 Electron，也不直接读取注册表。Provider 非 2xx 错误保留原始 HTTP status/body，
连接失败保留脱敏后的 Error/cause 链，只有已知 SDK 外层前缀会被移除。

发送前组装的文本 artifact 称为 assembled input。新 Turn 在 Pi provider `onPayload` 边界捕获实际
payload，按 allowlist 丢弃 header、credential 和未知扩展字段，并在已知 secret 替换后写入拥有它的
v3 Session artifact 目录。原子提交的 `index.json` 记录有序调用及 SHA-256，每次调用各有结构化 JSON
和确定性 TXT，`index.txt` 可由 JSON 重新生成。User 卡片按 project scope、Session、Turn 内部标识
打开 context index，Renderer 不能指定任意路径。index 同时记录 app version、protocol、Session
revision 和 Worker epoch；可读 index 合并 Provider Call/Attempt 状态、时间和错误审计。产品界面仍
显示当前版本尚不具备自举资格；真实 provider 的 Stop/Continue、自动重试、应用重启和数据 reset
由对应 Iris Agent Issue 跟踪人工验收。

## 安装依赖

```powershell
npm install
```

`front-cpu` 通过 npm registry 安装，不再依赖本机相邻目录。lockfile 固定其下载地址和完整性校验，干净 clone 可直接执行 `npm ci`。发布包当前使用无扩展名的 ESM 相对导入，因此 Vitest 将该依赖内联给 Vite 解析；renderer 的开发与生产构建本身也由 Vite 处理。

## 开发服务器

```powershell
npm run dev
```

该命令启动 electron-vite 开发环境和 Electron 窗口，并为渲染进程启用热更新。开发端口会从 `17273`、`9273`、`7273`、`3273`、`8273`、`5173` 中选择首个可绑定端口。

需要指定端口时：

```powershell
$env:IRIS_DEV_PORT = 17273
npm run dev
```

若指定端口不可用，配置会继续尝试候选端口。

## 代码检查与测试

```powershell
npm run typecheck
npm test
```

`typecheck` 分别检查主进程、preload 和 Web 渲染进程，并运行基于 TypeScript compiler API 的
renderer async boundary 门禁；未进入受控 helper、没有 `catch` 或没有明确理由的 floating Promise
会使检查失败。`test` 运行一次 Vitest 测试集。开发测试可使用监听模式：

```powershell
npm run test:watch
```

## 可靠写入与临时文件

主进程可靠写入统一使用 `src/main/atomic-write.ts`。临时路径与目标位于同一目录，格式为
`<目标文件名>.<pid>.<uuid>.tmp`，以 `wx` 排他创建并在写入和 `fsync` 后原子替换；失败路径
只清理由当前调用成功创建的临时文件。Markdown 文档、资产导入和收编、项目设置、机器级用户
设置、Agent 入口文件、焦点脚本及 hook 配置都使用这一入口。机器级 JSON 设置仍在替换前保存
`.bak`，加载失败时按主文件、备份、默认值顺序恢复。

同目录临时文件避免跨设备 rename，PID 和 UUID 避免并发临时路径冲突；业务层原有的
串行化、revision 和 compare-and-swap 约束保持不变。异常中断残留固定以 `.tmp` 结尾，
scanner 不会将其投影为 Markdown 业务文档。调试日志单代轮转名为 `main-debug.1.log`，保持
`log` 为最后扩展名。

## 文档资产实现

受管资产住在 Markdown 同目录的 `<文档名>.assets/` companion 目录。主进程
`AssetManager` 负责内容 hash 命名、MIME 魔数、大小限制、原子写入、remark AST 引用
审计、旧相对路径与 data URL 收编以及孤儿回收；所有写操作经 project-scoped IPC 和
FrontCPU 的 `asset.*` 指令串行化。scanner 把 `.assets/` 当作不透明叶子，但 Raw Tree
仍展示真实磁盘内容。

文档删除会把 Markdown 与 companion 目录先移动到同文件系统暂存目录，再整体交给
系统回收站；回收失败会恢复原路径。PNG、JPEG、GIF、WebP、AVIF 单文件上限 10 MiB，
普通附件上限 25 MiB；SVG 与符号链接资产拒绝。

## Markdown 文件拖放

文档编辑区域在 `DocView` capture 阶段统一治理路径拖放。左栏 Iris 文档通过自定义 MIME
提供项目相对路径，OS 文件通过 preload 的 Electron `webUtils.getPathForFile()` 解析绝对路径；
单文件原样插入，多文件按拖放顺序每行一个。Crepe/ProseMirror 与 CodeMirror 只负责把统一
文本插入实际落点，不再分别采用图片上传或读取文件全文的默认行为。普通文本、URL、编辑器
内部块拖动和 clipboard 图片粘贴仍走原有链路；路径解析或插入失败会在文档区域显示错误。
路径 drop 只取消默认行为，不停止事件传播，使 Milkdown 与 CodeMirror 的 drop indicator
observer 仍能在松手时清除悬浮落点横线。

`DocView` 也统一承载 Markdown 编辑器的剪切、复制、粘贴和全选右键菜单；Crepe 与
CodeMirror 通过同一个编辑器适配器恢复各自焦点，再调用 main 的 `webContents` 编辑命令，
因此可视化与源码模式共享菜单行为和剪贴板链路。

## 多语言运行时

界面支持 `system`、`zh-CN` 和 `en-US` 三种机器级语言偏好，默认跟随系统；系统 locale 以
`zh` 开头时使用简体中文，其余回退到英文。main 与 renderer 使用独立 i18next instance 和
同一份 typed catalog。设置广播会让全部窗口立即切换，renderer 同步 HTML `lang`，开发态
FrontCPU 控制台映射到其支持的 `zh-CN` / `en`。

本地化只覆盖 UI chrome、对话框、辅助文本和可操作错误。typed folder、frontmatter key、
canonical status、协议 tag、环境变量、IPC/ISA id、路径和用户内容保持原值。协议模板与
SessionStart 注入正文始终只有一份英文 canonical 版本；受保护词汇和跨 locale 生成 bytes
由回归测试锁定。

## Issue 状态语义与生命周期

Issue 官方状态为 `Todo`、`In Progress`、`In Review`、`Blocked`、`On Hold`、`Done` 和
`Canceled`。共享 `document-status` 模块同时拥有规范词汇及 activity、resolution、
close-sessions-on-enter、completion 四项语义；renderer 不再通过 `active = !resolved`
或局部字符串集合推断行为。协议仍允许 exceptional soft value：旧 resolved 拼写保持兼容，
未知值安全降级为 active + open 且不携带转换副作用。

`On Hold` 是 inactive + open：它从左栏和待办投影移除，但不进入已解决分类。Issue 面板
分别提供活动、挂起、已解决和全部视图。Iris UI 主动切换到 `On Hold`、`Done`、`Canceled`
或 report `Backlog` 时，会先确认并关闭锚定终端；自动勾选正文任务仍是 `Done` 独有且受设置
控制。文件监听只更新读侧投影，不把 Agent 或外部工具的 Markdown 写入追认为新的 UI 手势；
仍有关联会话的 inactive issue 沿用现有保护规则暂留左栏，直到会话关闭。

文档状态徽章在左栏、Issue 面板、文档头部、状态菜单和 Report 时间线统一复用
`StatusBadge`。九个官方状态和未知值都使用无边框 `soft pill`，结构固定为语义浅色背景、
左侧圆点和原始状态文字；`md` / `sm` 只有密度差异。主题层通过 `--status-*` 别名提供
中性、执行、评审、阻塞、挂起和完成语义色，未知值降级为中性样式。

## 文档集合浏览器与详情

Issue、status、report 和 misc 使用同一个 `DocumentCollectionShell` 两栏管理视图：左侧由
`DocType` registry 选择领域列表，右侧统一渲染完整 `DocView`，不显示全局文档树或终端。
Todo 不属于文档集合，仍在默认 shell 中使用全宽任务布局。集合 view 保存类型、工作区范围、
`selectedPath`、来源主页面和来源文档工作区；返回可恢复原文档、根 hub、子工作区 hub 或
Todo 视图。来源文档被外部删除时回退到其所属工作区 hub，再无法确定时回退根 hub。

四类集合共享 `iris-document-collection` 可调分栏，默认比例 40/60，并单独记忆宽度。
`DocumentCollectionShell` 在左侧 viewport 左下角提供固定的 Lucide `ArrowLeft` 图标按钮，
带中英文 tooltip、`aria-label` 和键盘焦点样式；列表统一预留 56px 底部空间，最后一行不会
被按钮覆盖。返回成功后会把焦点恢复到原工作区和文档类型的集合入口。

IssuePanel 使用统一列模型驱动的 CSS Grid，而不是 HTML table。标题是唯一的
`minmax(0, 1fr)` 弹性轨道，承接全部剩余空间。行首使用与分组 Header 相同的 12px 左内边距、
14px 图标槽和 8px 间距；当前详情行在图标槽显示 `ChevronRight`，普通行保留等宽空槽，因此 issue 标题
和分组文字共用稳定基线。状态、工作区和日期由分段纯函数获得响应式外层槽位，再按当前
筛选结果中的最宽实际控件或文本建立共享内层轨道。内层轨道受外层宽度限制、整体居中、内容
左对齐，分组折叠不会改变列级对齐轴，窄宽度下内容只在自身槽位内截断。

四类集合行点击只更新右侧详情；Issue 的 `Enter` 和 `o` 也遵守同一语义，且 Issue 面板没有
复选框、多选状态或批量操作栏。详情切换复用统一的
editor flush、navigation intent、项目 scope 和文档读取事务，保存失败或冲突可以阻止切换，
快速请求不会提交过期内容。store 校验选中文档必须匹配当前集合类型和工作区 scope。
详情 Header 和所有集合行的右键菜单都可把目标无重载地带入默认 doc view。集合内创建文档会先
刷新扫描投影，再在右侧选中新文档，不会退出集合。WYSIWYG 草稿在布局重挂载前转成新的初始
正文，同时保留 dirty 与冲突状态；当前详情被删除时只清空右侧并移除失效记忆。

选择记忆按项目、类型和工作区 scope 隔离。Issue 另记忆筛选、搜索、分组、排序、折叠、活动行
和滚动位置；Report 记忆 Active/全部、日期桶折叠和滚动位置；status 与 misc 记忆滚动位置。
集合详情统一使用 fluid 栏内排版，普通文档仍使用 `editorMaxWidth` 与原有阅读对齐设置。

## Markdown 扩展渲染

Crepe/Milkdown 的 CodeMirror 代码块把 `mermaid` 围栏交给 Mermaid 异步预览器，支持
流程图、时序图、状态图和饼图。预览使用 Mermaid `strict` 安全级别，生成 SVG 再经
DOMPurify 清洗；完成或失败后通过 Milkdown 的响应式回调重新提交最终预览，避免其
清洗复制 loading 节点后停留在渲染状态。语法错误显示可读降级内容，其他语言代码块
不进入此路径。预览态的编辑切换和复制操作并列在代码块工具栏右侧，均为紧凑图标按钮；
铅笔按钮位于复制按钮左侧，不使用悬浮文字按钮。复制按钮点击后会短暂显示对钩反馈，
1.5 秒后自动恢复；每个代码块独立计时，重复点击会重新计时。

Milkdown 原生 HTML atom 使用只读 NodeView 显示经过白名单清洗的静态 HTML，覆盖
`details`/`summary`、`kbd`、`mark` 和原生表格。脚本、事件属性、嵌入对象和未批准
标签不会进入文档 DOM；Markdown 源码仍由原 schema 往返序列化。

WYSIWYG 编辑器统一接管 Markdown 链接点击。HTTP(S) 交给系统浏览器；当前文档 fragment
和项目内相对 `.md[#fragment]` 通过带文档路径、editor generation 和请求代次的导航目标，
在对应 Crepe 挂载后定位。Iris 自有 slug 保留 Unicode 字母、数字和中文，剔除标点，重复
标题使用 `-2`、`-3` 后缀；显式锚点支持清洗后的 `<a id="...">`。绝对路径、根目录逃逸、
非 Markdown 目标、无效编码和危险协议在 renderer 拒绝，main 同时阻止未接管的当前窗口导航，
文档读取用真实路径再次校验项目根边界。
Milkdown 默认的链接 hover preview 已从 plugin 配置层关闭，避免它形成不经过 Iris resolver 的
第二个打开入口；选区工具栏的链接创建/解除能力和编辑上下文仍保留，正文链接悬停时使用
系统手型指针提示其可点击。

Milkdown 表格限制在编辑列宽内，实际 `.table-wrapper` 为超宽表格提供横向滚动；单元格
内的行内代码不沿用 Crepe 的不可拆分 `inline-block`，连续长 token 可在单元格内断行，
不会撑破文档页面。

应用下拉菜单与右键菜单的共享 Radix Root 均默认 `modal=false`，避免菜单打开时对 Markdown
编辑器施加全局滚动锁、焦点陷阱、外部指针屏蔽或无障碍隐藏；调用方仍可显式选择模态行为。
Crepe 代码块首次进入视口后保留同一 CodeMirror NodeView，普通滚动离屏、下拉菜单和应用任意
位置的右键菜单都不会把已初始化代码块替换为 placeholder，删除代码块或销毁文档仍完整释放资源。
ProseMirror 向 CodeMirror 同步选区时会把 anchor/head 限制在当前代码文本范围内，避免预览
DOM 更新期间的暂态越界触发 `Selection points outside of document`。

## 项目级快捷命令

项目级 App 设置保存在 `.iris/settings.json`，`prompts.project` 是项目提示词唯一真相源，
`agentContext.entries` 是接收静态 Agent 上下文的显式入口列表，`toolbar.actions` 提供有序
左栏快捷命令。每个动作包含 Lucide `icon`、用于悬浮提示和无障碍名称的 `description`、
`command` 以及 `iris` / `system` 终端类型；设置页的“项目”分类负责编辑。左栏中系统
动作保持左对齐，自定义动作占用剩余空间并整体右对齐；空间不足时按数组顺序折叠到
溢出菜单。Lucide 名称清单由
`npm run gen:lucide-icon-names` 从当前依赖生成，并由回归测试检查同步。

`AGENTS.md` 是必需参与入口，其他受支持 vendor 入口只能由用户显式加入。列表中的每个
入口同时投影 App 内置 `<iris-software>` 和项目级 `<iris-project>`；列表外文件绝不修改。
项目加载审计两层的缺失、漂移、重复块和写入失败，但不会静默修复或把入口编辑反向导入
JSON；UI 提示用户重同步。添加入口先更新设置再投影，停止同步先删除两个托管块再退出
列表且保留文件其他正文。初始化会重建列表中缺失的入口。缺少 `agentContext.entries` 的旧
设置会一次性收编迁移时已存在的受支持入口，此后新出现的 vendor 文件保持未参与。

项目首次打开、窗口恢复和切换项目时会审计提示词投影；可修复的不一致只询问一次是否立即
重同步，用户拒绝后项目仍可正常使用。提示词缺失、漂移、重复、migration conflict 或非法
settings 都不会阻断普通终端、外部 Agent 终端或内置 Iris Agent 的启动和发送，也不会在会话
启动时再次要求同步。诊断继续进入按项目隔离的 health store，并可从设置页显式修复。Iris
只治理明确的 `<iris-software>` 与 `<iris-project>` 受管块；受管块外正文不参与诊断或健康状态，
也没有自动清理入口。

项目命令不会自动执行。renderer 只发送动作下标和配置 revision，main 从磁盘重新解析
动作；首次执行按规范化项目根和 SHA-256 revision 建立机器级信任，文件变化后需重新确认。
Iris 动作新建项目根 hub PTY。Windows 系统动作只通过 `wt.exe -w new` 新建 Windows
Terminal 窗口；不使用文件系统预探测 App Execution Alias，也不回退到 `conhost.exe`。
操作系统无法解析或启动 `wt.exe` 时直接向 renderer 返回错误。main 记录终端宿主、PID、
shell 和 cwd。非法 JSON、未知图标、无效动作、超限文件和 revision 冲突不会覆盖原配置或
执行命令。

项目首次打开和同窗口切换返回同一个完整 `ProjectOpenResult`，其中扫描、会话和项目配置
快照属于同一 `ProjectScope`。main 在项目切换串行事务结束前读取配置和机器级信任状态，
renderer 先安装该快照再发布项目 ready，不再在 ready 后补发配置查询。renderer reload
恢复 main 已持有的 active scope 时仍在首帧前显式水合配置。左栏工具栏的宽度观察绑定真实
DOM 节点 attach/detach，配置异步到达时无需通过设置页重挂载即可建立测量。

## 异步错误与运行健康

应用 IPC 使用统一 request/result envelope。preload 为每次调用生成 request id，可携带
FrontCPU correlation id；main 的注册 wrapper 是唯一 handler 错误序列化和日志边界，返回
domain、code、安全 details、retryable 与 incident id，renderer 以 `RemoteAppError` 恢复，
不解析 Electron rejection 字符串。应用级 flush 和新窗口 handler 也使用同一注册入口。

renderer 的用户动作通过 action runtime 收口为成功、取消或可见失败。离散错误进入支持 FIFO、
去重计数、sticky 状态和恢复动作的 notification；需要用户决定的流程进入 FIFO dialog queue。
session open/close、issue 状态、todo、shell、clipboard、窗口操作、主题、终端字体、编辑器命令和
bootstrap 已接入边界。启动前失败有静态 fallback，React render failure 有 Error Boundary，
全局 `unhandledrejection` / `window.error` 只作为最后兜底。

Project/Git watcher、project/git/session/prompt projection 和 system 异常进入按项目 scope 与
generation 隔离的 health store。顶部 banner 展示当前最高优先问题，可重试项使用有上限的
指数退避，成功后显式清除 degraded 状态。terminal input/resize 使用 session-local failure
latch：持续失败只产生一个 sticky 错误并触发 hydration，自愈后清除断连状态。

## Git 基础控制面

Source Control 的稳定边界为 status、stage、unstage、commit 和已有本地分支切换。main 的
`GitManager` 以真实 worktree 为完整作用域，同时保存 Iris 项目根、Git dir 和 common dir；
项目位于仓库子目录时 UI 显示实际仓库根，列表和 commit 始终对应同一个完整 index。linked
worktree、submodule、unborn 和 detached HEAD 都沿用这一模型。

`git status --porcelain=v1 -z --branch --untracked-files=all` 由独立 parser 投影。rename/copy
消费连续双路径并保存 `originalPath`，二维 XY 状态可同时进入 index 和 working tree。文件操作
使用 literal、NUL 分隔的 stdin pathspec，不受命令行长度、前导短横线或 Git pathspec magic
影响；unborn HEAD 取消暂存不依赖 `HEAD`。

Git 写操作按实际 repository identity 在全部 Iris 窗口间串行，status 等待仓库写队列。快照
携带 repository identity、revision 与 stale 标志；renderer 另以项目 generation 和本地请求屏障
拒绝乱序响应。刷新失败保留最后有效快照并禁用写操作，重新聚焦、手动刷新和 watcher 事件都会
执行完整 reconciliation。提交草稿按规范项目根隔离，只在 commit 明确成功后清空。

Git 自动刷新使用有界混合信号源。Chokidar 只监听 `index`、`index.lock`、`HEAD`、
`packed-refs` 和当前 symbolic ref，不再递归监听 worktree；HEAD 改变后重建 current-ref target，
`index.lock` 删除后才触发失效。main process 级协调器按真实 repository identity 共享 watcher、
状态指纹和退避，最后一个订阅者关闭时释放；linked worktree 因独立 git dir/index 保持隔离。

worktree 内容由 Git 原生 porcelain status 与 refs 指纹每 2 秒加 jitter 探测，输出改变才触发完整
reconciliation。probe 同一 identity 不重叠，全应用并发上限为 2，失败指数退避到 30 秒；Git
自身负责 tracked、untracked、ignore、submodule 和仓库子目录语义。非仓库项目低频重试 discovery，
保留打开后 `git init`。该边界不修改 `core.fsmonitor`，ignored 目录数量和写入频率不会扩大 watcher。

Git 专项测试包含 parser、manager 和 renderer store 三层。manager 使用临时真实仓库覆盖普通与
unborn 提交、rename、双层状态、冲突、submodule、linked worktree、仓库子目录、特殊及大批量
路径、lock、hook、配置失败、外部 watcher 事件和双 manager 并发；watcher 回归另覆盖外部 commit、
deep tracked/untracked 修改，以及 5,000 个 ignored 子目录写入不产生失效。store 覆盖乱序响应、
mutation 屏障、失败恢复、尾随刷新和草稿隔离。

## Windows 退出与终端回收

Windows 会话关闭是可等待的异步协议。`SessionManager` 先在 PTY 宿主 PID 仍存活时调用 `taskkill.exe /pid <pid> /t /f` 终止整棵子进程树，再调用 `node-pty.kill()` 关闭 pseudoconsole 和本地管道，并保留 `onExit` 监听最多等待 2 秒。关闭过程幂等，重复 shutdown 会共享同一个 Promise。

窗口 `close` 会在后端清理完成后才真正销毁窗口；`before-quit` 同样会阻止 Electron 提前退出，等待所有当前 context 和已开始的 disposer。未捕获异常路径也会先尝试同一套清理，8 秒后才强制退出。

同一窗口切换项目也使用可等待的会话回收，但不会调用一次性的 `shutdown()`。`project.open` 通过 CPU 的窗口级项目写锁与其他项目操作互斥；main 在目标预检成功后关闭旧 `{ root, generation }` 的会话，再提交新 watcher 和递增后的项目代际。项目级 IPC 还会在 main 校验代际，拒绝切换期间或来自旧项目的请求。

renderer 只按文档或工作区 anchor 保存粘性终端选择；当前显示终端由当前 view 与该选择
派生，不再维护可被导航覆盖的全局 active session。跨 anchor 激活会等待编辑器离开检查，
再校验项目代际和 session 存活后提交，navigation intent 使过期异步操作不能覆盖较新的
用户选择。状态点变化和普通导航不会抢占选择；关闭选中会话时只在同 anchor 内回退，
reanchor 会搬迁选择，切换项目代际会清空旧项目记忆。

## 许可证声明

`scripts/generate-third-party-notices.mjs` 从 `src/` 的真实第三方导入、生产依赖和少量生成型依赖计算分发闭包，再从 lockfile 与已安装包收集版本、来源和许可证原文。当前生成的 `THIRD_PARTY_NOTICES.txt` 覆盖 643 个包；缺少许可证文本或标识的新包会使生成失败，DOMPurify 明确选择 Apache-2.0 许可。

```powershell
npm run licenses:generate
npm run licenses:check
```

notices 是受版本控制的生成文件。依赖变更后运行 `licenses:generate` 并审阅 diff；CI 和 `npm run dist` 都运行 `licenses:check`，阻止陈旧清单进入发布。electron-builder 将 Iris 自身的 `LICENSE.txt` 和 `THIRD_PARTY_NOTICES.txt` 放入应用 resources，NSIS setup 还会显示 Iris 的 MIT 许可证页面。Electron 与 Chromium 的原生声明继续由 electron-builder 自动附带。

## 终端运行时与数据面

终端规则分为 `src/shared/terminal` 的纯状态机/策略、`src/main/terminal` 的 PTY 数据面 owner 和 `src/renderer/terminal` 的 browser runtime/controller/adapter。`SessionManager` 保持会话 IPC facade；`TerminalView` 只装配 runtime 并承载 React/DOM 手势，不直接访问 terminal IPC、xterm 私有 API、replay queue、ResizeObserver 或输入确认规则。

renderer 用带 epoch 的 attachment token 声明唯一可见 session。main 只为该 session 生成 renderer 输出 payload；browser xterm 以 write callback ACK 消费进度，headless mirror 也统计 parser pending bytes。任一必要消费者达到 384 KiB 高水位时 PTY 暂停，全部回落到 96 KiB 后恢复。用户查看 normal-buffer 历史或选择 alternate-screen 动画帧时，可见帧进入 `history-frozen` 并立即 ACK 后续输出；回到底部、输入或清除选区时通过 main mirror snapshot resync。focus-reporting 的 `ESC[I` / `ESC[O` 属于协议流，不触发回底。resync 在 DEC 2026 synchronized-output 事务内清理旧状态、写 snapshot 和实时尾队列，parser fence 锚底后只提交最终绘制帧。

OSC 10/11 查询由 main 的跨 chunk protocol parser 按当前主题回答并从显示流消费。普通 URL 与 OSC 8 都通过 `shell:open-external-url` 交给 main，只允许 `http:`、`https:` 和 `mailto:` 系统 handler。每个 session 维护 128 条有界 flight recorder；窗口无响应和恢复日志会附带 process/activity、pending/in-flight、last seq/ACK、flow blocker 与最近状态转移。终端直接测试位于 `src/shared/terminal/**/*.test.ts`、`src/main/terminal/**/*.test.ts` 和 `src/renderer/terminal/**/*.test.ts`，Vitest 配置显式收集三层测试。
