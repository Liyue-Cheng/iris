## 问题

在左栏点 Git 之后，顶部的「排序」和「搜索」两个图标消失，后面的按钮整体左移约 56px。

改动前顶部是一排按钮：

```text
[项目▾] [新建工作区] [排序] [搜索] [文件树] [待办] [Git]          [自定义命令…]
```

点 Git 之后：

```text
[项目▾] [新建工作区] [文件树] [待办] [Git]                     [自定义命令…]
```

直接原因是 `LeftPane.tsx` 用 `!gitOpen &&` 把排序和搜索从这一排里移除了。

## 为什么这不是好的交互

1. **刚点过的按钮离开了鼠标。** 想再点 Git 切回文档时，原来的位置已经空了，得重新找。左栏较窄时，右侧的自定义命令会因为腾出空间而多显示出来，可能落到原来 Git 的位置上，有误触风险（这一点是从布局推断的，未实测）。
2. **一排里混着三种性质不同的按钮。**
   - 全局入口：项目菜单、新建工作区、待办；
   - 视图切换：文件树、Git；
   - 只对某个视图有效的工具：排序、搜索。

   只有第三种需要跟着视图变，但它们夹在全局按钮中间，所以一变就把整排挤乱。
3. **视图切换的方式不直观。** 文件树和 Git 都是「再点一次回到文档」的开关，「文档视图」本身没有按钮。用户要靠记忆才知道怎么回去，也看不出这三个视图其实是三选一。

## 设计原则

**顶部这一排要保持稳定，随视图变化的只能是下面的内容区。** 视图自己的工具跟着视图走，和内容一起切换。VS Code 也是这样处理的：活动栏图标固定不动，刷新、折叠、筛选等操作放在各视图自己的标题栏里。用户切换的是内容，不是工具栏。

## 方案

改动后顶部在任何视图下都完全一样：

```text
[项目▾] [新建工作区] [文档] [文件] [Git³] [待办]          [自定义命令…]
─────────────────────────────────────────────
文档 / 文件视图： [🔍 筛选…                ✕] [排序]
                  └ 列表
Git 视图：        沿用 SourceControlPanel 自带的标题行（标题、分支、刷新）
                  └ 变更列表
```

1. **文档 / 文件 / Git 做成三选一的视图切换。** 三个按钮位置固定，当前视图高亮（`aria-pressed`）；点已经选中的视图不做任何事，不再有「再点一次回去」的开关逻辑。文档视图新增 `ListTree` 图标；Git 保留变更数角标。最初有一个细框把三个按钮框在一起，试用后按用户意见去掉，改成和其他按钮同样大小（28px）。
2. **排序和搜索移到列表上方的工具行。** 只在文档视图和文件视图出现；切到 Git 时，这一行连同列表一起换成 Git 面板。
3. **搜索框改为常驻。** 直接点进去就能输入，不用先点放大镜展开；按 Esc 清空并离开输入框。代价是每个视图多占约 36px 高度。聚焦时边框不高亮（按用户意见去掉了最初的 focus ring），只靠光标表示输入状态。
4. **顶栏最右按钮、排序按钮、树里的「+」三者竖向对齐。** 树里每行右侧的「+」（新建文档、新建会话）图标中心离左栏右边缘 27px：预留滚动条 10px + `LensTree` 的 `px-1` 4px + 行的 `pr-1` 4px + 「+」按钮宽 18px 的一半 9px。排序按钮宽 28px，所以工具行右内边距设为 13px（13 + 14 = 27）。同时让树容器始终预留滚动条位置（`scrollbar-gutter: stable`），否则列表短到不需要滚动时，「+」会右移 10px，又对不齐了。代价是列表右侧固定留出 10px 空白。顶栏最右边的按钮（自定义命令或「更多」）同样宽 28px，顶栏右内边距也改为 13px，于是三者的图标中心都在离左栏右边缘 27px 的同一列上。左内边距保持 8px 不变。

5. **待办、项目菜单、新建工作区留在原位。** 待办打开的是中栏，和左栏当前是哪个视图无关。

### 和此前方案的关系

[iris左栏逻辑优化](../issue/2026-09-28-iris左栏逻辑优化.md)曾建议把 Git 和文件树收进一个「视图 ▾」下拉菜单。本次没有采用：Git 是高频视图，收进菜单后每次要多点一下，变更数角标也没有地方常驻显示。三个视图平铺，占的宽度和原来差不多，切换只需一次点击。

### 考虑过的最小改法

不移除排序和搜索，只在 Git 视图下把它们置灰。改动约 10 行，按钮不再跳动，但 Git 视图里会多出两个没用的灰按钮，「三种按钮混在一排」的根本问题也还在。可以作为过渡方案，本次没有采用。

## 实现

- `src/renderer/components/layout/LeftPane.tsx`
  - 新增 `selectMode(next)`：目标就是当前视图时直接返回，否则调用 `projectStore.setLeftPaneMode(next)`。
  - 原来的文件树、Git 开关改为三个按钮组成的 `role="group"`。
  - 排序按钮和筛选输入框移到顶部下面的工具行，仅在 `mode !== 'git'` 时渲染。
- `src/renderer/stores/lens-prefs.ts`：删除不再使用的 `filterOpen` 状态和 `toggleFilter()`。
- `src/shared/i18n/resources.ts`：新增中英文 `layout.leftPaneViews`、`layout.documentsView`。

## 验证

- `npx vitest run src/renderer src/shared`：481 项通过、1 项跳过。
- 按项目约定，没有启动开发服务器截图，也没有运行 build/dist。用户已在实际界面中试用第一版，认为效果可以，并提出去掉细框。

## 回滚与后续修改须知

这个设计不一定长期保留。下面记录回滚方法，以及改动周边代码时容易踩的坑。

### 提交范围

左栏代码改动全部在一个提交里：`7809a9c`（Keep the left pane header stable across views），只涉及三个文件：

- `src/renderer/components/layout/LeftPane.tsx`
- `src/renderer/stores/lens-prefs.ts`
- `src/shared/i18n/resources.ts`

本 report 单独提交，回滚代码时不受影响。

### 整体回滚

```bash
git revert 7809a9c
```

- **没有数据迁移，回滚是安全的。** 左栏模式仍然是原来的 `documents / files / git` 三个值，按项目保存在 `leftPanePrefs` 里，存储格式没变，回滚前后保存的值都能直接读。
- **回滚会恢复以下旧行为：**
  - Git 视图下排序、搜索按钮消失，后面的按钮左移；
  - 搜索框需要先点放大镜展开；
  - 文件树、Git 按钮恢复为「再点一次回到文档」的开关。
- **以后的提交可能和回滚冲突。** 如果后续代码用到了 `lens-prefs.ts` 中被删掉的 `filterOpen` / `toggleFilter()`（回滚会把它们加回来），或者用到了新增的 i18n 键 `layout.documentsView`、`layout.leftPaneViews`（回滚会把它们删掉），`git revert` 可能冲突或导致类型错误。回滚后先跑 `npm run typecheck`。

### 部分回滚

三处改动相互独立，可以只撤一部分：

| 想撤掉的部分 | 怎么改 |
| --- | --- |
| 常驻搜索框 | 在 `lens-prefs.ts` 恢复 `filterOpen` 和 `toggleFilter()`；工具行改为点放大镜才显示输入框，放大镜和排序按钮仍放在工具行里，顶栏保持不变 |
| 三选一视图切换 | 把 `selectMode` 改回切换逻辑：再点一次当前视图就回到 `documents`；同时去掉「文档」按钮 |
| 三列对齐 | 顶栏和工具行改回 `px-2`；去掉树容器上的 `[scrollbar-gutter:stable]`，右侧 10px 空白随之消失 |

### 对齐依赖的数值（改其中任何一项都会错位）

顶栏最右按钮、排序按钮、树里的「+」三者的图标中心都在离左栏右边缘 27px 的位置。这个 27px 是由下面这些分散在不同文件里的数值拼出来的，代码层面没有任何约束把它们绑在一起：

| 数值 | 位置 |
| --- | --- |
| 滚动条宽 10px | 全局样式 `::-webkit-scrollbar { width: 10px }`（`src/renderer/styles/`） |
| 树容器预留滚动条位 | `LeftPane.tsx` 树容器的 `[scrollbar-gutter:stable]` |
| 树容器右内边距 4px | `LensTree.tsx` 根节点的 `px-1` |
| 行右内边距 4px | `LensTree.tsx` 分类行和工作区行的 `pr-1` |
| 「+」按钮宽 18px | `LensTree.tsx` 中的 `p-0.5` 加 `h-3.5 w-3.5` 图标 |
| 顶栏、工具行右内边距 13px | `LeftPane.tsx` 的 `pr-[13px]`（两处） |
| 顶栏和排序按钮宽 28px | `LeftPane.tsx` 的 `w-7` |

修改滚动条宽度、树的内边距或「+」按钮尺寸时，要按 `13 = 10 + 4 + 4 + 9 − 14` 重新计算两处 `pr-[13px]`。`LeftPane.tsx` 的注释里也写了这个算式。

另外，`scrollbar-gutter: stable` 让树右侧始终留出 10px。如果以后改成悬浮（overlay）滚动条，这个预留位就失去意义，需要重新确定对齐基准。
